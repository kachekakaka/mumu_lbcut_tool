## 问题陈述 (Problem Statement)

在多模拟器多路直播录播系统中，录播 Worker（执行单元）与调度平台（Orchestrator）在早期的职责划分上存在以下结构性缺陷：
1. **Worker 存在不当外网依赖与职责越界**：Worker 内部集成了基于公网 HTTP 的短链解析与网页 HTML 爬虫，尝试在内部探查直播标题与下播状态。这不仅与调度平台（基于类似 f2 机制）的高并发 API 巡检功能严重重叠，而且极易因外网网络抖动或抖音网页反爬风控导致 Worker 启动延迟或假死；
2. **下播探测主权分散引发误判**：Worker 试图在模拟器内部通过屏幕 UI 文字或网络请求复合判断下播，极易被直播间弹幕、PK 浮层干扰误判，导致正在进行的直播被误杀中断；
3. **录播停机缺乏标准封口保护**：MP4 视频依赖尾部索引（`moov atom`）闭合，若外部由于下播直接粗暴终止 Worker 进程，ffmpeg 来不及封装索引会导致整段切片损坏报废；
4. **切片生命周期职责模糊**：对于下播瞬间产生的几秒微短残卷切片，缺乏统一的过滤层级定义，导致碎片文件混入下游 B 站投稿流程。

---

## 解决方案 (Solution)

对 Worker 执行**职责纯化与外网解耦重构**：
1. **外网 API 100% 彻底剥离**：下线 Worker 内部所有公网 HTTP/HTTPS 请求代码，保留纯本地离线正则清洗。调度平台在拉起 Worker 时直接传入已解析好的标准数字房间号（`--target <web_rid>`）与归档目录（`--output-dir`），Worker 启动零网络等待，秒级直达模拟器；
2. **纯本地核心机制全量坚守**：
   - 本地 MP4 文件增长检测；
   - 基于本地 ADB 截屏的像素差分与颜色方差动态看门狗（Visual Stall Watchdog）；
   - 遭遇 10 秒卡死时的本地 ADB Intent 原地重拉自愈（`snssdk1128://live?room_id=...`）；
   - 本地 UI 树弹窗识别与模拟点击跳过（Popup Dismiss Matrix）；
3. **下播主权完全收归调度平台**：开下播状态判定 100% 由调度平台通过官方 Web 接口掌控。当下播时，调度平台向 Worker 发送标准操作系统中断信号（`CTRL_BREAK_EVENT` / `SIGINT`）；
4. **确定性停机封口机制 (Graceful Finalization)**：Worker 捕获中断信号后，平滑通知底层 ffmpeg 完成 MP4 尾部索引（`moov atom`）写入与文件安全闭合，并在最后一段切片事件中显式标记 `is_final=True`，确保生成的切片 100% 合法可播且终态可感知；
5. **切片过滤职责外移**：Worker 始终忠实记录并上报所有落盘切片的物理路径；小于 15 秒的下播微短碎片切片由调度平台在投递给外部 biliup 上传服务前执行过滤。

## 用户故事 (User Stories)

1. 作为外部调度系统，我希望在拉起 Worker 时直接传入已解析好的标准数字房间号（`web_rid`），以便于 Worker 启动时无需发起任何公网 HTTP 请求，实现秒级冷启动直达。
2. 作为录播 Worker，我希望严格限定在本地模拟器与本地文件系统上下文内执行录制，以便于彻底规避公网网络抖动或抖音 Web 网页反爬风控带来的进程卡死风险。
3. 作为开发者/测试人员，我希望在手动调试 Worker 时，输入完整的网页 URL（如 `https://live.douyin.com/74400659583`）依然能通过本地正则 0 毫秒清洗出房间号，以便于兼顾手动单兵调试的便利性。
4. 作为录播 Worker，我希望在长时间录制期间持续通过本地 ADB 截屏像素比对与本地 MP4 文件增长率监控画面，以便于在不依赖外网 API 的前提下秒级识别推流卡死。
5. 作为录播 Worker，我希望在检测到画面假死卡顿超 10 秒时，通过本地 ADB 原地发送安卓系统 Intent 唤醒当前直播间，以便于在不离开当前房间、不清屏、不关 App 的情况下原地秒级恢复推流渲染。
6. 作为录播 Worker，我希望在遭遇抖音免登录风控弹窗时，通过本地 ADB 遍历 UI 树并点击安全跳过按钮，并在不可跳过强阻断时立即以专用退出码 15 退出，以便于让调度系统接管并执行切机漂移。
7. 作为外部调度系统，我希望在通过官方 API 探知主播已下播时，向 Worker 发送标准操作系统中断信号（`CTRL_BREAK_EVENT` / `SIGINT`），以便于驱动 Worker 停止录制并完成最后一段视频文件的安全封口。
8. 作为录播 Worker，我希望在捕获到调度系统发出的中断信号后，通知底层录制管线完整写入 MP4 尾部索引（`moov atom`）并将文件安全闭合落盘，在最后一段事件中标记 `is_final=True`，以便于杜绝进程强杀造成的视频损坏并明确通知调度器录制终态。
9. 作为外部调度系统，我希望 Worker 将所有切片严格输出到指定的归档目录并实时上报绝对路径，以便于调度平台将切片元数据装配后可靠投递给外部 biliup 上传服务。
10. 作为外部调度系统，我希望全权掌管切片过滤逻辑，在向外部上传服务投递前自动剔除小于 15 秒的下播微短残卷，以便于保持 Worker 的无业务偏见与高度纯粹性。

## 实现决策 (Implementation Decisions)

### 1. 模块调整与代码剥离

- **下线公网 HTTP 依赖**：
  - `src/worker/resolver.py`：移除 `requests` 依赖，重构为纯本地离线解析器 `OfflineRoomTargetCleaner`：
    - 纯数字：`74400659583` -> `74400659583`；
    - 网页 URL：`https://live.douyin.com/74400659583?extra=...` -> `74400659583`；
    - 无法离线正则解析的未清洗口令/短链：直接抛出明确异常，提示“需由上层调度器解析后传入”，坚决不发起网络请求；
  - `src/worker/stream_end_detector.py`：废弃网络 API 轮询下播，Worker 内部不再有下播退场判断，状态完全由调度平台信号主导；
- **核心本地守护机制巩固**：
  - `src/worker/health_monitor.py` & `src/worker/watchdog.py`：完全保留本地文件大小采样、本地 ADB 截屏帧差分与 `snssdk1128://live?room_id=...` 原地 Intent 刷新自愈；
  - `src/worker/popup_bypasser.py`：完全保留基于 ADB UIAutomator 的访客弹窗跳过与退出码 15（`LOGIN_BLOCKED`）阻断报告；
- **信号停机与切片封口 (Graceful Finalization)**：
  - `src/worker/events.py`：在 `SegmentFinishedEvent` 中新增 `is_final: bool = False` 字段；
  - `src/worker/cli.py` & `src/worker/controller.py`：注册 `SIGINT` 与 Windows `SIGBREAK` 信号处理器：
    1. 捕获信号，状态机切为 `STOPPING`；
    2. 指挥 ffmpeg 写入 `moov atom` 完成当前切片物理闭合；
    3. 发射带 `is_final=True` 的 `SegmentFinishedEvent`；
    4. 清理 ADB 反向代理端口与命名锁；
    5. 以 Exit Code 0 干净退出。

### 2. 命令行与退出码契约

- **CLI 参数**：
  - `--target`：接收标准房间号（纯数字如 `74400659583`）或标准网页 URL；
  - `--output-dir`：接收调度平台计算好的主播归档目录（如 `D:/recordings/林思琪_74400659583/`）；
  - `--segment-duration`：切片周期（默认 1800 秒 / 30 分钟）；
  - `--overlap-duration`：双管线无缝交叠窗口时长（默认 3.0 秒）。
- **退出码标准契约**：
  - `0`：正常完成录制或收到调度器停机信号安全封口退出；
  - `15`：遭遇抖音不可跳过的未登录强阻断（`LOGIN_BLOCKED`），通知调度器执行切机漂移与原机复位；
  - `1`：参数非法或底层严重致命故障（如 ADB 通信物理断开）。

## 实施步骤 (Step-by-Step Execution Plan)

1. **Step 1: 纯化 `src/worker/resolver.py`**
   - 移除 `import requests` 与网络请求逻辑；
   - 提取为离线正则提取器，兼容纯数字、标准直播间网页 URL，若为非数字且非可解析 URL 则安全报错；
2. **Step 2: 扩展切片终态事件 `is_final`**
   - 在 `src/worker/events.py` 的 `SegmentFinishedEvent` 中增加 `is_final: bool = False`；
   - 在 `src/worker/controller.py` 中，区分正常周期切片轮转（`is_final=False`）与最终停机封口（`is_final=True`）；
3. **Step 3: 加固中断信号平滑停机时序**
   - 确保在 Windows 控制台或后台子进程模式下，`CTRL_BREAK_EVENT` 与 `SIGINT` 能稳定驱动底层录制管线执行 `stop()`，等待 ffmpeg 写完索引后退出；
4. **Step 4: 编写专项测试并全量回归**
   - 新增 `tests/test_worker_offline_purification.py`，专门测试“零网络请求”与“中断信号封口”；
   - 运行全量单元测试，确保全库原有测试与新测试 100% 绿灯。

## 测试决策 (Testing Decisions)

### 1. Seams（高层测试接缝）

- **Seam: Worker CLI / Controller 端到端本地隔离 Seam**
  - **位置**：通过 Mock ADB 环境与测试桩执行 Worker Controller；
  - **断言与验证**：
    1. **零外网调用验证**：监控网络 Socket / Mock 拦截，断言 Worker 运行全生命周期内**未发生任何公网 HTTP/HTTPS 请求**；
    2. **信号封口与 MP4 完整性**：向运行中的 Worker 发送中断信号，断言底层管线调用平滑 stop，生成的切片事件携带 `is_final=True`，并以退出码 0 退出；
    3. **本地自愈看门狗**：注入假画面定格，验证本地 Intent 原地刷新动作触发；
    4. **免登录阻断上报**：注入不可关闭弹窗，断言 Worker 立即抛出退出码 15 并发射 `LoginBlockedEvent`。

### 2. 良好测试标准
- 不测试函数内部私有局部变量；
- 严格断言公开的操作系统退出码、stdout 输出的单行 NDJSON 事件流与落盘文件的完整性。

## 范围外说明 (Out of Scope)

- **直播间开下播探测与网络元数据抓取**：完全归属于调度平台（基于类似 f2 机制），Worker 坚决不碰外网；
- **切片视频向 B 站上传投递**：归属于调度平台与外部上传服务对接管线；
- **微短切片（<15秒）业务过滤**：归属于调度平台的上传投递前置过滤，Worker 负责忠实落盘。
