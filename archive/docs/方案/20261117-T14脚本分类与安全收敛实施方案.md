## 一、背景、目标与边界

2026-11-17 对工作区 `scripts/` 的 27 个 Python 脚本逐个做了静态阅读，并追踪相关 MuMu、ADB、依赖管理和 Worker 调用。调查基线为提交 `4a71935`，调查时工作区干净；未执行、导入这些脚本，未运行依赖工具、联网查询或设备操作。

脚本包括 10 个设备操作入口、3 个联网查询入口和 14 个本地分析入口；17 个在模块顶层执行工作。主要问题是默认或固定设备、历史路径、覆盖或删除旧输出、旧 MVP 探针绕过实例锁，以及把有限指标表述为完整验收。现场目录还存在 8 张 JPG、2 个 XML 和 14 个缓存文件，未列入 Git 跟踪；这些文件只完成名称和数量盘点，没有读取其私人内容或验证来源。

目标是留下少量用途清楚、输入明确、失败可判断的维护工具，将历史探针与日常入口分开，并使设备操作、产物写入及停止流程具有明确边界。

本专项拟包括：

1. 按第二节逐个处置 27 个源码文件，建立脚本使用说明。
2. 为保留入口补齐参数校验、依赖检查、路径约束、执行边界和必要测试。
3. 对历史源码作不再可直接执行的归档，保留来源及已有历史证据引用。
4. 更新脚本说明、测试说明及相关导航，记录真实验证结果。

不包括：清理、覆盖或迁移已有截图、XML、缓存、录像、日志、数据库和工具安装；删除旧 MVP 公共模块；重新实现音频隔离或视觉识别算法；批量复跑历史测试；后台/前台混合模式；远程部署、重启现有控制台或正式发布。T3、T18 的暂缓决定继续适用。

本方案提出的历史**源码**归档属于未来实施内容；当前不移动任何文件。已有数据和产物的整理是独立事项，不因后续接受本方案而自动获得授权。

## 三、保留入口的共同执行约定

### 3.1 参数、导入和执行前检查

- 入口统一为 `main(argv=None)`，导入阶段不得创建输出、联网、调用外部命令、连接设备或实例化会产生副作用的对象。参数解析与真正操作分开；帮助和无效参数在加载运行依赖前处理。
- 纯离线工具在明确输入后可直接执行。联网和设备工具无 `--execute` 时只解析参数、检查本地配置/文件并展示计划；不运行 MuMuManager、ADB、ffmpeg，不联网、不建目录、不取得锁。动态检查标为“执行阶段待核验”，不输出“设备空闲/已就绪”。
- 显式执行不是交互式二次询问；说明中列出副作用，由调用者在授权范围内使用参数。不得提供绕过占用保护、自动覆盖或强制删除开关。
- 实例为非负整数；执行阶段从 MuMu 管理信息确认存在，不仅按端口公式猜测。目标、输入路径和输出路径不得为空。时长、等待及并发参数验证为有限的合理正值。Worker 验证的 `--segment-duration` 默认 20 秒，`--record-seconds` 默认 50 秒，要求 `segment_duration >= 5`、`2 * segment_duration + 10 <= record_seconds <= 600`；不足以覆盖正常切片及最终封口的组合在启动任何子进程前拒绝。本工具不承担长稳测试，实际片数仍按第 4.4 节事件与文件核验，不能靠时间参数推定。
- 项目资源定位独立于当前工作目录：按 `__file__` 推导仓库根；用户相对路径明确按调用目录解析并展示绝对路径；子进程明确设置工作目录和完整继承的环境变量。支持从仓库外以脚本绝对路径调用，无需手工设置 PYTHONPATH。
- 扫描输入沿用现有样本 JSON 字段约定，先验证完整集合再联网；重复样本 ID 或规范化后重复的网页入口报输入错误，不静默去重。UI 筛选模式使用明确的 `--filter all|top|controls`，顶部阈值通过 `--top-y` 指定，默认 300；这些筛选仅帮助人工观察，不自动点击候选节点。

### 3.2 依赖与固定路径

- ADB/MuMu 使用既有安装发现逻辑，不在脚本中保存个人盘符、用户名或 serial。运行前检查依赖缺失并明确报错，不安装 Python 包。
- 媒体信息与抽帧统一使用 `DependencyManager.get_media_tools()` 的固定 FFmpeg/ffprobe 成套工具；不再回退个人虚拟环境或 PATH。纯 XML/事件解析不要求 MuMu、scrcpy 或媒体工具。
- 保留脚本不使用 OpenCV；截图验证使用已有 Pillow。不得仅为历史探针向运行依赖添加 OpenCV。
- 实机验证不得触发 `ensure_scrcpy()` 的自动下载和覆盖。拟为依赖管理增加只检查本地 scrcpy 及 server 的方法，并通过 Worker 的 `--require-local-tools` 参数、对应配置字段和控制器分支贯穿本次验证子进程。缺失时拒绝，不进入下载分支；不能只在父进程做一次存在检查然后允许子进程自动下载。该改动仅承接验证入口的明确依赖策略，不借本专项重写全项目工具部署流程。
- 依赖检查不写工具目录；并发使用者自行替换工具的情况不靠本专项提供全局部署锁，测试记录工具路径与版本，并要求验证窗口内不更新工具。

### 3.3 输出与旧材料保护

- 设备取证和录制工具必须指定输出父目录，并要求位于仓库之外；推荐根 README 约定的仓外临时目录。解析最终路径，拒绝落回仓内（含可解析的链接路径）；不自动改写到另一个目录。
- 每次创建“时间 + 随机标识”独立批次目录，使用排他创建；文件写入使用排他创建或只在本次新建目录内操作。禁止复用已有批次、删除 `run_*`、清空目录或覆盖同名产物。
- 离线分析默认输出到标准输出，不隐式生成图片、报告或修改输入。媒体错误不能回退读取上次生成的图片；NDJSON 损坏不能静默忽略后宣布完整通过。
- UI dump 的设备端文件使用本次唯一名称，成功读取并验证后仅删除本次创建的临时文件。失败时保留位置和错误；不操作旧 `/data/local/tmp/ui.xml`、`/sdcard/screen_probe.png`，不通配清理。
- 本地失败材料、未封口录像、日志都保留于本次目录并标明失败。不为了让测试重复通过而删除它们。

## 四、设备安全与当前 Worker 验证

### 4.1 实例选择、占用和锁

`launch_vm.py`、`dump_screen.py`、`save_screenshot.py` 在任何设备操作前取得当前 `WorkerInstanceLock`，持有至操作及本次资源收尾结束；忙碌则非零退出，不重试抢占、不解锁他人。截图/UI 取证也采用同一保守规则，本专项不提供录制期间旁路取证模式。

`verify_worker_e2e_live.py` 由 Worker 子进程取得并持有锁，父进程不预先持锁启动子进程，以免自我冲突。父进程不在 Worker 取得锁前发送 ADB、Intent 或窗口命令。子进程明确报告实例忙碌或准入失败时，父进程及时结束，不能继续等满“开录超时”。

现有锁仅覆盖相同共享锁目录的协作进程，不能证明其他仓库副本、远程部署、手工 ADB/scrcpy 没有占用。实机前要核对实际部署和活跃任务；若存在其他根目录的控制台或录制进程，不能凭本仓库锁空闲继续操作。无法排除占用时停止实机阶段，保留待验状态；不擅自停止服务、不新增跨部署锁系统。

严格设备核验必须接入实际持锁的 Worker，不能仅在父脚本启动前核对一次。拟在 `src/mvp/mumu_client.py` 提供共用的严格实例查询、serial 解析和绑定连接能力，由三个独立设备工具和 `src/worker/controller.py` 调用。Worker 的执行顺序明确为：

1. 取得实例锁并完成本地依赖检查，查询指定实例是否存在；未找到或查询结果冲突则退出，不发实例开机请求。该阶段允许已确认存在的关闭实例尚无运行端口，不凭端口缺失把它当作另一台设备。实施时本机无 MuMu 主程序的只读管理查询出现超时，因此补充冷启动准备边界：仅启动类入口允许在安装根的 vms 下唯一确认指定实例配置存在后准备 MuMu 主程序，再重新查询管理信息确认实例；配置文件只用于证明安装记录存在，绝不提供端口或替代开机后的严格映射。该准备另计 20 秒预算，截图/UI 入口不得借此拉起主程序。
2. 仅对已确认存在的指定实例启动并等待 Android 就绪；每个阶段遵守第 4.3 节的取消和截止时间。
3. 开机后在仍持锁时重新查询管理信息，取得与指定实例相符的主机、有效端口及就绪状态，形成已确认的 serial。信息不足、实例指向冲突或多个实例的映射相互冲突时拒绝；不得回退到旧配置文件或 `16384 + 32 * vmindex` 公式。
4. 把该次确认的 serial 显式交给有界连接流程，核验 ADB 中该精确目标的在线状态，并在进入窗口/设置/导航操作前复核管理映射未变化。连接方法不得在内部重新推算或换成另一 serial。复核失败则中止，不创建用于操作抖音的客户端。
5. Navigator、采集管线和正常收尾客户端均绑定该 serial，运行中不自动选择其他在线设备；后续重连也只能重连已确认目标。若已观察到映射变化，停止后续设备修改和设备端清理并报告，不把旧地址用于关闭可能已变更归属的应用。

截图/UI 工具在持锁后直接走已启动实例的严格核验流程，未启动则拒绝，不借取证隐式开机。独立启动工具也在开机后核验实际映射才报告成功。上述严格校验属于本次明确列入的 Worker 准入改动，不能因“复用现有连接方法”保留公式兜底。

实例锁和前后复核仍不能阻止不参与锁的外部管理程序在任意时刻改端口，因此保留“验证窗口内不由其他程序操作该实例”的前提；不宣称能在任意外部并发修改下保证设备归属。

### 4.2 目标、身份与已知副作用

- Worker 验证只录制调用者指定目标。删除自动扫描候选和历史 room_id 兜底，不因目标下播切换主播。
- 沿用当前 `--target-kind`、`--web-rid`、`--expected-anchor-uid` 和身份参数校验。可由当前 RoomResolver 查询调用者指定的网页入口，取得独立 room_id/UID；查询 UNKNOWN、ENDED 或关键身份缺失时明确失败，不能当成 LIVE。
- 默认不传 `--allow-unconfirmed-identity`。确需验证未确认模式时必须由调用者显式传入，并在计划和证据中标记；可靠身份冲突仍由当前 Worker 阻断，不修改 K15/K17 规则。
- 窗口默认置底；不提供本专项的后台会话、隐藏或离屏试验。说明会启动指定实例、打开/切换指定直播间、设置静音/帧率/渲染配置，收尾会关闭该实例的抖音，且现有配置可能持续保留。
- 只选择获准使用的测试实例，不承诺自动恢复原直播页、原设置或关闭本次启动的模拟器；这些恢复无法从当前 Worker 生命周期保证，不以补偿动作制造更多设备操作。

### 4.3 子进程、超时和中断

- **冷启动取消贯通：**在 `WorkerController` 中维护停止事件，由 `request_stop()` 同时设置现有停止状态和该事件，并传给 `MuMuClient.launch_player()`，再贯通到主程序准备、开机受理重试和 Android 就绪等待。阶段等待改用可被该事件唤醒的方式；已经发出的命令按本节单次上限返回。取消后的启动返回应由控制器优先识别为取消，不能仅因 `launch_player()` 返回 False 就归为普通开机失败。
- **取消后的操作门禁：**在开机前后、ADB 连接/重试前、每条实例设置命令前及导航前检查同一停止状态；在正在执行的命令返回后再次检查。收到取消后不再新增开机重试、连接、设置、Intent 或录制操作。已交给 MuMu 的开机请求可能自行完成，记录实际状态，不额外关机补偿。尚未通过严格映射复核、未进入应用操作阶段时不得因 `finally` 关闭抖音；已进入该阶段的正常收尾仍只针对确认过的设备，并在日志中区别业务操作与收尾操作。
- **底层命令同样有界：**独立设备工具和 Worker 共用的连接流程都必须传递截止时间及停止状态，不能只让父进程限时等待。拟定命令和阶段预算如下；这些是未来实现目标，现有 `adb connect`、`adb devices` 尚无超时，不能直接原样复用。

| 操作 | 单次上限 | 整体截止时间及重试规则 |
| --- | --- | --- |
| MuMu 管理查询、启动请求、单条设置命令 | 5 秒 | 主程序准备 15 秒、启动受理重试 45 秒、Android 就绪 60 秒沿用现行阶段预算；单次 timeout 取与阶段剩余时间的较小值；前后映射查询分别计入预算；设置阶段按固定命令数乘 5 秒计上限，不无限重试 |
| `adb connect`、`adb devices`、`get-state` | 分别 5、3、2 秒 | 一次连接及所有重试共享 20 秒，重试间隔也消耗该预算；取消后不再发下一条命令 |
| UI dump、读取/pull XML | 分别 15、5 秒 | 焦点查询、生成、读取共用 25 秒；不因生成失败读取旧 XML；超时不重新开启完整预算 |
| 截图 `exec-out screencap` | 10 秒 | 一次截图流程 15 秒，包含结果检查；无无限重试 |
| ffmpeg/ffprobe 版本检查 | 每个 8 秒 | 配套工具检查总计 20 秒，不回退其他工具 |
| 单文件 ffprobe、预览抽帧 | 分别 15、10 秒 | 每个文件媒体检查共用 25 秒；Worker 停止后按已确定的文件数 N，检查总预算为 `20 + N * 25` 秒，不递归扫描目录或持续增加输入 |
| 本次客户端超时后的回收、设备临时文件清理 | 客户端回收 1 秒、删除命令 2 秒 | 收尾另列固定预算；设备不可确认/已离线时保留临时文件位置，不为清理重新开机或无限重连 |

- 所有时间用单调时钟计算，重试不得重置阶段截止时间；实际调用 timeout 为单次上限与剩余预算的较小值，剩余时间不足时直接失败或取消。超时只结束本次持有的命令客户端，不结束共享 ADB server；等待客户端回收和读取剩余管道也必须有界，不能再使用无 timeout 的 `communicate()`。截图保留二进制输出，不误用文本解码的命令封装。
- 当前固定 90 秒开录等待改为本地工具检查、实例前后查询、启动、连接、设置、导航及采集准备的阶段上限之和，再加 15 秒父子调度余量。导航使用实际配置预算，采集准备按当前开录实现的预算来源核对；在代码中统一表达预算并测试其组成，不在父脚本复制另一套隐含值。异常恢复不重置父进程开录截止时间。父进程还需监听子进程提前退出，不能只等事件超时。
- 录制观察计时从首次有效 `segment_started` 开始。父进程持续并行排空 stdout/stderr，原始事件和日志从启动起落盘；事件解析异常单独记录，不丢弃原文。
- 正常结束、启动超时、用户中断及异常均进入统一 `try/finally` 收尾。Windows 使用独立进程组，先向本次 Worker 发平滑停止信号，再等待有限宽限期。宽限期必须覆盖剩余单条命令、采集停止、尾片校验、探针回收和确认设备上的应用收尾；实施时对照现行阶段上限求和并测试，不仅取某个 `stop()` 的默认值，也不能因反复收到事件而续期。
- 超过宽限期才终止已确认属于本次启动的 Worker 和专属采集/分析子进程，依据保存的进程对象/创建信息核实归属；不得无差别结束整棵后代树，即使由本次启动，MuMu 主程序/实例和共享 ADB server 也不纳入强制清理。不按进程名批量杀 MuMu、ADB、Python、scrcpy，不使用全局 kill-server。强制终止必须判为验证失败，并报告残留/未封口情况，不能算作平滑停止成功。
- 复用现有进程管理能力时先核查其作用域；若无法可靠确认后代归属，不扩大杀进程范围，报告残留并停止后续设备测试。父进程被操作系统强杀等不可捕获退出不承诺由 finally 保障。

### 4.4 结果判定

- 正常切片与主动中断验收必须同时满足以下条件，不能仅凭进程退出码或某一个最终片判断成功：

  1. 测试指定的 Worker/run_id 正常启动，事件均归属本次运行；按事件 ID 去除完全相同的重复投递后，每个已开始切片恰有一个匹配的完成终态，索引、路径与实际文件一一对应，无相互矛盾的重复终态。
  2. 至少有一个正常完成的非最终片，以及主动停止后正常完成的最终片，即总计至少两片；最终片恰有一个，其前面的完成片均为 `is_final=False`。各文件位于本次批次内，具有有效音视频轨及正时长。
  3. 到达 `record_seconds` 时，已出现正常非最终片、还有后续已开始但未终结的片，且 Worker 仍存活、未进入自然结束或异常恢复，才执行本次计划内停止。停止条件不满足也要进行有界收尾，但结果为“验收条件未满足”，不得延长录制直到凑够片数后冒充原定测试通过。
  4. 记录本次计划内停止信号的发送时刻及结果，收到对应 Worker 的正常停止终态：退出码为 0、原因是本次请求停止而非自然下播/总时长结束/事件流丢失，且 `had_segment_errors=False`；父进程未走任何强制终止路径。不向 Worker 配置与计划停止竞争的录制总时长，由父进程掌管本次观察截止时间和停机。
  5. 整个运行无异常切片、采集/封口失败、恢复或质量告警。检查当前事件协议中 `segment_aborted`、`worker_failed`、`stall_detected`/`stall_healed`、恢复及质量事件，并检查最终 `had_segment_errors`；实施时逐项映射现行协议，补齐已恢复但退出码仍为 0 的案例，不能只判断最终健康状态。

- 结果分开记录“正常通过”“有恢复/质量告警”“失败”“验收条件未满足”。只有上述正常通过返回成功；出现恢复或质量告警，即使最终切片及退出码正常，也保留恢复是否成功的事实并返回非零，不能计入无异常通过。输入损坏、终态缺失/冲突、强制终止或媒体不合格判失败；自然下播、过早结束、缺少非最终片或停止条件未满足均不能算主动中断验收通过。显式未确认身份模式须独立标记，不能用于关闭本节要求的正常确认身份实机验收。
- 原始日志、测试输入、实际工具版本、预期/实际身份、设备映射、正常/强制停止、各项通过/失败/未测结果写入本次报告。
- 媒体探测成功不等于完整解码、画面无遮挡、音频隔离或音画同步通过。工具不得输出“100% 验收通过”“完好无损”等超出检查范围的结论。
- 参数错误、依赖缺失、输入损坏、设备忙碌、超时和断言失败均非零退出，并给出可区分原因；扫描出现请求失败/UNKNOWN 时保留逐项结果并以非零表示不完整，ENDED 是正常查询结果。具体退出码表在 `scripts/README.md` 唯一维护。
