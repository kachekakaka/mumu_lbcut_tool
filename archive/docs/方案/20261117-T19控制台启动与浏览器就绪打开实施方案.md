## 三、CLI 与地址规则

在 `run` 子命令添加 `--open-browser`（布尔开关），传递到 `ServerConfig.open_browser`，默认值为 `False`。帮助信息说明“服务就绪后在运行服务的计算机上打开默认浏览器”。

仓库根目录下的最小交互启动形式为：

```powershell
python -m src.orchestrator.cli run --output-dir <录制目录> --open-browser
```

`<录制目录>` 为说明占位符；实际路径含空格时需要引号。解释器和环境准备继续遵循[运行说明](../../../docs/最小调度运行说明.md)，不新增全局命令安装机制。

浏览器地址只从经过校验的监听地址和端口生成：

| 监听配置 | 本机浏览器地址 |
| --- | --- |
| `127.0.0.1:8000` | `http://127.0.0.1:8000/segments` |
| `0.0.0.0:8000` | `http://127.0.0.1:8000/segments` |
| 指定私网 IPv4、其他端口 | 使用该 IP 和实际端口，路径为 `/segments` |
| 当前允许的 IPv6，例如 `::1` | 使用方括号，例如 `http://[::1]:8000/segments` |

不扩大当前 host 校验范围，不新增对 `::` 或主机名的支持。`0.0.0.0` 是监听地址，不输出为浏览器访问地址；本机 URL 也不冒充其他设备可直接使用的访问地址。

无论是否启用自动打开，服务成功就绪后都输出明确的访问地址。没有前端文件时明确提示前端不可用，避免把地址日志表述为切片页面可用。SSH 启动不能保证浏览器出现在已登录用户的交互桌面，更不能打开 SSH 客户端所在设备的浏览器，运行说明需写清这一点。

## 四、服务就绪与单次打开流程

在现有 `ConsoleServer` 子类中覆盖异步 `startup()`，保留原有信号处理逻辑：

1. 先 `await super().startup(sockets=sockets)`，由 Uvicorn 完成 lifespan 与 HTTP listener 初始化。
2. 仅在本次 `server.started` 为真、未要求退出、运行时未失败且调度线程处于运行状态时，发布就绪访问日志。
3. 检查当前前端 `index.html` 是否存在。不存在则记录前端不可用并跳过自动打开，API 服务按现有规则继续运行。
4. 启用了 `--open-browser` 且本服务实例尚未尝试打开时，先记录“已尝试”，再启动一个专用 daemon 线程调用 `webbrowser.open(url)`。只调用一次，不根据返回结果重试。
5. 线程在调用前再次检查本次服务是否正在关闭或已失败；已知退出或失败则跳过。
6. 线程创建失败、调用异常、返回 `False` 均只记录警告及手动访问地址，不改变服务退出码，不终止调度器。

不用固定等待时间，不轮询端口上的未知服务，不在 `Runtime.start()`、lifespan 的 `yield` 前或阻塞的 `server.run()` 返回后打开浏览器。即使旧服务占用了目标端口且能响应健康请求，本次绑定失败仍不能触发打开。

浏览器调用不占用 HTTP 事件循环，也不使用退出时需要等待完成的默认线程池。专用线程不持有运行时锁跨越系统调用，服务停止时不等待浏览器调用返回；避免系统浏览器处理异常造成接口和退出流程被拖住。

“仅一次”指每次服务进程生命周期最多发起一次系统打开请求，不承诺操作系统一定新建窗口或标签。操作系统已经接收的打开请求无法撤回；若随后服务立即故障或退出，浏览器可能仍出现，这是并发边界，不能宣称完全消除这种瞬时情况。

前端存在性检查沿用当前 `frontend_available` 的判定，不新增接口字段。它不能证明所有构建资源可加载，实际切片页可用仍需浏览器验收。

#### 两个启动包装的约定

新入口的命令仍须显式携带现有数据和录制目录，形态如下：

```powershell
& <现用Python> -m src.orchestrator.cli run --data-dir <现用数据目录> --output-dir <现用录制目录> --host 0.0.0.0 --port 8000 --open-browser
```

- `.bat` 在 Python 返回后立即保存 `%ERRORLEVEL%`，再执行提示或可选暂停，最后用 `exit /b` 返回保存的退出码；不能让 `pause`、输出或后续命令覆盖结果。
- `.ps1` 通过 `pwsh` 执行，用调用运算符和独立参数传递路径；Python 返回后立即保存 `$LASTEXITCODE` 并用 `exit` 返回。解释器缺失、工作目录设置失败等发生在 Python 启动前的错误也必须终止并返回非零，不使用可能遗留的旧退出码。
- `.bat` 使用 UTF-8 无 BOM、CRLF 换行，并在中文内容前以 ASCII 命令设置 UTF-8 代码页；`.ps1` 使用 UTF-8、PowerShell 7。Python 明确启用 UTF-8 模式。实际入口验证须覆盖中文路径、提示及重定向日志，不能只检查文件编码。
- 所有路径按各自 shell 的规则引用和传参，不把完整命令拼成字符串后再次解释；保留现有显式目录参数。包装只设置确定的工作目录、解释器及部署环境，不新增浏览器进程或后台延时任务。
- 两个候选入口先在隔离环境验证成功和失败退出码、参数原值及编码，再替换实际入口。失败覆盖解释器不可用、工作目录不可用、参数错误、端口占用和初始化失败；使用测试服务或替身，不使用生产目录制造失败。可选暂停需在测试中完成后再核对最终退出码。

#### 现场替换与收尾

替换时要求：

- 核对最终代码目录与 `PYTHONPATH`，确保解释器加载的是新版本，不能只改开关却仍加载旧 CLI。
- 两个入口统一委托 CLI，不保留 `timeout`、`Start-Sleep` 或额外浏览器任务，也不通过删掉目录参数来缩短命令。
- 在覆盖入口前保留原入口与原部署副本；新版本按上述同级目录要求准备，不清理既有产物。切换必须已有数据兼容性结论、路径核对结果、候选入口验收及具备明确适用条件的恢复方法。
- 活跃服务切换涉及现有调度和录制，需先确定允许重启的窗口；未明确授权该现场切换时，继续完成候选文件和隔离验证，保留部署待办，不停止当前服务。
- 切换时仅操作确认属于该控制台的进程，先按正常退出流程收尾，再启动新入口；不让两个服务争用现有数据目录，也不为测试终止未知占端口进程。
- 从 250 交互桌面使用实际入口验收；确认既有目标、设置和切片记录仍来自原目录，默认浏览器直接进入 `/segments`，局域网访问仍可用。另一路入口需在前一路已退出后验证，避免同时运行。

只有阶段 A 与阶段 B 的必要验收都完成，才按[文档生命周期](../../../docs/README.md)关闭 T19 并归档。若现场切换暂不进行，状态保持“待验证”，清楚记录仓库实现完成、远端部署未完成。

## 七、验收场景

| 场景 | 验收要求与方法 |
| --- | --- |
| CLI 默认与传参 | 不带开关不自动打开；带开关正确传递；默认数据目录、地址、端口不变；缺少输出目录仍报参数错误 |
