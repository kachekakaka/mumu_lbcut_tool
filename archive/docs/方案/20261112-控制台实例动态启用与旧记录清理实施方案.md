## 问题陈述 (Problem Statement)

目前调度器启动时必须通过命令行参数 `--instances` 静态指定允许使用的 MuMu 实例编号，且控制台「实例」界面仅允许只读查看，不能在启动后动态选择或调整录播实例：

1. 使用者必须在启动命令中提前记清并填写实例编号，漏填或填错需要重启服务；
2. 当复用同一数据目录 `--data-dir` 并缩小 `--instances` 重启时，旧库中残留的实例记录既不会被清理也不会被过滤，仍会出现在「实例」列表和「总览」统计数字中（已知缺陷 `K14`），误导实际可调度容量。

## 解决方案 (Solution)

取消启动参数 `--instances` 的强制必填限制，让调度器启动后自动探测本机全部 MuMu 实例，并由使用者在控制台「实例」界面通过开关持久选择启用或停用哪些实例参与录播：

1. 全新数据目录且未在命令行显式预设时，本机探测到的实例默认处于「未启用」状态，避免误抢占用户用于其他用途的模拟器；后续重启自动保留界面勾选结果。
2. 「实例」界面展示本机全部已发现容器，提供启用/停用开关与状态筛选；「总览」界面的实例计数和下方实例条带只统计与展示「已启用」实例（存在待对账任务占用的历史实例临时保留以供处置），不再被未启用或已删除实例干扰。
3. 成功扫描后，本机已探测不到且无活跃或待对账任务占用的旧实例：未启用的自动清理；仍启用的保留为 `offline / not_discovered`，停用后清理。查询失败保持原记录。占用中（录制、启动、停止、开机、复位或待对账）的实例禁止直接停用，需先结束对应操作或完成对账。

## 用户故事 (User Stories)

1. 作为录播操作者，我希望不传 `--instances` 也能直接启动调度服务与控制台，以便启动服务前无需反复查询实例编号。
2. 作为录播操作者，我希望首次启动新数据库时本机已有的模拟器默认「未启用」，以便系统不会未经我同意就自动占用我用来手动测试或日常使用的 MuMu 实例。
3. 作为录播操作者，我希望在控制台「实例」界面看到本机探测到的全部 MuMu 实例及其真实在线/未开机状态，并通过开关自由启用或停用它们，且重启后保留我的选择。
4. 作为录播操作者，我希望「总览」界面的 `空闲 / 离线实例` 数字和实例卡片只反映我已启用的录播池大小（同时可看到另有几个本机实例未启用的辅助提示），以便准确判断当前真实可录播容量。
5. 作为录播操作者，当我手误去停用一个正在录制、复位中或待对账的实例时，我希望系统拒绝操作并给出明确中文提示，以便防止正在进行的直播录制被意外掐断或丢失对账入口。
6. 作为录播操作者，删除本机实例后，我希望未启用且无占用的旧记录自动消失；仍启用的旧实例明确提示未发现，停用后再清理，不把它误报为空闲容量（`K14`）。
7. 作为自动化脚本或测试使用者，我希望保留 `--instances` 作为可选启动预设，按下述明确规则应用，以便批处理与测试脚本无需依赖网页手工点选也能启动即用。

## 实现决策 (Implementation Decisions)

### 1. 领域模型与持久化变更（内部开发阶段直接改写结构，不做旧库迁移）

- **数据表结构（存储模块）**：在 `instances` 表新增 `enabled INTEGER NOT NULL DEFAULT 0` 字段，用于持久化「已启用（`1`）」与「未启用（`0`）」状态；新增实例启停控制命令类型，与现有命令表与幂等去重体系共用事务提交边界。
- **同步与清理规则（`Store.sync_instances`）**：
  - MuMu 命令非零退出、超时、JSON 解析失败或实例集合结构无效均视为查询失败，不进入同步事务；只有成功返回的空集合才表示当前没有发现实例。
  - 不再按启动静态白名单丢弃扫描结果，而是同步 `MuMuManager` 返回的全部本机实例（写入/更新名称、按 `android_started` 映射为 `idle` 或 `offline` 及对应 `reason`，同时保留已存在行的 `enabled` 取值）。
  - 对于当前未发现（不在 `MuMuManager` 结果中）且无活跃/待对账任务占用的旧记录：若 `enabled = 0`（未启用，含停用已不存在的旧实例或命令行缩减预设后移出的编号），在同步事务内直接删除；若仍为 `enabled = 1`，先标记 `offline / not_discovered` 提示用户，用户点击停用或显式缩减预设后即自动清除。存在活跃或待对账（`needs_reconcile`）任务占用时一律保留，待占用结束再清理。
- **命令校验与拒绝边界（控制事务）**：
  - 启用/停用指令进入现有 `commands` 排队与 `Idempotency-Key` 幂等体系（与目标 `auto_record` 修改同构，采用显式目标值 `{enabled: bool}` 而非盲目 toggle）。
  - 若目标实例存在活跃任务（`job_id` 非空）、处于 `resetting`、或关联 `needs_reconcile` 任务，执行停用时返回明确业务错误（如 `instance_busy` / `reconcile_required`），拒绝停用；若尝试启用本机尚不存在且数据库无记录的编号，返回 `instance_not_found`（404）。

### 2. 启动参数与调度器演进

- **启动参数与配置校验**：将控制台运行入口中的 `--instances` 改为可选参数（默认 `None`）；允许调度器在初始「已启用实例数为 0」的情况下正常启动，并固定线程执行池为正整数上限（不再使用 `len(allowed)`，避免初始 0 个实例时线程池报错或后续动态启用多实例后并发不足）。
- **预设与持久化优先级**：未传 `--instances` 时不自动启用新实例，保留已有配置；显式传入时启用指定编号，并停用无占用的预设外实例，有占用的保留原配置。重复预设不重置已经启用实例的开机退避，只有从未启用变为启用才重置。预设不是持续生效的白名单，运行中仍可在界面修改。
- **派发与复位范围**：调度器 `_dispatch()` 在分配排队任务、`_instances()` 在触发 `resetting` 复位抖音时，从数据库动态读取 `enabled = 1` 且满足空闲/复位条件的槽位，不再依赖内存中的静态 `self.allowed`。

### 3. HTTP 接口契约与前端交互调整

- **只读与查询口径（查询层）**：
  - `Instance` 返回结构新增 `enabled: bool`；`GET /api/instances` 支持可选筛选参数 `enabled: bool | None` 与现有 `status`，按 `vmindex` 升序返回（涵盖已启用和本机探测到的未启用实例）。
  - `GET /api/overview` 中的 `instance_counts` 仅统计 `enabled = 1`（或有 `reconcile` 占用）的实例，确保总览指标只反映实际纳管录播池；可扩展辅计或前端直接从列表统计“未启用数量”用于轻量提示。
- **变更接口（API 层）**：
  - 新增 `PATCH /api/instances/{vmindex}`，请求体 `{enabled: bool}`，必须携带 `Idempotency-Key`；提交后返回 `202 {command_id, status}` 并由前端复用既有命令轮询器追踪到终态后立即刷新列表与总览。
- **前端界面（控制台前端）**：
  - 实例页移除“实例只查看，不提供操作”限制，新增「参与录播」开关列与「全部 / 仅已启用 / 仅未启用」筛选；当实例 `job_id` 非空或处于 `resetting` / `reconcile` 时，禁用停用开关并通过悬停提示说明原因；对未启用实例给出清晰的语义状态标签（区分“未启用（本机已开机/未开机）”）。
  - 总览页下方实例卡片条带只展示已启用（及待对账）实例，当存在未启用本机实例时显示引导提示（跳转实例页勾选），避免把未纳管模拟器混入总览。

## 测试决策 (Testing Decisions)

2026-11-12 审查修正的回归范围与结果见[验证记录](../../../docs/证据/验证/20261112-实例控制与按需开机审查修正验证.md)。

- **良好测试标准**：只通过公开接口与外部行为边界断言结果（HTTP 响应体、命令终态、任务是否派发/拒绝、重启持久化结果、界面渲染与接口调用），不测试内部私有辅助函数或 SQL 拼接细节。
- **测试边界（Seams）—— 优先复用现有高层边界**：
  1. **后端单一高层边界**：沿用现有调度集成与控制台 HTTP 沙盒边界（`FastAPI TestClient` + 真实 SQLite `Store` + `Scheduler.tick()`，仅替换外部 `MuMu` 探测器与 `Worker` 子进程替身）。覆盖：
     - 不传 `--instances` 正常解析与启动，首次发现实例默认 `enabled=false`；
     - `PATCH /api/instances/{vmindex}` 的幂等去重、成功启停、忙碌/复位/待对账拒绝停用、重开服务持久化保留；
     - 调度派发仅命中已启用空闲实例，关闭实例不再接新任务；
     - 本机未发现且未启用、无占用的旧行被清理；仍启用的失联旧行保留离线提示，停用后清理。仅缩减预设但仍存在于本机的实例继续在实例页显示为未启用，不计入总览；失败扫描不删除或改写实例（`K14` 回归）。
  2. **前端接口与交互边界**：沿用现有前端 `Vitest` 单测边界（mock `fetch` 与 `OperationDeps`），覆盖新增 `patchInstance` / `instances({ enabled })` 请求参数构造、命令轮询联动与实例状态/错误提示映射，并执行完整 `npm test` 与 `npm run build` 验证。
  3. **实机本地验收**：在本机真实运行不带 `--instances` 的调度控制台进程，确认页面准确探测并展示本机两个 MuMu 实例（`#2`、`#3`）及开关持久化生效。

## 范围外说明 (Out of Scope)

- **暂不实施 `T8`（按需自动开机 MuMu）**：仍保持调度器不自动开关模拟器的现状；`ADR 0018` 为后续 `T8` 预留了“仅作用于已启用实例”的前置边界，本轮不改开机逻辑。
- **暂不实施 `T9`（切片打开目录）与 `T10`（停录关闭抖音）**：留待本项改完验收后再单独推进。
- **不做旧运行数据库迁移兼容**：本次与按需开机变更统一使用数据库格式版本 `3`；拒绝打开旧版本并提示使用新的独立数据目录，不覆盖或迁移旧数据库。
- **不新增实例重命名、删除模拟器或远程开关模拟器功能**：仍由 MuMu 多开器自行维护实例生命周期。
