## 1. 背景与目标

切片保存在录制机文件系统中，原控制台仅支持复制路径，复核录像需要手动寻找文件。本功能在切片列表和任务详情的公共表格中增加“打开目录”，让本机和可信私网设备均可发送桌面定位请求。

远程点击操作的是录制机文件管理器，不在手机上下载或打开录像。文件管理器启动成功不等于桌面已显示窗口，提示必须说明请求已发送，并让用户在录制机桌面确认。

## 2. 实现选择

- 使用 `(job_id, segment_index)` 实体主键寻址；不接收前端任意路径。后端规范化数据库中的文件路径，并检查位于当前 `output_dir` 白名单内。
- 文件存在时请求高亮定位；文件不存在但父目录存在时请求打开父目录；资源缺失、越界或进程启动失败必须明确报错。HTTP 参数、错误码和响应字段以接口契约为准，不在方案中重复维护。
- 桌面操作为即时接口，不入持久化调度命令队列，不自动重试，不依赖调度器正在运行。请求期间及完成后 1.5 秒禁用同一表格的打开目录操作。
- 断线或连接尚未确认时禁用打开目录，并在处理函数入口再次检查；复制路径仍可用。恢复连接后自动解除连接限制。
- 可信内网客户端均可触发。前端按访问主机名区分本机和远程提示；这只是提示分类，不是权限判断或实际桌面位置探测。
- 长路径采用单行省略和完整路径悬停提示；按钮不随文字压缩。“常驻”指不被长路径挤掉，不代表表格横向滚动时固定在视口。

## 3. 已实施文件与调用方式

| 文件 | 实现职责 |
| --- | --- |
| `src/orchestrator/queries.py` | 查询单个已登记切片 |
| `src/orchestrator/api.py` | 即时接口、路径白名单与存在性检查、统一错误响应和完整启动异常日志 |
| `src/orchestrator/desktop.py` | `reveal_in_file_manager` 组装定位/打开参数，`run_file_manager` 使用 `Popen`；异常向上传递 |
| `web/src/api/index.ts`、`types.ts` | 客户端方法和响应类型 |
| `web/src/components/SegmentTable.vue` | 按钮、连接状态保护、请求与冷却期 Loading、复制及准确反馈 |

路由使用同步 `def`，由 FastAPI 在线程池中执行；不额外调用 `asyncio.to_thread`。`Popen` 不等待资源管理器完成桌面展示。非 Windows 分支使用系统文件管理器打开目录，不能当作 Windows 高亮已通过的证据；测试应 mock 外部进程。

## 4. 验证与验收

自动化覆盖：

- 后端通过真实 HTTP 参数解析和数据库查表检查文件存在、文件缺失目录仍存在、目录缺失、记录缺失、未落盘和输出目录越界。
- 在真正的子进程边界模拟启动异常，文件定位及目录降级两分支均需返回失败，且服务日志保留异常。
- 前端验证本机/远程请求提示、后端错误不报成功、无路径不显示按钮、连接未知/断线禁用、复制仍可用、连接恢复后操作及跨行连击保护。
- 请求未完成时持续阻止重复调用，结束后保留 1.5 秒冷却；失败也应在冷却后解锁。
- 运行后端相关 pytest、前端 `npm test` 和 `npm run build`；数量及实际结果见验证记录。

T9 实机验收仍需：录制机交互桌面下从切片列表及任务详情定位并观察真实高亮；含空格和中文路径；文件丢失时打开父目录；笔记本/手机触发后的动作位置和提示；375px 五页相关表格长路径与按钮布局。SSH/服务启动方式的桌面可见性应单列，不用 HTTP 200 或进程创建成功代替验收。
