# MuMu 整场自动投稿真实使用测试方案

创建于 2026-11-20，同日获准从项目候选选一位在播主播，真实自动投稿一份仅自己可见的稿件。2026-11-21 按用户要求归档，归档类型为**余项转交**。

台式机已自动开录，在主动停止本场后自动投稿成功。用户在 B 站创作中心看到了原稿，并确认显示「仅自己可见」。原稿的 B 站回放音画及网页端稿件数量、投稿信息的核对转交 T16。真实扫码已成功，扫码后原账号下拉框是否自动更新继续由 T23 跟踪。[归档复核](../../../docs/证据/验证/20261120-MuMu整场自动投稿真实使用测试记录.md#2026-11-21-归档复核) · [剩余待办](../../../docs/待办.md#t16-投稿实测)

**执行人是收到实施指令的 AI。** AI 操作台式机、配置主播、等开录、跟踪上传，再用投稿账号打开 B 站回放并出具结果。用户发出实施指令即可。需要本人扫码或手机验证时，AI 打开官方登录界面，提示账号持有人完成认证，随后自行继续。

本轮验收一位主播的一场新录制，真实提交一份「仅自己可见」的 B 站稿件。MuMu 自动开录、正常收尾后自动交单，B 站上只有对应的一份稿件且能播放，整条流程才算通过。已有 0.2.0 联调用的是合成录像，真实扫码刷新可在本轮一并验收。[改造联调结果](20261120-mumu统一上传平台客户端改造实施方案.md#本轮联调结果) · [待办 T16、T23](../../../docs/待办.md#待做)

## 开测前

1. **连到实际受测机器。** 目标是此前实录用的台式机 `DESKTOP-VPIBHSS`。实施窗口在笔记本时，AI 用现有已授权的远程通道进入台式机，核对主机名，在台式机的交互桌面控制浏览器。MuMu 的 `127.0.0.1:8000` 和上传平台的 `127.0.0.1:8765` 均从台式机访问。笔记本的日常切换记录只用于比对配置。[台式机实录环境](../../../docs/证据/验证/20261120-T22双路四小时实机复验.md#环境与计时) · [日常运行配置](../../../docs/证据/验证/20261120-MuMu日常版切换记录.md#日常运行配置)
2. **让真实服务就绪。** AI 检查 MuMu 总览与 `GET /api/system`、上传平台 `GET /api/v1/system/health` 和 `GET /api/v1/platforms`。记录版本、部署编号、调度器和上传 Worker 心跳，核对 B 站真实引擎支持 `self_only`、平台可读录像目录及其 `sessions` 配置目录。优先复用就绪服务。台式机缺服务时，AI 自行准备匹配的 MuMu 版本、已验收的上传平台包及配套 B 站引擎，让 API 和 Worker 共用台式机的运行目录和引擎配置。需要新建运行目录时使用独立位置。遇到已有任务占用实例或服务时，先找空闲资源或等它结束。[运行说明](../../../docs/最小调度运行说明.md#设备与运行目录) · [已验收包及依据](20261120-mumu统一上传平台客户端改造实施方案.md)
3. **选定本轮对象，留好起点。** 使用实施指令指定的主播，或从获准用于本次私密试投的项目候选中选一位经调度确认在播的主播。候选暂未开播时由 AI 继续观察。选一台空闲实例，优先使用主播已有绑定且可用的投稿账号和分区，也可使用本轮扫码登录的账号及适合内容的可用分区。记下原有开关、绑定和该账号已有的相关任务。若账号或素材归属确实无法从指令和现有配置判定，AI 一次说明缺哪项信息。
4. **让这次运行可以续查。** AI 在仓外建立本批次记录，保存阶段、时间和取得的编号。用浏览器自动化操作正常页面，用台式机上的 PowerShell 7 或 Python 做观察和媒体抽查。需要长时间采样时，AI 自行准备或复用一次性脚本，按本场 `target_id`、`session_key`、`job_id` 筛选，取得上传任务编号后固定跟踪该任务。每个阶段写下结果，断开重连时从原批次继续。[文件存放约定](../../../README.md#项目目录与文件存放) · [控制台读取接口](../../../docs/控制台接口契约.md#2-读取接口及筛选)

## AI 执行的端到端测试

| 阶段 | AI 的操作 | 必须取得的证据 |
| --- | --- | --- |
| 1. 配好主播 | 必要时启用选定实例。新加在播主播时先选「仅手动录制（不自动开录）」，先给这位主播配置「自动投稿」。选定账号、填分区并保存，刷新后核对设置，再开启「自动录制」。已有主播正在录制时选下一场新录或另一位获准候选。 | 保存后的账号、分区、私密范围和两个开关。若需扫码，AI 从主播设置打开「管理投稿账号」，认证后直接检查下拉框是否出现该账号。能自动出现才记 T23 通过。沿用现有登录时 T23 记未覆盖，主流程继续。[主播自动投稿设置](../../../docs/最小调度运行说明.md#在主播页启用自动投稿) |
| 2. 等系统自行开录 | AI 观察主播、录制任务和台式机画面，等待 MuMu 检测开播并自动分配实例。以首个正式切片开始事件计时。 | 主播和房间身份与实际画面一致。记下场次、录制任务编号、直播间标题和北京时间。点击「立即开录」产生的任务无法证明自动开录通过。[任务和事件接口](../../../docs/控制台接口契约.md#2-读取接口及筛选) |
| 3. 正常收尾，核对本地录像 | 主播提前下播时，AI 等调度器确认并封好尾片。若开录约 20 分钟后仍在播，AI 对同一场次执行「停止本场」。AI 从切片台账定位本场 MP4，用配套 ffprobe 核对时长、音视频轨，并实际解码开头、中间、结尾的画面和声音。 | 记录实际收尾原因、正式切片及顺序、三处媒体抽查结果。提前下播已有完整成片即可继续。错房、未封口或损坏的素材记录为异常。[正常收尾规则](../../../docs/最小调度运行说明.md#在主播页启用自动投稿) · [媒体工具](../../../docs/最小调度运行说明.md#固定媒体工具部署) |
| 4. 观察自动交单 | AI 在「自动投稿 → 最近场次」等本场出现「查看任务」，读取原作品、任务快照、事件和回执。刷新后从原场次和切片再次打开。测试工具只观察交单结果，稿件由 MuMu 的整场流程创建。 | 此场对应一个作品和一个任务，账号、分区、`self_only`、有序素材均与本场相符，刷新仍是原编号。若需点「安排上传」或脚本代为提交才能建单，记录自动交单失败。[本机场次接口](../../../docs/控制台接口契约.md#本机主播自动投稿) |
| 5. 验证 B 站收到的那一份 | AI 持续跟踪原任务，取得回执和 BV 号后，在台式机浏览器用同一投稿账号打开 B 站创作中心。按本场标题、开录时间和 BV 号核对稿件数、可见范围、分区、标签与转载信息。打开实际播放页，播放与本地抽样对应的片段。 | 创作中心只有一份本场稿件，BV 号与任务回执一致，明确显示「仅自己可见」。留存播放器时间推进、对应画面及实际播放音频的观察结果。若当前工具取不到声音，AI 换用台式机可用的音频采集再核对，仍无法取得时将回放音频记为待验。浏览器要求本人登录时，AI 打开认证界面并在认证后继续。 |

## 等待、恢复与收尾

- **由 AI 等到有结果。** 录制和上传期间可每 30 至 60 秒观察一次。从 MuMu 的 `GET /api/uploads/session-uploads/{target_id}` 找本场，从上传平台的 `GET /api/v1/tasks/{task_id}` 及其 `/events` 查同一任务。B 站转码或审核中，保留原 BV 号，拉长查询间隔并继续等待。服务短暂掉线时重连原部署。回执不明时沿原场次、原请求只读查回，避免重复试投。每次续查更新最近状态和时间。[原单查回约定](../../../docs/控制台接口契约.md#mumu-向统一平台交单)
- **控制本轮影响。** 原任务受理后，AI 恢复本轮临时改动的主播开关和绑定，本轮新加的目标则停用临时录制与投稿。等实例空闲后恢复其原设置，再继续跟踪原任务。若交单失败或结果不明，先记录原状态、停止本轮新增录制意图，并保留原安排供查回。只处理本轮选定的对象，保留已有录像、任务和真实稿件。
- **按实测结果报告。** 五个阶段证据齐全记「通过」。出现重复稿件、误公开、错房、需要补单、音画错误或平台明确拒绝，记「未通过」并指出最早出错的环节。本人认证待完成、台式机访问无法恢复，或到达用户明确指定的观察截止时间仍在等待 B 站时，记录最后阶段、原编号及恢复位置。只有本地受理或只有 BV 号时，回放项保持待验。
- **由 AI 交付验收记录。** 在 `docs/证据/验证/` 写入当日实测摘要并更新 T16、T23 的对应项。用场次、录制任务、切片、作品、上传任务和 BV 号串起同一份录像，附受测版本、收尾方式、去除私人信息的截图或日志位置、音画核对和设置恢复结果。扫码图和账号凭据不进材料。需要用户介入时只说明必须由本人完成的动作，诊断、盯进度、播放和写结论均由 AI 完成。[证据约定](../../../docs/README.md#文档职责与入口)

手动选片作为独立用例另测。本场自然产生多片时，主流程仍应只建一份稿件。AI 可用同一稿件补核每一 P 的播放和顺序，只有单片时如实保留多 P 待验。[T16 投稿实测](../../../docs/待办.md#t16-投稿实测)
