## 1. 背景、事实与目标

### 1.1 本次调查依据

受测代码为 `3f7f5bc2f1a65e27863d39b0a96b38b91c314af6`，调查开始时工作区干净。2026-11-16 在本机 MuMu 实例 2、Android 15 上使用真实 Worker、30 秒切片和独立 ADB 观察器调查；观察器没有替换 Worker 取证、核验和恢复实现。

| 场景 | 已观察事实 | 结论边界 |
| --- | --- | --- |
| A 录制中通过房间链接跳转 B | B 的 room_id、UID 均可独立读到；返回后复用原 LivePlayActivity 实例和任务号；切房后观察 125 秒，其中实际 B 身份的首末采样相隔约 116 秒；没有自动纠偏，身份时间仍为开录前的旧时间 | 跳转曾短暂经过 DeepLinkHandlerActivity，不能描述成整个操作从未离开直播 Activity |
| 切房后继续切片 | 观察期间完成 4 片；第 2 片抽帧确实显示 B，文件名仍属于 A，事件沿用旧 verified | 已复现受控错房录制；不据此声称历史生产任务自然发生过相同问题 |
| 三次上滑 | room_id、UID 和抽帧仍为 A | 未实际切房，不计入滑动切房通过或漏检样本 |
| Home 离开直播页 | 约 18 秒触发 runtime_left_live_page，约 35 秒重新核验 A 并恢复录制 | 现有离页恢复可用，但不能替代同 Activity 内的身份检查 |

原始材料按仓库根目录相对位置保存在 `../mumu_lbcut_tool_dev/mumu_lbcut_tool_tmp/k17-runtime-20261116-b7e9/`，包括 `probe.py`、`probe.log`、`observations.ndjson`、`worker-events.ndjson`、`summary.json`、`analysis.json`、`media-check.json`、Activity 原始转储、抽帧和录像。本方案不复制私人原始材料进 Git，不清理仓外材料。

### 1.2 实施前的缺口

- [ContinuousSession.poll_surface](../../../src/worker/continuous_session.py) 检查前台直播 Activity 和窗口遮挡，没有比较当前房间身份。
- 同文件的 `sync/collect` 处理切片登记、媒体校验和终态，不重新取证。
- [Navigator.inspect_live_surface](../../../src/worker/navigator.py) 返回窗口信息，不返回房间双标识。
- [Controller._locate_target_room](../../../src/worker/controller.py) 在初始定位和重新定位时核验身份；持续采集没有独立周期触发。

### 1.3 目标

1. 即使 Activity、任务号、帧率和文件增长都正常，也持续检查当前房间是否仍匹配原任务。
2. 短暂缺项或页面过渡允许有界复核；稳定错房和长期失证不能无限继续录制。
3. 异常后恢复原目标，同时保留可能受影响录像的风险记录，包括已经完成的切片。
4. 心跳和控制台能区分历史核验、当前待确认和证据过期，不再让旧 verified 掩盖长期未核验。

## 2. 范围与非目标

### 2.1 本方案范围

- 运行期只读身份探针、周期调度、稳定复核、失证截止时间。
- 与已有离页、遮挡、卡顿、采集恢复和停止流程的协调。
- 身份事件、心跳字段、切片风险、后端查询和前端展示。
- 对应自动化测试、实机回归、文档移交和 K17 验收记录。

### 2.2 非目标与保证边界

- 不按昵称、主播画面、Activity 名称或目标 Intent 推断身份；不改变任务期望的 room_id、UID，也不将 B 自动接管为新的录制目标。
- 不重写采集架构，不新增通用插件框架、数据库迁移或兼容层；本项目内部开发约定继续适用。
- 不删除、裁切、覆盖已有录像，不改写已经完成切片的终态或任务归属。
- 不新增上传服务；当前项目未交付上传服务。本方案不承诺撤回用户已复制或交付的文件。
- 周期采样不能保证每一帧身份正确，也不能保证捕获发生在两次采样之间、随后自行返回的短暂切房。目标是有界发现持续异常并准确表达不确定性。
- 10 秒等参数最初为建议值；实施阶段已按实测说明原因并修订，最终多实例负载与长录依据见实施验证，不将有限样本当作所有客户端性能保证。

## 3. 推荐参数与时间语义

首版使用集中定义的内部常量，不新增用户必须配置的选项；测试可注入时钟和观察器。

| 参数 | 建议值 | 精确定义 |
| --- | --- | --- |
| 正常巡检周期 | 10 秒 | 按一轮首次观察的启动时间计算下一轮到期时间；一轮未完成不叠加、不补发积压轮次 |
| 单次只读观察预算 | 5 秒 | 覆盖前台上下文、Fragment 读取和必要的上下文复查，所有 ADB 子命令共享同一截止时间，预留客户端超时清理；不是每条命令各 5 秒 |
| 稳定样本间隔 | 至少 1 秒 | 上次独立观察完成后再等待至少 1 秒，才开始下一次；同一 dump 不重复计数 |
| 匹配确认 | 连续 2 次 | 两次均取得完整且匹配的双标识，且属于当前有效检查上下文 |
| 冲突过渡宽限 | 5 秒 | 从本次异常 episode 中首次可靠冲突被接受时计时；之后需两次相同冲突的独立观察，且这两次观察都在宽限结束后开始 |
| 默认失证上限 | 30 秒 | 从最近一次可靠确认的保守时间点计算；已有异常时还受该异常首次出现后 30 秒的上限约束，取更早者 |
| 开录前只读复核窗口 | 最多 30 秒 | 一次启动准备流程共用，不随采集启动重试重置；单次观察仍为 5 秒，成功条件仍为两次完整匹配 |
| 停止采集预算 | 最多 8 秒 | 自发出停止决定计时，包含停止命令、必要的强制结束及退出确认；不包含之后的重新定位和文件异步校验 |
| 恢复预算 | 沿用现有值 | 所有运行期恢复共用 5 分钟内最多 2 次，不为身份检查另开额度 |

所有调度、宽限、样本有效期和恢复预算使用单调时钟。事件的显示时间仍使用墙上时间，单调时间不作为跨进程可比较的时间戳。

一轮正常匹配包含两次观察，最慢预算约为 `5 + 1 + 5` 秒；不能把“一轮”误解成只读一次。耗时超过正常周期时只启动下一轮，不补发积压请求。异常后按至少 1 秒间隔加快复核，但仍遵守单次预算和总截止时间。新一轮采集被接受后立即安排首轮检查，之后按正常周期运行；不能通过开新切片刷新确认时间。

默认严格模式下，30 秒限制的是“决定停止未经确认的持续采集”，不是恢复完成时间；不能到期后再开启容忍期或等待完整遮挡操作结束。所有在持续采集期间执行的阻塞操作均受剩余身份期限约束，按第 6.4 节及时退出并交给主循环停止。真实设备仍存在调度及退出延迟，分别记录异常发现、停止决定、采集停止完成和恢复完成时间，不把发出停止命令当作停止成功。

## 4. 只读取证设计

在 `navigator.py` 增加独立运行期观察入口，例如 `inspect_live_identity(deadline, stop_requested)`。命名可随现有风格调整，职责不变。

### 4.1 观察内容

1. 新鲜读取前台 Activity 及真实任务上下文，记录采样开始时间。
2. 当前确为直播页时只转储实际前台直播组件，校验输出任务号与 Activity 实例后，复用 `current_live_fragment_evidence` 的保守解析；不请求含后台任务的整份 `activity top`，不解析历史目标 Intent，不接受 FROM_ROOM_ID 作为当前房间。
3. 复查前台上下文，排除在取证期间离页、换任务等跨页面结果；上下文不一致视为不可用。
4. 返回成功证据或明确的不可用原因，并携带开始／完成时间、采集代际及探针序号等关联信息。

ActivityRecord token、任务号和 RoomEvidence 中的 `activity_token` 含义不同，禁止混用。前者辅助判断上下文是否变化，后者不能承担“房间没变”的证明；房间始终比较同语义双标识。

### 4.2 不允许的副作用

- 不点击头像、资料卡、BACK、Home，不发送导航 Intent。
- 不调用会回退到资料页点击的完整 `observe_live_room()`。
- 不写主导航的 `_operation_deadline`、资料卡状态、焦点缓存或导航代际等可变字段。
- 不在探针线程更新 Controller 身份、恢复状态或 emitter 全局上下文；探针只返回结果，由主循环决策。

Fragment 缺项、冲突副本、超时或格式不合法时返回不可用，不为运行期另建宽松解析规则。复用 `compare_evidence`：两个有效标识匹配才通过，可靠可比较标识冲突不通过；若共享解析器只能给出完整证据，不从被拒绝的片段中另行拼出“可靠冲突”。

## 5. 核验状态与转换

运行期核验状态与 Worker 的 RECORDING/RECOVERING 分开管理。以下为内部状态，不能直接充当新的 Worker 状态枚举。

| 内部状态 | 条件与动作 | 对外身份 |
| --- | --- | --- |
| 已确认 | 最近取得两次稳定匹配；安排下一轮正常检查 | verified，并显示确认时间及证据年龄 |
| 待复核 | 首次缺项、超时、可靠冲突或上下文异常；创建异常 episode、记录风险起点、加快复核 | unconfirmed，不能继续显示旧 verified 为当前有效 |
| 需要纠偏 | 宽限后两次相同可靠冲突，或已有冲突一直无法消解而到期 | 稳定冲突为 mismatch；未形成稳定冲突时为 unconfirmed 并保留冲突未解决原因 |
| 允许未确认 | 用户原本显式允许未确认身份，且只有缺项、从未有未解决可靠冲突 | unconfirmed，持续风险提示，正常周期继续尝试核验 |
| 恢复／停止 | 退出日常检查，失效旧探针，按既有流程收尾 | 重新定位期间 unconfirmed；只重启采集保留身份上下文，按第 5.3、6.3 节完成对应准入 |

### 5.1 样本累计规则

- 连续两次完整匹配才更新最近确认时间；中间缺项、冲突或上下文变化会清空匹配计数。
- 冲突比较键为实际双标识组合；不同冲突组合不能凑成两次稳定冲突。
- 首次可靠冲突设置 episode 内的冲突锁存。后续缺项会清空连续冲突计数，但不解除锁存、不重置首次冲突时间。
- “B→缺项→C→缺项”即使一直不能形成稳定冲突，仍受同一个截止时间约束。
- 只有两次完整匹配，或结束当前采集并完成新的 K15 定位核验，才清除未解决冲突。清除当前冲突不删除历史录像风险。
- 新异常开始、恢复开始、用户停止时清空尚未完成的匹配／冲突样本，不能跨阶段拼接。

### 5.2 截止时间与显式例外

- 有可靠确认基线时，默认截止时间取 `最近确认 + 30 秒` 与 `episode 开始 + 30 秒` 中较早者。最近确认使用最终匹配观察的采样开始时刻，避免把较早读取的数据当成观察完成瞬间的新证据。
- 严格模式没有可靠确认基线时，不得通过正式录制准入，按第 5.3 节处理；显式允许未确认时，风险从本轮采集开始计算。启动准备已经消耗的证据年龄不能在进入 RECORDING 时重置。
- 队列阻塞、未发起探针、超时、缺项和轮次切换都不能刷新年龄。主循环独立检查年龄，不依赖 future 完成才发现超期。
- `allow_unconfirmed_identity` 只豁免纯失证导致的强制恢复；此时始终标记未确认，超过 30 秒只维持一次持续异常 episode，恢复正常 10 秒采样以避免忙轮询。
- 一旦获得可靠冲突，显式例外失效。若原本已长期失证，首次冲突另有不超过 30 秒的处置期限，不因已经过期而跳过稳定复核，也不允许无限续期。
- 能明确证明离页、登录阻断或设备离线时，交给对应恢复／失败路径处理；身份状态先失效，不能把非直播页直接比较为某个错误房间。

### 5.3 开录前的证据新鲜度与只读能力门禁

此门禁覆盖首次启动、重新定位后的启动和只重启采集后的启动，位于 `start_epoch` 的准备阶段；不得先发布正式 `capture_session started`／`segment_started` 再判断证据是否过期。

1. K15 在最终稳定匹配观察开始时同时保存墙上时间和单调时间，并随 `LandingResult` 向 Controller 传递确认基线；运行期复核采用相同语义。单调时间只在本 Worker 进程内使用，不能用 `observed_at` 的墙上时间差倒算，也不能把接收定位结果的时间当成确认时间。
2. 在启动采集前和正式录制准入前分别检查基线。基线缺失、年龄达到 19 秒（提前预留双样本预算）、或本次定位只通过资料页取证而尚未证明当前页面支持只读核验时，在准备阶段完成两次新鲜完整匹配；一轮门禁最多 30 秒，采集启动重试不能重置这个窗口。
3. 等待画面和管线启动会继续消耗证据年龄。准备阶段若已产生临时媒体，继续按现有准备产物规则保存；门禁通过前不登记为正常切片，门禁失败不得发布“录制成功”。实际媒体包含证据过期或未确认区间时，严格模式在重新确认后停止并保留该准备目录，重新启动临时采集，不发布旧媒体为正式切片，也不消费运行期恢复额度；显式允许纯未确认而接纳已有媒体时，从采集起点标记未确认风险，后续恢复匹配按第 7.2 节封闭风险边界。
4. 两次匹配成功且正式接纳瞬间仍未过期，才进入 RECORDING。准备阶段如果发生页面改变或可靠冲突，先停止准备采集，沿用 K15 有界重新定位；不得把同一次过期事实变成运行期反复恢复。
5. 仅因缺项／超时一直不能完成只读门禁时，严格模式以 `runtime_identity_probe_unavailable` 结束准备，不消耗运行期恢复次数，不反复导航尝试刷新年龄。其含义是“本次无法建立运行期只读核验”，不能断言客户端永久不支持。
6. 显式允许未确认时，纯失证可以按既有例外准入，但必须是 unconfirmed 并从媒体起点标风险；已有未解决冲突仍不允许准入。过期复核不能代替或绕过 K15 的冲突处理。

### 5.4 资料页核验成功但 Fragment 持续不可用

K15 能通过资料页确认身份，不等于 K17 能在录制中持续只读确认。首版不在录制中周期打开资料页，也不把资料页成功当成只读能力恢复。

- 首次准备发生此情况时执行第 5.3 节的能力门禁；严格模式失败后直接结束该任务，不进入“录 30 秒—重新定位—再录 30 秒”的循环。
- 已运行后持续失证，最多先按本次异常触发一次重新定位；新的启动仍必须通过能力门禁。若资料页再次成功、只读门禁仍失败，则结束为 `runtime_identity_probe_unavailable`，不再尝试下一个采集代际。
- 为避免调度器不断重建同一失败任务，计划将该原因映射到已有的 `needs_fix` 停止自动重试语义（退出码 9），显示“运行期身份核验不可用，需检查后手动重试”，不标成“房间不存在”或“身份冲突”。后端原因映射和对应测试同步调整；不新增永久能力黑名单或数据库迁移。
- 用户检查环境后通过既有人工重试／重新启用流程再尝试。只有纯失证的显式例外允许继续带风险录制；冲突不能以能力不足为由降级放行。

## 6. 并发、恢复与退出

### 6.1 调度归属

在 `ContinuousSession` 主循环调度身份检查。身份探针使用有界单任务执行通道，不因媒体校验积压而长期排队；不创建每轮一个的新线程池。窗口检查继续存在，不能被身份探针替代或饿死。

每次请求绑定 run_id、采集 generation/epoch、观察序号及当时预期身份快照。接收结果时检查这些信息、预算和是否已经停止；旧代际、迟到、取消或已被其他恢复作废的结果仅记录丢弃原因，不改变状态、不重复恢复。

探针线程不操作页面；但在主循环准备进行导航或遮挡处理时，仍应停止派发并作废已发请求，避免把跨操作读取误认为同一页面证据。超时取消不能只调用 `future.cancel()`：ADB 子命令必须有剩余预算，退出等待也必须有界。

### 6.2 统一恢复

按顺序执行：

1. 接受异常事实、登记风险、更新对外身份；即使预算耗尽或用户正在停止，也不能跳过风险登记。
2. 主循环统一仲裁恢复原因，避免本轮 watchdog、窗口探针和身份探针各触发一次恢复。设备离线和用户停止优先；已发现的身份风险保留。
3. 通过现有 `recover(reason, relocate=True)` 及共享预算停止当前采集并收尾。建议原因码：`runtime_identity_mismatch`、`runtime_identity_unavailable`、`runtime_identity_conflict_unresolved`。
4. 调用原目标的 `_locate_target_room()`，复用 K15 的预算、稳定确认、资料页回退及冲突不可绕过规则；这些主动页面操作只发生在停止当前采集之后。
5. 定位成功且画面就绪后启动新代际；失败、离线或预算耗尽沿用现有失败退出与调度退避，不擅自改目标或继续旧采集。

其中重新启动后的只读能力门禁失败按第 5.4 节进入需处理状态，不进入普通自动退避重试。

停止、录满、探针结果同一轮发生时：不再启动新探针或恢复；先处理已经接受的异常事实及风险，再完成唯一切片终态。尚未完成的观察不能被宣称通过，证据已过期时保留未确认风险。

总时长仍遵循现有录像时间语义，错误／待确认期间已经录下的时间不自动补录。`worker_stopped`、完成带警告和失败状态保留现有区分，不把恢复成功解释为整场录像无风险。

### 6.3 只重启采集时的身份状态继承

身份确认基线、未解决冲突及异常截止时间属于 Worker 的目标身份上下文，不属于某一采集代际。媒体账本和探针请求才绑定代际。

| 重启前情况 | 采集进程退出／文件停滞要求 `relocate=False` 时的处理 |
| --- | --- |
| 身份新鲜、无异常 | 可以只重启采集；保留原确认时间，经过第 5.3 节准入，不因为 generation 增加而刷新年龄 |
| 纯缺项但尚未到期 | 保留未确认状态、原截止时间和异常起点；新代际按保守范围承接未解决风险，不能重新获得 30 秒 |
| 存在未解决可靠冲突，或严格模式已过期 | 将该次恢复升级为重新定位；只消费一次共享恢复预算，不先重启采集再额外触发一次纠偏 |
| 纯缺项且显式允许未确认 | 可以只重启采集，但保持 unconfirmed，新代际从起点标风险；出现冲突后按上一行处理 |

恢复开始可以清空连续样本计数、使旧 future 失效，但不能清掉冲突锁存、首次异常时间、处置期限或确认基线。只有两次新鲜匹配或新的 K15 稳定核验才解除未解决冲突；发布正式录制还需满足准备门禁。

旧代际风险记录保留到其切片全部收尾，新代际不复用旧切片索引或媒体时间。若身份异常仍未解决，新代际建立自己的受影响范围；只有异常已解决且旧媒体边界已封闭时，才能不继承持续风险。

### 6.4 遮挡等持续采集操作的截止时间

- 遮挡关闭、画面等待和其内部 ADB／截图调用共用 `min(操作自身截止时间, 当前身份处置截止时间)`，不允许每个子步骤重新获得完整预算。纯失证例外没有强制停止期限，但已有冲突的期限仍有效。
- 身份期限到达时，等待回调设置“需停止／恢复”请求并退出当前操作；不在回调内嵌套调用 `recover()`。主循环接管后先记风险、作废旧探针，再统一停止采集。
- 以“最近确认后第 29 秒开始遮挡处理”为边界用例：不能继续使用完整 30 秒遮挡预算；剩余约 1 秒到期即退出并决定停止。不得等待遮挡处理完成后才第一次检查年龄。
- 记录 `anomaly_detected_at`、`stop_decided_at`、`capture_stopped_at` 和 `recovered_at` 及相应单调耗时；30 秒约束停止决定，停止确认使用独立 8 秒预算，重新定位和启动耗时另计。
- 8 秒内未确认采集进程退出时记录停止失败，不宣告已停止或恢复成功，不启动并行的新采集；按现有故障清理路径处理。停止与取消测试必须覆盖子命令超时及进程退出确认，不能只检查 future 是否取消。

## 7. 风险区间与切片处理

### 7.1 风险语义

- 首次异常产生 `identity_unconfirmed` 风险，风险起点回溯到最近一次可靠确认；没有基线时从本轮采集开始。
- 稳定冲突追加 `identity_mismatch` 风险。标签文案必须说明是“可能包含错房画面”，不能把整个回溯区间描述成已逐帧证明属于 B。
- 单次冲突后来恢复、纯缺项后来恢复，都不删除已经产生的风险；两次采样之间的内容无法事后证明。
- 正常情况下所有切片的“完成”只表示媒体校验通过，不能等同身份全程正确。

### 7.2 时间边界与保守映射

不能使用 ledger 当前的 `wall`（发现片段的时间）或异步校验完成时间判断录像是否受影响。

实施时保留 `Fragment.start_pts/end_pts`，并在身份采样起止时记录本代际媒体进度及其有效性。仅在验证过清单 PTS 与媒体进度处于同一时间轴、没有重置或异常跳变时做精确关联：

- 起点采用最近可靠确认那次观察开始时的媒体进度作为保守下界；没有可信值则回退到本代际起点。
- 已封口片段按实际 PTS 区间相交判断；未封口、待登记、待校验片段先保留 episode，后续登记／终态前再次检查。
- 终点必须覆盖恢复确认前已进入采集链路但尚未写出的数据。不能直接把“确认完成时 ffmpeg 当前进度”当作安全上界；只有实测并验证映射及缓存边界后才收窄。
- 无法证明上界、PTS 缺失／异常或进度长时间不更新时，保守标记到旧采集代际收尾，包括随后发现的片段，不使用任意固定秒数猜测缓存延迟。首版采用下述受控收尾规则，不能让一次已经解除的短暂失证把后面数小时的同代际录像一直标成风险。
- 确认错房会停止当前代际，其收尾自然提供风险上界；短暂缺项或单次冲突后取得两次匹配，但仍无法证明风险终点时，立即安排一次 `identity_risk_boundary_reset`：结束旧代际、保留其风险和原始媒体，再只重启采集。正常情况下不重新导航；若收尾／启动期间身份过期或出现新冲突，按第 6.3 节升级处理，不增加一份恢复额度。
- 该边界重建消费一次共享恢复预算，同一待关闭风险 episode 只安排一次；与已经决定的故障恢复合并。预算耗尽则停止任务，不选择继续数小时扩大风险；用户停止或已经录满时仅收尾，不重开。其实际代价是一次采集间断，事件和控制台须明确原因。
- 只有确认旧采集链路结束、旧代际后续发现的片段均已归入旧账本，且新代际通过准备门禁，才认为旧风险范围封闭。当前身份恢复 verified 不会撤销旧片风险，也不能提前宣告边界重建完成。
- 首版默认使用上述受控收尾建立可靠上界；如实施时不能给出可验证的精确时间映射，就不启用“仅靠时间映射、不断采集”的优化路径。将来启用该优化须单独补充算法与缓存边界证据。

上述保守回退是首版正确性要求；精确映射优化不能成为遗漏切片的理由。验证记录必须区分精确映射与保守扩大范围，不能承诺切房帧级定位。

### 7.3 终态与存储

- 复用 `SegmentQualityWarningEvent` 给已完成片段补风险；`Storage.record_event` 当前允许追加风险，不将 finished 改成 aborted。
- 因身份异常或风险边界重建实际停止采集时，当前受影响片段按既有 interrupted 规则收尾为 aborted，原始文件保留；不追加一个冲突的 finished。只有已经验证可靠风险上界而无需停止采集时，短暂异常恢复后的片段才可以仅追加风险并在媒体校验通过后正常 finished；首版默认采用第 7.2 节的受控收尾。
- 单个 episode 对每个切片、每种风险只发一次；同一片可以同时有未确认、冲突和其他质量风险。利用既有 event_id 防重放，不按整条文本生成摘要。
- `sync`、`collect`、恢复收尾和 `close` 都要应用未结算 episode，覆盖“风险先到、片段后登记”和“片段先完成、风险后到”。
- 新代际不继承已结束 episode 的旧片风险，但仍未解决的身份异常必须按第 6.3 节继续标记；旧片异步完成不得使用新代际 verified 为其身份背书。切片事件若携带身份上下文，必须取该片所属代际和风险快照，而非发射时的 Controller 全局状态。

## 8. 事件、接口与控制台

### 8.1 Worker 数据

建议新增专用 `room_identity_check` 事件，避免把只读巡检伪装成导航。至少包含 action、reason、generation_id、probe_id、实际 room_id／UID、证据来源、采样开始／完成时间、是否接受及判定结果。正常每轮仅汇总一次，异常记录状态变化和关键样本，避免每个主循环 tick 刷日志。

心跳保留 `room_identity_status`、`room_evidence_source`、`room_evidence_at`，新增：

| 字段 | 语义 |
| --- | --- |
| room_identity_checked_at | 最近一次完成且被接受的运行期观察时间；不可用观察也会更新，不能当成确认时间 |
| room_identity_confirmed_at | 最近一次稳定确认的保守采样时间；没有则为空 |
| room_identity_age_sec | Worker 用单调时钟计算的确认年龄；没有基线则为空 |
| room_identity_stale | 没有可靠基线或年龄达到 30 秒；与“首次异常立即 unconfirmed”分别表达 |
| room_identity_reason | 当前待确认、失证、未解决冲突或显式例外原因；正常时为空 |

失败观察不能刷新 confirmed_at 或旧证据来源。重新定位时使当前证据失效，内部保留历史确认时间、冲突和截止时间直至获得新的稳定结论；只重启采集按第 6.3 节保留身份上下文。历史字段不代表当前 verified；资料页重新定位成功后由 K15 建立基线，但仍需通过开录前新鲜度／只读能力门禁。

### 8.2 后端与前端

- `queries.py` 当前只从心跳投影部分身份字段，需与 `api.py` 的严格响应模型一起扩展，不能只增加 Worker 字段后认为前端已经可见。
- `JobResponse`、`web/src/api/types.ts`、mock 和接口断言同步上述字段；复用 JSON 事件／心跳存储，不为本方案新建数据库列或迁移既有库。
- `JobDetail.vue` 展示最近确认时间、年龄、待确认原因及恢复结果；`JobsView.vue` 标签区分已确认、待复核／未确认和冲突。心跳过期或任务结束时显示最近报告状态，不能让浏览器把旧数据当作实时核验。
- `labels.ts` 增加风险和恢复原因文案。切片风险展示沿用现有 quality_flags，已完成切片追加风险后能够刷新显示。
- 不改变现有“完成带警告”的判定：存在身份风险也应完成带警告，后续恢复不能将其变回无警告。

接口的正式字段说明已移交[控制台接口契约](../../../docs/控制台接口契约.md)。

## 10. 验收矩阵

### 10.1 自动化验收

沿用 `test_identity_stability.py`、`test_continuous_and_overlay.py`、`test_continuous_real_transport.py` 及现有调度／接口测试入口，按职责补充用例，不复制实现细节充当测试。

| 场景 | 必须验证的行为 |
| --- | --- |
| 正常 A 长录、多个切片 | 周期检查双样本，证据持续刷新；不点击页面、不重启采集、不增加断片 |
| 同 Activity 稳定 B | 不依赖 Activity 变化；过渡宽限后确认冲突、标风险、仅触发一次恢复 |
| A→短暂缺项→A | 两次完整匹配才恢复确认；单次缺项不立即重启，匹配恢复后无法证明风险上界时只重建一次边界，历史风险保留 |
| A→单次 B→A | 单次冲突不直接确认错房；冲突锁存只由稳定匹配清除 |
| B→缺项→C 持续交替 | 计数正确重置、异常期限不续期，到期恢复，例外不能绕过 |
| 整轮超时／探针未派发／队列拥塞 | 独立年龄检查生效，不能永久保持 verified；子命令和退出等待有界 |
| 纯缺项且显式允许未确认 | 不误报 verified、不忙轮询；出现冲突后受处置期限约束 |
| 只读探针与导航、遮挡交错 | 无页面副作用、无共享导航变量污染；跨操作结果丢弃 |
| 旧代际迟到匹配／冲突、重复完成通知 | 不更新新代际、不双重恢复、不跨轮累计样本 |
| 系统时间前跳／回拨 | 周期、宽限和到期不变；展示时间不参与时限计算 |
| 片段已完成／校验中／未封口／尚未登记 | 全部相关片段追加风险，终态仍唯一，文件不删除 |
| PTS 缺失、进度滞后／重置、异步收尾 | 保守范围生效，不把发现时间当内容时间，不漏延迟出现的片段 |
| 预算耗尽、设备离线、用户停止、录满 | 已发现风险不丢失，退出原因正确，无新恢复，原始数据保留 |
| 接口、重放、前端刷新 | 字段贯通、风险不重复、完成片风险能后补、完成带警告不被恢复抹除 |
| K15 后慢画面／慢采集启动使证据达到 30 秒 | 正式事件发布前在准备阶段重新取得两次匹配；复核共用有界窗口，不先进入 RECORDING 再循环消耗恢复预算；准备媒体保留且不伪装成全程已确认 |
| K15 资料页成功、Fragment 持续不可用 | 严格模式准备失败为 runtime_identity_probe_unavailable，调度进入 needs_fix 而非自动无限重建；运行中首次失证恢复后能力仍不足同样停止；显式例外只允许纯缺项 |
| 一次 B 冲突与采集进程退出／文件停滞同时发生 | 只重启升级为重新定位；仅消费一次恢复额度，不清除冲突锁存或重置期限，新代际不能直接继承旧 verified |
| 无冲突的只重启采集 | 保留原确认年龄；纯缺项的未到期期限跨代际延续，已过期严格模式升级定位；未解决风险在新代际从起点标记 |
| 第 29 秒开始遮挡操作 | 到身份截止时间退出操作并决定停止，不继续等待完整遮挡预算；回调无嵌套恢复，停止完成时间单独记录 |
| 短暂失证恢复但媒体上界不可证明 | 一次受控边界重建使旧风险封闭；旧片迟到仍有风险，新代际正常片不继承已解决风险；预算耗尽、停止或录满时不重开 |

合成测试固定时钟验证预算和转换；不能把其中的毫秒级响应当作真实设备性能。

### 10.2 必要实机验收

1. **同 Activity 的受控切房**：沿用独立观察器和真实 Worker；A→B 后分别记录外部首次确认 B、Worker 首次异常、确认冲突、停止采集、重新定位成功及新代际首帧时间。必须在配置的检查／复核期限内推进处置，不能等待下一切片或其他故障触发；恢复耗时另计。
2. **跨切片风险**：在切片边界前后分别切房，检查原始录像、已完成 MP4、事件和控制台风险；至少覆盖一片已经完成后才补风险。风险回溯不能只看日志而不看成片内容。
3. **正常录制**：至少连续 30 分钟并跨多个切片，核对无探针导致的页面操作、额外恢复或漏核验；记录探针耗时和帧率／采集异常。此项不等于长期稳定性背书。
4. **既有恢复回归**：Home 离页及可安全复现的遮挡场景仍正常恢复，身份检查不重复消耗预算或造成无休止重启。
5. **多实例负载**：使用两台确认空闲且在本次测试范围内的实例同时正常录制至少 10 分钟，记录探针耗时、完成轮次、超时和采集情况；不影响用户已运行任务。没有可用实例时保持待验证，不能以单实例替代。
6. **审查新增边界场景**：在隔离输出下验证慢画面／慢启动后的准备复核、资料页成功但只读持续失证的停止与人工重试状态、身份冲突与采集故障同时出现、临近期限的遮挡退出，以及短暂失证后的风险边界重建。自然环境不能稳定触发的条件允许用明确标注的探针注入覆盖，但必须分列“真实设备上的受控注入”和“自然发生”；不能将注入结果宣称为自然故障复现。记录两种时间：停止决定是否遵守身份期限、真实进程是否在独立停止预算内退出。
7. **收尾**：只停止本次进程／实例，确认锁释放；日志、录像和截图保留在独立仓外目录，不进入 Git。

滑动切房单列补验：只有实际双标识和画面已换房才计入覆盖；若当前客户端仍无法通过滑动切房，如实记录未覆盖。受控同 Activity 切房通过可证明本方案核心路径，但不能据此声称所有自然切房方式通过；是否关闭该补验应在最终验收中明确，而非悄悄当作成功。

| 风险或待验证项 | 处理方式 |
