## 问题陈述 (Problem Statement)

在自动录制抖音娱乐/PK直播间时，用户和上层调度系统面临三大核心痛点：
1. **多路录制系统耦合严重**：以往系统将多模拟器管理、任务检测轮询和录制执行混在一套单体进程中，单路异常或崩溃极易波及全局，且难以灵活扩展到 2 路以上的任意路数；
2. **长时间录制音画脱节（累积漂移）**：模拟器运行 6–8 小时时，由于渲染丢帧和时间戳偏差，录制文件后期出现严重的声音快于画面的脱节现象；
3. **直播推流偶发卡死死锁**：长时间运行中抖音客户端或网络抖动偶发画面静止，常规的屏幕手势滑动容易误触发切房（换到别的主播）或清屏，导致有效录像中断或内容被污染。

---

## 解决方案 (Solution)

构建轻量、无状态、工业级的**单路“录播 Worker（执行单元）”**：
1. **进程级解耦**：Worker 作为独立 CLI 子进程运行，仅负责纳管单一指定 MuMu 实例并直达目标直播间，并发多路能力由外部调度软件（Orchestrator）拉起多个 Worker 进程自然实现；
2. **单调硬件 PTS 对齐 + 30 分钟周期切片**：录制管线强制绑定 Android 系统底层 PTS，每 30 分钟顺滑封口一个 MP4，新建切片时时间轴物理归零，从根源上彻底消除音画累积漂移；
3. **无副作用原地自愈看门狗（Stall Watchdog）**：严禁屏幕拖拽手势，在检测到推流卡顿超 10 秒时，通过同房间 ID 的 Intent 原地唤起，触发抖音播放器内核原地重新建链拉流，秒级恢复画面渲染且完整保留弹幕与比分；
4. **标准 NDJSON 事件输出契约**：Worker 标准输出严格以单行 JSON 流式输出事件（心跳、切片、自愈、下播退场），便于任何外部调度程序非阻塞监听。

## 用户故事 (User Stories)

1. 作为外部调度系统（Orchestrator），我希望能够以独立命令行子进程拉起一个录播 Worker（传入实例索引、目标直播间与输出目录），以便于以极简的进程模型管理任意多路并发录制任务。
2. 作为用户或调度程序，我希望传入的直播间目标可以兼容分享口令、短链链接（`v.douyin.com`）、网页 URL 或纯房间号，以便于无需前置清洗即可直接唤起录制。
3. 作为审核/回放人员，我希望连续录制数小时的视频每 30 分钟生成一段独立完整的 MP4 文件，以便于视频可随时播放且各分段内音画绝对同步、毫无脱节。
4. 作为用户，我希望录制过程中若因网络抖动或客户端卡死导致画面定格超 10 秒时，系统能自动在后台原地恢复推流，以便于录制不中断且不会切到别的主播房间。
5. 作为外部监控程序，我希望能够从 Worker 的 stdout 中实时读取到单行 JSON 格式的心跳与状态事件，以便于无须跨进程文件锁即可精准掌握当前录制帧率、切片文件与自愈动作。
6. 作为用户，我希望当主播主动下播或直播间封禁时，Worker 能自动完成当前切片视频封口并正常退出（返回明确退出码），以便于避免空转录制数小时黑屏并通知调度器回收资源。
7. 作为外部调度系统，我希望在需要提前终止录制时向 Worker 发送标准中断信号，Worker 能平稳完成当前 MP4 尾部索引封装，以便于确保已录制视频 100% 完好可播。

## 实现决策 (Implementation Decisions)

### 1. 模块组织架构
```text
src/worker/
├── __init__.py
├── cli.py               # Worker CLI 入口与参数解析（--vmindex, --target, --output-dir, --segment-duration）
├── events.py            # NDJSON 事件结构与标准输出流发射器
├── resolver.py          # 智能宽容直播间解析与开播校验器
├── navigator.py         # ADB Intent 秒级直达与系统弹窗放行
├── pipeline.py          # 基于 scrcpy 数字流的 MP4 切片录制器与 PTS 时间戳对齐
├── watchdog.py          # 卡顿看门狗线程（文件增长探测 + 原地 Intent 自愈）
└── controller.py        # Worker 主控制循环与生命周期管理（退出码语义封装）
```

### 2. 外部接口与命令契约 (CLI Contract)
```powershell
python -m src.worker.cli \
    --vmindex 2 \
    --target "https://live.douyin.com/737141" \
    --output-dir "D:/records/anchor_A" \
    --segment-duration 1800 \
    --stall-timeout 10
```

### 3. NDJSON 标准事件流规范 (stdout)
- **切片启动**：`{"event": "segment_started", "segment_index": 1, "file_path": "...", "timestamp": 1792458000}`
- **运行心跳**：`{"event": "heartbeat", "elapsed_sec": 300, "segment_elapsed_sec": 300, "file_size_mb": 45.2, "fps": 29.8, "status": "recording"}`
- **卡顿自愈触发**：`{"event": "stall_detected", "stall_duration_sec": 10, "action": "intent_reconnect"}`
- **自愈成功**：`{"event": "stall_healed", "action": "intent_reconnect", "latency_sec": 1.2}`
- **切片完成**：`{"event": "segment_finished", "segment_index": 1, "duration_sec": 1800, "file_size_mb": 270.5}`
- **下播结束**：`{"event": "stream_ended", "reason": "anchor_offline", "exit_code": 2}`

### 4. 退出码语义 (Exit Codes)
- `0 (SUCCESS)`：正常停止（达预设时长或接收到调度器停止信号并封口完成）；
- `2 (STREAM_ENDED)`：主播已下播或直播已结束（切片已封口，通知调度器无需重试）；
- `10 (TARGET_INVALID)`：输入的直播间标识无法解析或格式错误；
- `20 (DEVICE_UNAVAILABLE)`：指定的模拟器实例或 ADB 端口不可连且自愈失败；
- `30 (RECORDING_FAILED)`：录制管线不可恢复崩溃。

## 测试决策 (Testing Decisions)

### 1. 核心测试 Seam（高层唯一测试 Seam）
- **Seam 定义**：`WorkerController` 顶层运行入口（即 `cli.py` / `controller.py`）。
- **测试标准**：严格以“黑盒外部行为断言”为原则，只测试从 CLI 接收参数到 stdout 抛出的 NDJSON 事件流序列，以及最终落盘的 MP4 文件属性；绝不刺探控制器内部私有状态。

### 2. 核心覆盖测试场景
1. **启动与正常切片生成**：验证传入有效直播间后，是否按期产生 `segment_started` -> 连续 `heartbeat` -> 达到切片时长后生成 `segment_finished` 并无缝开启新切片；
2. **下播主动退场**：注入直播间下播信号，验证 Worker 是否平稳封口当前视频并以退出码 2 优雅退出；
3. **看门狗原地自愈**：模拟 scrcpy 停止输出或画面冻结 10 秒，验证 Worker 是否自动触发原地 Intent 并在流恢复后抛出 `stall_healed` 事件；
4. **外部中断信号封口**：模拟接收外部 SIGINT / CTRL_BREAK 信号，断言进程平稳退出且 MP4 索引（moov atom）正常闭合。

## 范围外说明 (Out of Scope)

1. **多任务调度系统（Orchestrator）**：定时扫描直播间开播、空闲实例池调度分发、Web 仪表盘均属于前半段调度系统，本 Worker 不负责跨任务调度；
2. **AI 高光与视频剪辑**：不涉及录制产物的二次加工；
3. **屏幕手势拖拽模拟**：因切房与清屏风险，本系统严禁包含手势拖拽滑动逻辑。

---

## 补充说明 (Further Notes)

- 本 Worker 架构天然兼容后续外部调用者（Python 脚本、Go/Node 调度后台、或现成分布式调度框架）；
- 录制引擎持续复用已验证的 scrcpy v5.0.1 二进制组件与 MuMu 自带 ADB。

## 实施与验证总结

- **实施代码**：位于 `src/worker/` 模块，包括 CLI 入口、事件协议、直播间解析器、ADB 导航器、scrcpy 切片录制管线、三级原地看门狗自愈器及主状态机控制器。
- **单元测试**：覆盖 19 项单元与集成测试（`tests/`），100% 通过。
- **真实环境验证**：
  - 针对用户提供的 31 个样本完成开播扫描（6 在播、25 未开播）；
  - 未开播房间（`xxuan0222`）实测准确发射 `stream_ended` 事件并以退出码 2 平稳退出；
  - 在播房间（`TuiTui.888_`）实机录制并通过 FFprobe 探针检测：H.264 60fps 视频与 AAC 48kHz 音频双流完整，音画时间戳对齐差 113ms（切片1）与 46ms（切片2），彻底消除累积漂移；
  - 详细数据与证据参见 [docs/证据/验证/20261031-录播Worker技术验证.md](../../../docs/证据/验证/20261031-录播Worker技术验证.md)。
