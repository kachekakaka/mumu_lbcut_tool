## 问题陈述 (Problem Statement)

在实际长达 10.5 小时的录播 Worker 实机连续挂机测试中，暴露了一项导致大量无效视频生成的严重缺陷：
1. **未登录账号被全屏阻断**：当模拟器未登录抖音账号时，外部 Intent 唤起直播间会被抖音客户端拦截并强推“登录后体验完整功能”（带跳过）全屏页或“优化直播推荐体验”（带关闭）半屏遮罩；
2. **盲目录制导致大白底垃圾切片**：录制管线（scrcpy）直接从 Android 屏幕合成器采集画面并硬件编码，即使前台被静态白色登录页完全挡死，视频流依然以 60fps 稳定生成 MP4，造成了系统连续生成 21 个切片（1.6GB）全部为静态登录页的严重事故；
3. **传统看门狗存在监控盲区**：原有的 Stall Watchdog 仅依赖“MP4 文件体积是否在增长”，由于视频编码器每秒持续写入 I/P 帧，看门狗被蒙蔽误判为录制健康，无法感知画面已经丧失业务有效性。

---

## 解决方案 (Solution)

构建覆盖**开录前准入校验**、**运行时低频视觉探针**与**标准阻断退场契约**的四重防御体系：
1. **物理环境基线明确化**：确立“模拟器预先登录账号”的标准部署规范，从根源消除绝大多数未登录全屏弹窗；同时保留“自动点击跳过/关闭”的双重自动化穿透；
2. **开录前置内容双重门禁 (Pre-flight Content Gate)**：Worker 在正式落盘录制前，强制等待推流就绪，并执行“UI 状态放行 + 帧差分动态推流校验”。未通过门禁（如仍处于白底登录页）坚决不开录，绝不落盘任何无效切片；
3. **运行时视觉动态看门狗 (Visual Stall Watchdog)**：看门狗每 30 秒执行一次轻量色彩矩阵抽样，若连续两次抽样命中大白底登录特征或完全静态死屏，立即触发自愈；自愈无效则立即封口当前切片并终止；
4. **登录阻断标准通报契约 (Escalation Contract)**：遇不可逆阻断时，抛出 `login_blocked` 标准事件，并以特定退出码 **`15 (EXIT_LOGIN_BLOCKED)`** 优雅退出，通知外部调度器（Orchestrator）下线该实例并调度人工介入。

## 用户故事 (User Stories)

1. 作为外部调度系统（Orchestrator），我希望 Worker 在启动录制前必须经过严格的前置内容门禁核验，以便于避免因直播间未成功渲染或被登录弹窗阻断而盲目录制数小时无效切片。
2. 作为系统运维人员，我希望能够根据部署指南为每个模拟器实例预先登录一个抖音小号，以便于彻底消灭抖音免登录全屏引导拦截的物理根源。
3. 作为外部监控程序，我希望当 Worker 遭遇无法自动绕过的登录风控（如必须短信或滑块验证）时，能够接收到 `login_blocked` 事件和退出码 15，以便于我将任务重新调度至其他健康实例并向管理员报警。
4. 作为录像质检与回放人员，我希望即使中途突发直播流卡死或弹窗遮挡，看门狗也能在 1 分钟内通过视觉抽样察觉并触发自愈或止损，以便于保障每个 MP4 切片内容的纯净度。
5. 作为录播 Worker 进程，我希望在检测到不可恢复的登录阻断退出时，依然能对当前正在写入的 MP4 完成尾部索引封口，以便于确保已录制的历史切片 100% 完好可播。

## 实现决策 (Implementation Decisions)

### 1. 模块职责变更与新增接口

#### (1) `src/worker/navigator.py`（导航与门禁验证器）
- 升级 `dismiss_login_prompt()`：
  - 覆盖全屏登录页左上角“跳过”坐标 `(84, 138)`；
  - 覆盖半屏浮层遮罩右上角“关闭”坐标 `(996, 692)`；
  - 兜底发送 Android 返回键（`keyevent 4`）。
- 新增 `verify_preflight_content_gate(timeout_sec: float = 8.0) -> bool`：
  - 连续采样两帧（间隔 1 秒）：
    - 检查当前前台聚焦组件是否为 `LivePlayActivity`；
    - 计算首帧白底占比（必须 `< 50%`）与色彩方差（必须 `> 35`）；
    - 计算两帧之间的绝对像素差异（差分面积 `> 1%`，证明直播流实际在动态渲染）；
  - 满足上述条件返回 `True`，超时未通过返回 `False`。

#### (2) `src/worker/watchdog.py`（升级为视觉动态看门狗）
- 看门狗主循环在原有的“文件体积增长检测”基础上，增加 **30 秒视觉抽样探针**：
  - 每 30 秒通过 ADB 获取一帧轻量图像矩阵；
  - 判定是否具备“高白底（白区 > 70%）且包含粉红按钮（像素 > 10,000）”的登录页特征；
  - 连续 2 次命中登录特征，立即调用 `on_stall_action("login_detected", 30)` 触发一级自愈（原地 Intent 重唤起并点击跳过）；
  - 若自愈后下一个 30 秒周期仍为登录特征，调用 `on_fatal_stall()` 触发致命阻断退场。

#### (3) `src/worker/events.py`（事件流扩展）
- 新增事件定义：
  ```python
  @dataclass
  class LoginBlockedEvent(WorkerEvent):
      event: str = "login_blocked"
      reason: str = "auth_required"
      vmindex: int = 0
  ```

#### (4) `src/worker/controller.py`（生命周期与退出码集成）
- 定义新退出码：
  ```python
  EXIT_LOGIN_BLOCKED = 15  # 遭遇抖音强登录阻断，无法进入直播间
  ```
- 在 `WorkerController.run()` 中：
  - 在 `nav.launch_room()` 成功后、调用 `self._pipeline.start_segment(1)` 之前，插入门禁核验：
    ```python
    gate_ok = nav.verify_preflight_content_gate(timeout_sec=8.0)
    if not gate_ok:
        logger.error("未通过开录前置门禁：直播间未成功渲染或被登录页死锁阻断！")
        self.emitter.emit(LoginBlockedEvent(reason="preflight_gate_failed", vmindex=self.config.vmindex))
        return EXIT_LOGIN_BLOCKED
    ```
  - 当看门狗因视觉异常上报 `_fatal_error` 且原因为登录阻断时，返回 `EXIT_LOGIN_BLOCKED`。

## 测试决策 (Testing Decisions)

### 1. 核心测试 Seam
- **高层唯一测试 Seam**：`WorkerController`（黑盒外部行为断言）。
- 绝不测试内部私有方法，仅通过控制 Mock 输入（模拟前台 UI、模拟抓取到的帧画面数据），断言 Worker 的 stdout 事件输出序列、退出码及是否启动了 scrcpy。

### 2. 覆盖的测试场景
1. **登录页阻断坚决不开录测试**：
   - Mock 前台返回高白底登录帧；
   - 断言：Worker **绝不调用** `pipeline.start_segment()`（零切片生成）；
   - 断言：stdout 抛出 `login_blocked` 事件；
   - 断言：进程退出码严格为 `15`。
2. **正常直播间顺畅通关门禁测试**：
   - Mock 前台返回动态、非纯白的真实直播帧；
   - 断言：门禁顺利放行，Worker 正常进入切片录制，产生 `segment_started`。
3. **运行时突发登录弹窗自愈与止损测试**：
   - 在录制过程中注入连续高白底抽样；
   - 断言：看门狗触发一级自愈（调用 `launch_room` 原地重唤起与点击跳过）；
   - 自愈失败时断言切片平稳封口并退出。

## 范围外说明 (Out of Scope)

1. **自动识别滑块验证码或短信验证码**：系统定位为无人值守录播执行器，不包含反爬验证码打码破解逻辑；遭遇强风控时直接以退出码 15 报告给调度器；
2. **账号自动化注册与批量养号**：账号由运维人员在初始化 MuMu 实例时手动登录配置，Worker 不负责账号注册。

## 补充说明 (Further Notes)

- 本方案全面兼容既有 ADR 0001 ~ ADR 0006 架构，且与上层 Orchestrator 的解耦接口（NDJSON stdout + 进程退出码）天然吻合；
- 前置门禁耗时控制在 2~3 秒内，不影响录制的实时性与端到端延迟。

## 实施与验证总结

- **核心代码变更**：
  - `src/worker/events.py`：实现 `LoginBlockedEvent` 事件契约；
  - `src/worker/navigator.py`：实现全屏/半屏登录遮罩自动穿透与 `verify_preflight_content_gate` 门禁；
  - `src/worker/watchdog.py`：升级 `StallWatchdog` 支持 30 秒视觉色彩与特征抽样探针；
  - `src/worker/controller.py`：开录前插入前置双重门禁校验，未通过则坚决拒绝启动 scrcpy，支持 `EXIT_LOGIN_BLOCKED = 15`。
- **自动化测试**：23 项单元与集成测试 100% 绿灯通过（涵盖事件序列、门禁拦截与视觉看门狗）。
- **实机闭环验证**：
  - 在播房间（`48859132415`）实机核验通过（白底率 0.6%、动态差分 94.5%）；
  - 录制切片通过 FFmpeg 与 OpenCV 视觉抽样检测，白底率降至 < 2%，彻底消除了全屏登录页盲目录制隐患；
  - 详细数据见 [docs/证据/验证/20261101-开录前置门禁与视觉看门狗技术验证.md](../../../docs/证据/验证/20261101-开录前置门禁与视觉看门狗技术验证.md)。
