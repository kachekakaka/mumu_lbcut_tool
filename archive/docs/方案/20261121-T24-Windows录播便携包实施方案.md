# T24 Windows x64 录播便携包实施方案

创建、最后更新和归档日期均为 2026-11-21。归档类型为 **完成**。经用户授权，录播内部候选 `portable-test.2` 与独立上传包 `portable.3` 已在台式机按 1080P 完成验收，覆盖离线开录、切片封口、双包交单和重开查回原单。按用户决定，原来占用默认端口的两项日常服务已关闭。本次内部候选验收已结束。720P 单实例跟踪和对外分发许可复核分别保留在 T25、K7。[台式机成品验收记录](../../../docs/证据/验证/20261121-T24-Windows便携包台式机验收.md)

## 拿到包后怎样用

目标是在已安装 MuMu、实例中已有抖音的 Windows x64 录制机上，以普通用户解压 ZIP 并双击 `启动录播控制台.cmd`。首次选择录像文件夹，以后双击沿用。网页打开后，从「实例」启用一台模拟器，从「主播」添加录制目标。关闭网页后录制继续，在启动终端按 Ctrl+C 平滑停机，等尾片封口再换包。

只录制时可单独运行录播包。需要投稿时，在同一台电脑上另行解压 **`fileUploadPlatform-0.2.0-windows-x64-mumu-portable.3.zip`**，双击其中的 `启动上传平台.cmd`，首次选择与录播包相同的录像文件夹。已有部署沿用原数据与账号。上传平台显示「MuMu 可以连接」后，从录播控制台进入账号和任务页。两包独立启动、升级和退出。单实例 720P 试验由 T25 跟踪，结果独立于本包验收。[待办](../../../docs/待办.md#待做) · [上传平台便携版使用说明](../../../../fileUploadPlatform/docs/operations/dashboard.md#mumu-便携版候选)

## 实施顺序

### 1. 固定输入并生成候选 ZIP

在 `scripts/` 增加可重复执行的 Windows 构建入口及随包启动文件。构建机通过 PATH 调用 PowerShell 7，从脚本位置定位仓库，允许显式指定嵌入式 Python、依赖包和工具来源。使用 Python 3.11 x64 与对应架构的 Windows wheels，根据当前运行清单锁定本次构建的直接和间接依赖版本，包含 httpx、PyYAML 及带原生扩展的依赖。在独立构建目录按 `web/package-lock.json` 安装依赖并生成生产网页。用户电脑只需安装 MuMu。[前端构建](../../../docs/最小调度运行说明.md#控制台网页)

| 包内位置 | 收集内容与检查 |
| --- | --- |
| `python/` | 嵌入式运行时、标准库和锁定依赖。显式配置嵌入式 Python 的模块搜索路径，验证从任意工作目录均能导入应用，并能启动真正的 Worker 和查询子进程。 |
| `app/` | 当前调度器、Worker、必需的 MVP 模块及第三方声明，网页放在 `app/web/dist/`。从明示的文件范围收集，排除已退役且引用已移除模块的 `upload_core_host.py`。 |
| `mumu_lbcut_tool_dev/tools/` | 已实测的 scrcpy 5.0.1，含 server 和配套 DLL。固定 Gyan 9.0.2 full build 的 ffmpeg、ffprobe 及配套说明。复用项目现有相对路径和版本检查，录制使用 MuMu 自带的 ADB。[工具部署](../../../docs/最小调度运行说明.md#固定媒体工具部署) |
| 根目录 | `启动录播控制台.cmd`、环境自检入口、中文使用说明、构建清单及许可证。清单记录录播源码版本和实际工作区状态、工具和依赖版本、网页构建来源及配套上传 ZIP 的完整文件名。 |

从新的暂存目录组包，检查实际 ZIP 内容，排除数据库、账号、录像、日志、示例直播名单及开发机配置。成品使用独立候选编号放入仓外打包目录。解压验包副本、构建日志和报告进入本批临时目录。保留旧包及日常前端。[项目文件存放约定](../../../README.md#项目目录与文件存放)

### 2. 接好首次选择、重复启动和停机

双击入口从自身目录调用包内 Python。首次用 Windows 原生文件夹选择框选一个包外可写的录像目录，可通过标准库 `ctypes` 调用系统接口。用户取消即可退出。建议将设置、调度数据库及事件日志放在当前用户的 `%LOCALAPPDATA%\MuMuLBCut\` 下，配置经校验后原子保存。首次使用新库。已有配置引用的录像盘离线、原库丢失或库格式不符时，停止启动并显示原路径，防止误建另一套运行数据。

启动时复用 `run --data-dir … --output-dir … --static-root … --open-browser`，固定本机入口 `127.0.0.1:8000`。先查 MuMuManager、MuMu ADB、scrcpy、媒体工具及网页资源，错误提示给出具体文件和位置。在调度服务配置与 `WorkerLaunchSpec` 中传递便携入口的本地工具选项，组装子进程命令时复用已有的 Worker 参数 `--require-local-tools`。启动终端保留现有 Ctrl+C 和 Worker 平滑封口行为。重复双击或 8000 被占用时，沿用服务的独占端口与主控锁，向本次启动报告冲突，已有录制继续运行。[调度入口](../../../src/orchestrator/cli.py) · [服务启动与停机](../../../src/orchestrator/server.py) · [Worker 启动参数](../../../src/orchestrator/models.py) · [Worker 工具检查](../../../src/worker/controller.py)

将便携实例锁放在同一 Windows 用户的固定目录，例如 `%LOCALAPPDATA%\MuMuLBCut\instance-locks\`。由启动器把锁位置传给子进程，复用现有按实例编号加的操作系统锁。两个解压副本即使选择不同录像盘，仍互斥使用同一实例。源码运行沿用现有目录约定。切换旧部署时先平滑停止旧主控并确认相关 Worker 退出，保留旧库和录像。[实例锁](../../../src/worker/naming_lock.py) · [升级与运行数据](../../../docs/最小调度运行说明.md#环境与目录)

### 3. 联通现有上传平台

沿用 MuMu 已有的本机投稿接口和网页入口。录播控制台使用 `127.0.0.1:8000`，上传平台使用 `127.0.0.1:8765`。两端选同一录像根，平台允许读取正式 MP4 和 `sessions/<作品编号>/upload.yaml`。在说明中给出「只录制」「启用投稿」「查看原任务」的操作顺序。平台离线时仍可完成本地录制。平台恢复后依据原部署号、原请求键和原任务查回。端口冲突和账号维护交给对应程序提示。[当前投稿契约](../../../docs/控制台接口契约.md#mumu-向统一平台交单) · [自动投稿操作](../../../docs/最小调度运行说明.md#在主播页启用自动投稿)

## 用最终 ZIP 验收

| 场景 | 操作及通过条件 |
| --- | --- |
| 干净环境首次启动 | 以普通用户将 ZIP 解压至带中文和空格的新目录，测试 PATH 不提供 Python、Node.js 或 pwsh。取消一次目录选择后重新双击，选包外录像目录。网页能加载、能列出本机实例。下次启动沿用选定路径。 |
| 平台离线也能录 | 在独立数据和录像目录中，让上传平台保持离线。用一个获准实例通过网页短录，跨过一次分片后平滑停止。任务终态正确，前片和唯一尾片都已封口，ffprobe 确认 H.264 和 AAC，抽查可播放、有声且画面为选定房间。 |
| 两个成品交接 | 启动指定上传 ZIP，选同一录像根。在测试部署按现行入口交单一次，从原切片或场次打开任务。核对正式素材、作品号和唯一任务号。平滑重启后仍能从原入口打开同一任务，平台台账未多出一单。需要实际投稿时使用约定的测试账号、素材和可见范围，分别记载本机交接与站内结果。 |
| 换包与并发保护 | 同一用户将相同成品解压到第二处，重开沿用原库、历史切片和录像目录。双击两次、其他服务占用 8000、两份副本争用同一测试实例时，逐项核对提示、原进程和原任务。已开始的录制能持续并正常封口。 |
| 缺件与数据异常 | 在隔离副本中分别模拟缺 MuMu/ADB、scrcpy server、网页或媒体工具，以及录像盘不可写、原库缺失或格式不符。错误能定位到缺件或原路径。旧数据完整，修正环境后可以重新启动。 |

记录实际 Windows 版本、两份 ZIP 的名称、运行目录、任务和切片结果及对应日志。网页可打开、单元测试通过、旧包跑通过均不能单独代替上述成品验收。首次用内部自用候选交付。若后续决定对外分发，先完成 K7 涉及的 F2 许可复核并备齐媒体工具和依赖的分发材料。[测试入口](../../../tests/README.md) · [第三方声明](../../../src/mvp/vendor/NOTICE.md)

实施时确定录播候选编号、可用的 Python 3.11 补丁版本与验包机空闲窗口。随包源和成品检查结果分别落入构建清单和验证记录。成品达到验收条件后，再更新运行说明、T24 状态及使用入口，并按项目流程归档方案。[文档职责与归档](../../../docs/README.md#方案归档时间与位置)
