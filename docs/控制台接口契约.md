## 1. 通用约定

### 本机 Bilibili 账号

账号页由上传平台 iframe 提供。新版 MuMu 的上传接口使用 `/api/uploads`，校验回环对端、Host `127.0.0.1:8000` 和同源请求，POST 正文使用 JSON，响应禁止缓存。扫码由上传平台直接处理。MuMu 校验子窗口、来源 `http://127.0.0.1:8765` 和消息协议 `upload-platform-embed` 的版本 1。已就绪的账号页发送 `account-updated` 后，主播设置重新读取可用账号。[内嵌页面实现](../web/src/components/UploadPanel.vue)

#### MuMu 与 Core 的扫码接口

旧桥接接口归档在 [2026-11-17 扫码实施方案](../archive/docs/方案/20261117-mumu接入Bilibili扫码登录实施方案.md)。

### 本机切片上传安排

下列路径相对 `/api/uploads/segment-uploads`。浏览器以录制任务编号及片号选择切片，服务器从台账定位录像。

| 方法与相对路径 | 输入与结果 |
| --- | --- |
| GET /context/{job_id}/{segment_index} | 返回当前部署、账号、录像、质量提示和表单预填。带 `revise=<已拒绝的安排编号>` 时使用原账号及投稿内容。 |
| POST /preview/{job_id}/{segment_index} | 正文包含 `deployment`、`account_id`、`remote_user_id`、`parameters` 和可选 `revise`。保存 YAML，返回平台预览内容、短期 `ticket` 及本机录像预览地址。 |
| POST /confirm/{ticket} | 正文包含 `quality_confirmed`。复核文件、账号和版本，记录切片归属后提交。重复确认指向原安排。 |
| GET 根路径 | 使用重复的 `keys=job_id:segment_index`，最多 200 片。返回安排号、Work ID、Task ID、整场归属、待核对原因及可执行的继续或修订操作。 |
| GET /{id} | 只读查回原安排或查询已关联的平台任务。 |
| POST /{id}/continue | 正文为 `{}`。手动单先查回，再按原请求继续。查回为空、重放明确返回 `409 preview_expired`、随后再次查回仍为空时，允许重新预览。 |

`GET /api/uploads/panel` 预检 `page=accounts|works|tasks`，可带本机关联的 `task_id`。 `GET /api/uploads/tasks/{task_id}` 由后端查询平台任务后更新可信摘要。

#### MuMu 向统一平台交单

两条入口均向 `POST /api/v1/submissions` 交单。手动单使用用户确认的 `preview_id`，自动场次提交 YAML 路径、素材根目录和冻结的配置版本。请求带上已保存的 `Idempotency-Key`，回执不明时向原部署的 `GET /api/v1/submissions/result` 带同一键查回。客户端从 `GET /api/v1/system/health` 获取持久保存的 `deployment_id`，并用 `X-Upload-Platform-Deployment` 发送预期部署。平台在受理前核对部署。提交和查回响应中的 `work_id`、`config_version`、`status=accepted` 与唯一 `task_ids` 项须能核对后才落本地关联。[改造时的恢复规则](../archive/docs/方案/20261120-mumu统一上传平台客户端改造实施方案.md#7-统一提交-api-与幂等)

#### MuMu 向 dev6 交单

仅用于核对切换前已保存的旧单。在原部署上，已有 Task ID 用 `GET /api/v1/tasks/{task_id}` 查询。旧单回包不明且有原 Work ID 时，用 `GET /api/v1/works/{work_id}/tasks` 分页查询。只有账号、上传单元、有序视频及路径唯一匹配才可关联。历史实现见[旧交付验证](证据/验证/20261120-MuMu按场次交付dev6本地验证.md)。

### 本机主播自动投稿

下列路径相对 `/api/uploads/session-uploads/{target_id}`。

| 方法与相对路径 | 输入与结果 |
| --- | --- |
| GET /settings | 返回 `enabled`、已保存的 `saved`、当前可投稿的 `deployment` 及 `accounts`。部署不可用时保留原设置，并通过 `problem` 给出原因。 |
| POST /settings | 开启需要 `enabled=true`、`deployment`、`account_id`、`remote_user_id` 和 `category_id`。保存时复核部署、账号与 MID，交单时由平台校验分区和私密能力。关闭发送 `{"enabled":false}`。 |
| GET 根路径 | 返回最近 30 场的 `items`，含 `session_key`、首片 `started_at`、可空的 `title`、`status`、`problem`、`arrangement_id`、`task_id` 和最近一次可信的 `observed` 缓存。 |

场次可能为 `recording`（录制中）、`waiting_close`（等待结束）、`checking`（核对切片）、`only_record`（只录）、`pending`（待交付）、`review`（待核对）或 `delivered`（平台已受理）。`problem` 是供本机页面展示的文字说明。

### 通用响应

- 路径统一 `/api`；请求和响应为 JSON，时间为 Unix 秒，布尔值使用 JSON 布尔，缺失值返回 `null`。不直接返回数据库原始行或内部 JSON 字符串。
- 请求字段、筛选值及范围严格校验；未知请求字段不静默忽略。错误格式为 `{"code":"稳定英文代码","message":"中文说明","details":null}`，不暴露异常堆栈。
- HTTP 400 用于无法解析的请求，422 用于字段/范围错误，404 用于对象或路由不存在，409 用于请求编号冲突或已知状态冲突，503 用于服务未就绪或关闭中；内部错误返回 500 并记录日志。
- HTTP 层能发现的错误立即返回；排队后才发现的业务变化写入命令的 `failed` 结果，由命令查询接口以 HTTP 200 返回。不能用一个 202 表示执行已成功。
- 列表返回 `{items, total, limit, offset, generated_at}`；默认 `limit=50`，范围 1～200，`offset` 为非负整数。筛选条件取交集，先筛选再计数和分页；固定排序且用唯一 ID 补齐同时间排序。
- 时间区间参数统一 `from_time`（含）与 `to_time`（不含），要求前者小于后者；客户端把所选本地时间转换为 Unix 秒再发送。
- 业务原因统一为可空对象 `{code,detail}`：`code` 是稳定英文代码，`detail` 是可空附加文本。适用于实例 `reason`、目标 `needs_fix_reason/last_failure_reason`、任务 `stop_reason/error_reason`、详情事件及切片 `reason`、告警 `reason`。后端统一解释 Worker 的“代码: 详情”，未知代码保留；无法识别为代码的文本使用 `unspecified` 并保留为 detail。修正标记的自由文本使用 `target_invalid` 加详情。前端只映射代码，不拆冒号。命令的 `error_code/message`、日志不可用的中文 `reason` 保持原契约。
- 状态值：实例 `idle/busy/booting/offline/reconcile`；任务 `pending/starting/running/stopping/needs_reconcile/finished/finished_with_warnings/failed/cancelled`；切片 `started/finished/aborted`；可信开播状态 `live/ended/unknown`。命令状态见第 7 节，前端对未知返回值保留原文。实例 `resetting` 已移除，不再返回对应总览计数，按该状态筛选返回 422。
- 调度操作提交后应查询命令结果，不能仅凭首次受理响应认定操作完成。第 8 节桌面定位为即时操作，不查询命令；页面刷新频率、连接状态和操作反馈见[控制台交互设计](设计说明.md#控制台页面与交互)。

## 2. 读取接口及筛选

| 接口 | 参数、排序或边界 | 返回内容 |
| --- | --- | --- |
| `GET /api/system` | 无分页 | `scheduler_running`、`service_state`（`running/closing/failed`）、`last_tick_at`、`server_time`、`upload_enabled=false`、`service_version`、`api_version=1`、`statistics_timezone="Asia/Shanghai"`、`frontend_available` |
| `GET /api/overview` | `limit/offset` 只分页告警 | `instance_counts`（仅统计已启用及 `reconcile` 实例）、`job_counts`（按各状态计数）、`recording_count`、`pending_count`、`today_finished_segments`、`statistics_timezone`、`generated_at`、`alerts` 列表分页对象 |
| `GET /api/instances` | `status`、`enabled`；按 `vmindex` 升序 | 第 3 节实例对象（含已启用与本机探测到的未启用实例） |
| `GET /api/targets` | `q`（昵称或原始地址子串）、`trusted_status`、`auto_record`、`has_notice`；只列启用目标，按 `created_at,id` 倒序 | 第 3 节目标对象 |
| `GET /api/jobs` | `active` 默认 true（false 为历史）；`target_id`、`status`、`from_time/to_time`；时间筛选及排序按 `created_at,id` 倒序 | 第 3 节任务对象 |
| `GET /api/jobs/{id}` | 按 ID 查询，包括历史与已移除目标的任务 | 任务对象及 `recent_events`，最多最近 50 条相关事件；切片通过 segments 的 `job_id` 分页读取 |
| `GET /api/jobs/{id}/log` | `lines` 默认 200，范围 1～2000 | 第 5 节日志对象 |
| `GET /api/segments` | `target_id`、`job_id`、`status`、`has_quality_flags`、`from_time/to_time`；按 `COALESCE(started_at,created_at),job_id,segment_index` 倒序 | 第 3 节切片对象；时间筛选同排序时刻 |
| `GET /api/commands/{id}` | ID 不存在返回 404 | 第 6 节命令对象 |

`active` 对应现有活跃状态集合（包括 `needs_reconcile`），不能仅凭 `ended_at` 是否为空判断。其他各列表同样接受通用分页参数。服务版本使用源码中的版本标识，不在每次请求时运行 Git。

`has_notice` 指本场抑制、需要修正或失败重试中任一成立；false 表示三者均不成立。总览的计数与告警同样在单个读快照内产生，避免一份响应中的数量和条目取自不同状态。

## 3. 读取对象字段

| 对象 | 字段 |
| --- | --- |
| 实例 | `vmindex,name,status,enabled,job_id,reason,updated_at,target_id,nickname` |
| 目标 | `id,raw,nickname,created_at,updated_at,trusted_status,observed_status,observed_at,confirmed_at,auto_record,room_id,anchor_uid,session_key,recording_intent,suppressed,needs_fix_reason,note,attempts,retry_at,is_retrying,last_failure_reason,active_job_id,active_job_status` |
| 任务 | `id,target_id,nickname,target_raw,vmindex,status,created_at,started_at,recording_started_at,ended_at,exit_code,stop_reason,error_reason,recovery_context,elapsed_sec,fps,room_identity_status,room_identity_checked_at,room_identity_confirmed_at,room_identity_age_sec,room_identity_stale,room_identity_reason,heartbeat_at,finished_segment_count,aborted_segment_count,reconcile_requested` |
| 切片 | `job_id,target_id,nickname,target_raw,segment_index,status,file_path,duration_sec,file_size_mb,is_final,reason,created_at,started_at,ended_at,updated_at,quality_flags` |
| 质量标记 | `flag,suspected_start_time`；每片保留全部已记录标记，未知值不丢弃 |
| 详情事件 | `event_id,event,timestamp,received_at,action,reason,phase,attempt`，缺失项为 null；范围包括导航、身份核验、卡顿发现/恢复、登录阻断、流结束和 Worker 失败/结束，不返回全量心跳 |

任务身份字段来自最近心跳，不是 HTTP 查询瞬间重新取证。`room_identity_checked_at` 为最近接受的运行期观察完成时间（包括不可用结果），`room_identity_confirmed_at` 为最近稳定匹配的保守采样时间；两者均为秒级时间戳或 null。重新定位取得的新确认可能晚于上一次运行期观察，不能要求两字段相等。`room_identity_age_sec` 是 Worker 用单调时钟计算的报告时确认年龄，无基线为 null；`room_identity_stale` 是无基线或年龄达到 30 秒，未报告时为 null。`room_identity_reason` 为当前异常原因代码字符串或 null。心跳过期／任务结束时只能展示历史报告，不能将旧 verified 当作实时保证。

切片 `identity_unconfirmed` 表示身份未确认风险，`identity_mismatch` 表示可能包含错房画面，不声称该片每一帧都已证明错误。质量标记可晚于切片或任务结束到达，处理规则见下方“质量标记与迟到事件”。`runtime_identity_probe_unavailable` 以退出码 9 进入既有 needs_fix 语义，须检查后显式 record 重试，不表示目标地址无效。

- 实例原因 `boot_interrupted` 表示后台开机被停服中断，实例暂记 `offline`，重启后重新探测；不表示开机失败或模拟器已被关闭。
- `recording_intent` 与 `suppressed` 由后端按当前场次计算；`needs_fix_reason` 去除内部 `needs_fix: ` 前缀后输出结构化原因，前端不自行解析存储状态。
- `is_retrying` 表示本场意图仍有效、已有失败尝试且尚未恢复到运行中，且没有抑制、修正或待对账阻挡；`last_failure_reason` 来自对应本场最近失败任务。
- `recovery_context` 无恢复事件时为 null，否则为 `{trigger,last_failure,outcome}`：前两项使用可空的结构化原因，`outcome` 为 `recovering/recovered/failed/cancelled`。后端从最近一次 `stall_detected` 起的持久化事件按入库顺序投影，保留其后最后一次真实恢复失败原因；导航取消不覆盖已有 `render_timeout` 等原因。该摘要独立于详情最近 50 条事件，并与任务 `stop_reason/error_reason` 一起显示，不能据后来下播把此前登录阻断抹去或把失败任务强改成功。
- 登录提示会触发优先开播状态复核，确认下播后取消当前恢复；LIVE 保持 Worker 恢复，UNKNOWN 不当下播。开始与结果事件可在任务详情追查，恢复摘要不改变原任务结果或尾片状态；查询资源、窗口和迟到结果处理见[复核设计](设计说明.md#外部状态查询与登录复核)。
- 心跳字段取最新有效心跳，没有心跳则为 null；同时提供 `heartbeat_at`，前端不得把旧值显示成刚采集的实时值，不按本地计时虚增录制时长。`started_at` 表示 Worker 拉起时间；`recording_started_at` 是该任务正式切片中最早的 `started_at`，没有切片开始事件则为 null，不能用 Worker 拉起时间补值；恢复采集不重置此时间。它是首片登记的宿主机时间，不是媒体第一帧的精确时间；启动门禁未放行的临时采集不进入切片列表。底层时序证据见[运行说明](最小调度运行说明.md#录制事件与时序)。
- 开录准备期间的 `capture_startup/rejected` 登录提示同样触发上述优先开播状态复核，但不生成运行期恢复记录或消耗 Worker 恢复预算；正式采集开始后取消该轮复核，晚到结果不得覆盖新状态。
- 录制中切片的路径可回退到 `raw_path`，完成或中止的时长/大小缺失时保持 null，不伪造 0 或扫描整个录像目录补值。
- 切片列表和状态筛选支持 `conflicted`（终态冲突），此时 `file_path` 为 null。投递的新建、修订和派发返回或记录 `segment_unfinished`，已发送的原单仍可查询。
- 已移除主播的任务、切片仍可读取，关联名称缺失时显示 `target_raw`；不因目标从监控列表隐藏而丢失历史列表项。

### 质量标记与迟到事件

`quality_flags` 每项对应一条已入账风险，允许相同名称和疑似时间重复出现；数量是标记记录条数，不是独立异常次数。同一事件重投不增加记录，不同事件即使内容相同也保留；内部去重边界见[设计说明](设计说明.md#质量事件入账与事务)。`has_quality_flags` 判断是否有风险记录，未知名称也算风险。

`suspected_start_time` 是秒级疑似开始时间，可早于当前切片，不表示确定发生时间。API 仅返回有限整数／浮点数（包含零）或 null；布尔值、字符串、容器、非有限值及缺失值投影为 null，原始证据不变。按名称分组后的最小／最大值只能解释为最早／最晚疑似开始，不能计算异常持续时长。切片 `updated_at` 取已接受切片事件的最大规范化事件时间，乱序不回退、重投不刷新；事件时间无效时在入账阶段使用接收时间，不使用疑似开始时间替代。

已登记、已开始且已终结的切片可正常追加风险，不改变媒体终态与文件信息。收集完整且退出码为零的 `finished` 任务收到新风险后变为 `finished_with_warnings`，保留原结束时间、退出码及原因；其他正常回标不改变任务状态。

已经结束的任务收到未知、未开始或未终结切片的风险时，保留占位／未完成切片和风险证据，但不伪造生命周期。原 `finished/finished_with_warnings` 任务改为 `failed`，原因类别为 `event_collection_incomplete`，详情注明切片与异常；结果码保留原非零值或使用 30，完整性标记置零。原成功任务完整性标记已经为零也按此处理。原 `failed/cancelled` 保留既有状态、退出码和错误原因，仅收紧完整性标记，附加异常可查警告日志及风险记录。占位切片的 `started` 状态表示生命周期尚未闭合，不能据此判断已结束任务仍在采集。

迟到处理不重新执行任务收尾、不改变停止意图、不占用实例或安排新重试；也不影响已复用实例的新任务。活动及待对账任务仍由原收尾／对账流程判断结果。后来补到生命周期事件不会自动把完整性失败恢复为成功。本规则不扫描修补历史数据库。

## 4. 总览与告警

今日完成数以北京时间（当前统计使用 UTC+08:00）的当日零点至次日零点为界，统计 `status=finished` 且 `ended_at` 在范围内的切片；中止切片不计入完成数。

告警项含 `type,object_type,target_id,nickname,target_raw,job_id,segment_index,reason,attempts,retry_at,timestamp`，按时间倒序分页。`reason` 使用结构化原因对象，不混入中文默认消息；重试告警直接提供 `attempts/retry_at`，其他类型这两项为 null。对象名称来自当前快照中的关联记录，前端不再额外查询主播列表补齐。类型覆盖 `retrying`、`needs_fix`、`needs_reconcile`，以及最近 24 小时内新出现的 `segment_quality`、`segment_aborted`；同一切片可分别有质量与中止告警。前端通过对象 ID 跳转，不接收任意跳转 URL。

当前状态告警使用最近对应失败/对账事件的时间，缺失时回退到对象记录时间；质量与中止告警使用对应事件时间。不能每次查询都把告警时间改成当前时间，也不能只截取一个列表却声称返回全部告警。

质量告警每个切片最多一条，时间取其风险记录中最新的规范化事件时间；没有风险不生成质量告警。24 小时窗口包含下界，有效零值不当作缺失；窗口外旧风险不因重投或较新的非风险事件再次变新。记录缺失有效事件时间时查询兜底到切片 `updated_at`，此类记录无法提供同等历史时间精度；不修复旧库已回退的更新时间或异常未来时间。

公共接口的 `upload_enabled` 为 false。切片页的手动安排和状态由[本机切片上传安排](#本机切片上传安排)提供。公共总览及切片列表不返回上传详情、筛选和告警。

## 5. 日志读取

返回 `{job_id,available,text,returned_lines,truncated,reason}`。任务存在但尚未启动或日志不存在时返回 200、`available=false` 和明确原因；任务不存在为 404，实际读取失败则返回对应错误，不伪装为空日志。

只允许读取当前数据目录 `events/<job_id>.log`，先核对任务并校验解析后的路径仍在该目录内；不接受请求传入任意路径。采用文件尾部有界读取，最多 1 MiB；行数或字节上限截断时 `truncated=true`。允许末行仍在追加，对不完整编码使用替换字符显示，既不改日志也不把一条未写完的行当成后端失败。

## 6. 控制与结果

| 接口 | 请求体 | 命令成功结果的关键内容 |
| --- | --- | --- |
| `POST /api/targets` | `{targets:[地址...],manual_only:false,allow_unconfirmed_identity:false}`；1～100 条，每条至多 2048 字符 | `items:[{input,target_id,outcome,message,code}]`；`outcome` 为 `created/existing/restored/error` |
| `DELETE /api/targets/{id}` | 无 | `target_id,changed,affected_job_ids`；表示停用与停止意图生效，录像保留 |
| `PATCH /api/targets/{id}` | `{auto_record:bool}`，指定目标值而非盲目 toggle | `target_id,auto_record` |
| `PATCH /api/instances/{vmindex}` | `{enabled:bool}`，指定实例是否参与录播 | `vmindex,enabled,cleaned`（占用、开机中或待对账时拒绝停用；停用 `not_discovered` 旧记录时立即清理；启用时清零开机冷却） |
| `POST /api/targets/{id}/record` | 无或 `{}` | `target_id,job_id,outcome`，`outcome=queued/existing` |
| `POST /api/targets/{id}/stop` | `{session_key:"页面当前场次"}`，必填非空 | `target_id,session_key,outcome,affected_job_ids,reconcile_job_ids`；`outcome=intent_cancelled/stop_requested/already_stopped`；无活跃任务时也可取消本场重试 |
| `POST /api/jobs/{id}/stop` | 无或 `{}` | `job_id,outcome`，`outcome=cancelled/stop_requested/already_stopping/already_terminal` |
| `POST /api/reconcile` | `{job_id:null}` 为全部待对账对象，或指定任务 ID | `job_ids,outcome`，`outcome=reconcile_requested/not_required`；CLI 使用，前端首版不提供按钮 |

`allow_unconfirmed_identity` 保留 CLI 现有显式选择；网页首版不提供该开关，创建时使用 false。重复或恢复已有目标不得借默认值或重复提交悄悄改变其身份策略。

LIVE 查询缺身份字段仍报告在播，`room_id`／`anchor_uid` 的缺项为空；保留的 `session_key` 仅用于最近已知场次关联，不保证最新身份齐全。`target_identity_incomplete`／`target_identity_stale` 分别表示缺项／过期，阻止新任务准入。未启动任务因此等待时，新的立即开录请求会重新查询；同场刷新复用原任务，换场结束旧任务并返回 `live_session_changed`。已运行任务保留普通幂等行为。Worker 的 `identity_unstable`／`identity_conflict_unresolved` 为身份失败原因（退出码 18）；进入重定位时心跳身份先变为 unconfirmed，旧证据来源和时间失效。

目标级停止与任务级停止共用场次抑制和封口处理逻辑，目标级停止不要求存在活跃任务，不移除监控，也不改变长期自动录制开关。目标级命令处理时若本场已被抑制且无新增作用，返回 `already_stopped`；有待对账任务时通过 `reconcile_job_ids` 告知“后续重试已取消，遗留进程仍需对账”。同一请求编号重试仍优先返回原命令结果，新请求编号必须重新校验场次。

首次受理返回 HTTP 202：

```json
{"command_id":"命令ID","status":"pending"}
```

相同请求编号再次提交时，返回同一个 `command_id` 和当前 `status`；非终态返回 202，终态返回 200。查命令返回：

```json
{
  "id":"命令ID",
  "request_id":"客户端UUID",
  "kind":"record",
  "subject":"目标ID",
  "status":"succeeded",
  "result":{"target_id":"目标ID","job_id":"任务ID","outcome":"queued"},
  "error_code":null,
  "message":"已安排录制，实际状态请查看任务",
  "created_at":0.0,
  "started_at":0.0,
  "finished_at":0.0
}
```

示例时间仅说明类型，不是实际运行记录。失败/中断通过 `error_code,message` 解释；错误码包括 `target_not_live`、`live_status_unknown`、`live_query_timeout`、`query_busy`、`target_changed`、`session_changed`、`job_stopping`、`reconcile_required`、`instance_not_found`、`instance_busy`、`service_interrupted` 等，不能靠前端解析中文判断状态。批量部分失败通过逐项结果表示，不把整个批次显示成“全部新增成功”。

## 7. 命令状态与请求去重

- 第 6 节调度变更请求必须携带 `Idempotency-Key`，值为客户端为本次操作生成的 UUID。同编号、同操作对象和同一规范化参数返回原命令；同编号异参数返回 409。去重先于可变业务状态检查，不能因连接超时自行换编号重做。第 8 节桌面定位不进入命令队列，不使用此去重机制。
- `pending` 表示已持久受理；`running` 表示处理中或等待查询，均不表示媒体动作已经完成。
- `succeeded` 表示业务状态和结果已原子提交；开录仅为已安排任务，停止仅为停止意图生效。媒体结果仍查看任务和切片。
- `failed` 表示校验、业务条件或查询失败；失败原因由命令结果提供。
- `interrupted` 表示关停或重启时尚未应用的命令已作废，不自动补执行；需要重新操作时使用新请求编号。

## 8. 切片桌面定位（Desktop Reveal）

- 接口：`POST /api/segments/{job_id}/{segment_index}/open-folder`，无请求体或空对象，无查询参数，`segment_index` 为非负整数。即时返回，不要求 `Idempotency-Key`，不创建调度命令，不自动重试。
- 适用场景：在宿主机 Windows 资源管理器中弹出并高亮选中切片文件；文件丢失时降级打开所在目录。
- 访问与安全边界：
  - 遵循 [ADR 0021](adr/0021-console-desktop-reveal-for-segments.md)，内网/局域网可信客户端均可触发；请求交给录制机文件管理器，客户端不下载文件。可见窗口需录制机有可用的交互桌面会话；SSH/服务启动环境的实际可见性需实机验收。
  - 接口不接受前端自定义文件路径，仅通过 `(job_id, segment_index)` 查询已持久化切片；
  - 严格校验切片绝对路径必须位于当前配置的 `output_dir` 录像根目录之内，越界返回 403 `path_forbidden`；
  - 切片未落盘返回 404 `segment_file_not_ready`；切片不存在返回 404 `segment_not_found`；目录亦不存在返回 404 `folder_not_found`。
  - 文件管理器启动失败返回 HTTP 500 `desktop_open_failed`，服务日志保留完整异常，响应不暴露异常详情，不返回成功或高亮标记。此前的查询与路径校验仍返回各自错误，不统一改写为启动失败；异常捕获实现见[设计说明](设计说明.md#桌面定位的异常边界)。
- 成功响应（HTTP 200）：
  `{"status":"succeeded","file_path":"绝对路径","folder_path":"所在目录绝对路径","revealed":true/false}`
  `status=succeeded` 仅表示已发出文件管理器启动请求；`revealed=true` 表示请求使用文件定位模式，`false` 表示使用父目录打开模式。这些字段不是桌面实际打开或选中的回执。
- 客户端应将成功表达为请求已发出，并提示到对应桌面确认；连接状态、按钮禁用与冷却规则见[控制台交互设计](设计说明.md#控制台页面与交互)。
