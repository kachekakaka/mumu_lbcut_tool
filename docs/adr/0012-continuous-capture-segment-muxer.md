# 0012 持续采集与独立分段封装

## Status
accepted（实现完成，验证边界见证据；不代表全场景实播验收）

## Context
重启 scrcpy 切片会改变采集生命周期，引入重连空档；双管线会增加设备并发编码负担。离线 stream-copy 已证明可保留编码包，本轮进一步验证了实时传输和真实 MuMu 分装。

## Decision
Windows 下每个采集会话运行一个 scrcpy 和一个 ffmpeg。scrcpy 向独占命名管道写 MKV；有界字节桥传入 ffmpeg stdin，使用 stream copy 在关键帧处分装多个 MP4。过程不修改 scrcpy 源码、不重新编码、不插帧、不产生无限增长的中间总录像。

计划分片由封装器执行，不重启采集。故障恢复另建捕获代际和唯一目录，序号继续递增。只有 muxer 完整 CSV 行确认文件关闭，才进行双轨/容器校验与无覆盖归档。最后一片由采集 EOF、封装退出和校验共同决定；异常结果如实报告，不把文件存在等同完成。

旧 restart/双管线为显式诊断路径，不是当前默认。停止后重新定位仍会有恢复空档；持续分装不修复渲染或采集阶段已经漏掉的帧，也不直接保证音画同步。

## Consequences
新增 ffmpeg 运行依赖及 Windows 命名管道组件；内存有界，校验队列有界。强杀/断电可能损坏未封口 MP4，已关闭文件独立保存。分段长度取决于关键帧，不承诺任意秒数精确切割。改动与测量见 [验证记录](../证据/验证/20261106-持续采集与遮挡恢复验证.md)，使用方式见 [运行说明](../最小调度运行说明.md)。
