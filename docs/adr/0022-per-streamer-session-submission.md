# 0022 MuMu 按直播场次向上传平台交付任务

2026-11-20 已确认设计并实现 MuMu 侧流程。实机投稿余项由[待办 T16](../待办.md#t16-投稿实测)跟踪。

主播自然下播或主动停录后，MuMu 等本场录制正常收尾、正式切片封口可读。本场各段均符合交付条件时，MuMu 按实际录制顺序列出文件路径，附上该主播保存的投稿账号、分区和本场投稿资料，向上传平台提交一份任务。本轮在任务里指定「仅自己可见」。多个切片列在同一份清单中，清单顺序就是一份稿件的分 P 顺序。[原交付约定](0010-orchestrator-architecture-and-delivery-contract.md)

上传平台受理任务后，MuMu 把平台任务编号关联到本场，交付完成。只登记了作品时仍待提交。关闭主播的自动投稿后，录制继续，本场尚未提交的安排停止交付。若提交请求已经发出但回执丢失，MuMu 按原安排查找平台任务，避免重复交单。

上传平台负责读取文件、上传视频、按任务参数向 B 站提交稿件、处理投稿重试并回传结果。MuMu 可凭原任务编号展示平台返回的进度和 BV 号。整场单片自动投稿及原稿的私密范围已确认，B 站回放音画待验。[台式机整场实测](../证据/验证/20261120-MuMu整场自动投稿真实使用测试记录.md#2026-11-21-归档复核)

现有 MuMu 手动入口一次安排一个切片。台式机验收按一场一片设计，多 P 的实际投稿和播放顺序需单独验证。[切片页手动安排](../最小调度运行说明.md#在切片页手动安排上传) · [台式机验收归档方案](../../archive/docs/方案/20261120-台式机单路录制至B站自动私密投稿实机验收方案.md)
