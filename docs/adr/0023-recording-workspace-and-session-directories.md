# 0023 MuMu 统一选择工作目录，按直播场次保存录像

2026-11-24 已确认设计。[归档方案与验收标准](../../archive/docs/方案/20261124-录播工作目录与场次录像存放方案.md) · [实测记录](../证据/验证/20261124-录播工作目录与场次录像验收.md)

MuMu 首次启动时让用户选一次工作目录，默认使用整合包同级的 `mumu_lbcut_tool_dev`，用总启动器旁的 `workspace.json` 记住选择。录播和上传各自管理运行数据，MuMu 启动上传平台时传入它的数据子目录。录像默认放在工作目录的 `recordings` 下，也可单独指定录像盘。这样程序换包和录像换盘都能与两边的数据库分开处理。

主播第一次录制时按昵称分配固定目录名。两位主播都叫「小林」时，分别使用 `小林` 和 `小林-2`。主播改昵称后，控制台显示最新昵称，以后的录像仍归入原目录，方便与历史录像一起查找。

主播一天可能开播多次，一场也可能经历多次录制尝试。正式录像一场一个目录，把开录日期和时间放在同一级，切片用短序号命名。程序在数据库和投稿清单里保存所需的编号。B 站多 P 投稿沿用平台按文件名生成的默认分 P 标题，例如 `001.mp4` 对应 `001`。整场稿件沿用[现行标题规则](../最小调度运行说明.md#在主播页启用自动投稿)。

场次目录采用本场首片实际开录的北京时间。跨午夜或同场断线续录时沿用原目录，已经分配的片号保留。第 003 片即使只录了几分钟，正常封口并通过检查就保存为 `003.mp4`。中断且有原文件时，原样保留在同一场次目录，命名为 `003-中断.mp4`，恢复后的新片从 `004.mp4` 继续。这既保留断线前可能还能播放的画面，也让中断位置可见。

整场投稿的 `upload.yaml` 与本场 MP4 放在一起。手动安排单片时，清单放在场内的 `投稿` 子目录，引用原视频。中断原片保留中断状态，启用整场自动投稿时沿用现有的待核对规则。同一切片投给多个账号的清单结构留待上传平台另议。[整场交付与查回规则](0022-per-streamer-session-submission.md)
