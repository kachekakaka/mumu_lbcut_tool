# 0018 实例改为启动后在控制台界面按需启用，并清理无效旧记录

## Status
accepted（2026-11-12 已实施，已同步[控制台接口契约](../控制台接口契约.md)与[最小调度运行说明](../最小调度运行说明.md)；本次审查修正见[验证记录](../证据/验证/20261112-实例控制与按需开机审查修正验证.md)）

## Context
调度器原要求在启动命令通过 `--instances` 必填显式指定允许使用的 MuMu 实例编号，且控制台实例页只允许查看、不可操作；同时，当复用同一 `--data-dir` 并缩减 `--instances` 重启时，旧库 `instances` 表仍保留历史实例行与旧状态，导致界面列表与总览统计出现与实际可派发范围不一致的幽灵残留（待办 `K14`）。

## Decision
1. 取消启动参数 `--instances` 的强制必填限制；调度器启动后通过 `MuMuManager` 发现全部本机实例。新数据库首次启动未预设时，探测到的实例默认全部处于「未启用」状态，由用户在控制台「实例」界面选择启用或停用并持久化保存。
2. 控制台「实例」界面展示全部本机探测到的实例并支持切换启用状态；「总览」统计已启用及待对账实例，调度只派发给已启用实例。成功扫描后，未发现且无活跃或待对账任务占用的历史旧行，未启用时自动清理；仍启用则保留为 `offline / not_discovered`，停用后清理。查询失败保持原记录。
3. 当实例有任务占用、正在开机或待对账时，拒绝直接停用。原 `resetting` 已由 [ADR 0020](0020-worker-cleanup-force-stop-douyin.md) 移除，应用清理由 Worker 在释放实例锁前执行。

## Considered Options
- **新环境首次启动默认全部启用**：容易在刚启动或接入按需开机后误占用本机其他用途的 MuMu 实例。
- **未启用或已删除历史行也计入总览实例统计**：会误报实际可用录制容量并保留无效旧状态。
- **允许忙时直接停用（引入排空中间态或强停当前录制）**：增加状态模型复杂度或容易误触打断正在进行的直播录制。

## Consequences
- 全新数据目录首次启动服务后，须在控制台「实例」界面至少启用一个实例才会被派发录制任务；`InstancesView` 不再是只查看页面，需配合 `Idempotency-Key` 变更接口。
- 后续实施按需自动开机（待办 `T8`）时，只允许自动启动「已启用」的实例，不启动「未启用」实例。
