# 0016 控制台采用独立前端工程，构建后由调度服务同端口托管；远程访问走组网，不做验证

## Status
accepted（2026-11-11 讨论确定；修订 [ADR 0010](0010-orchestrator-architecture-and-delivery-contract.md) 第 1 条中的前端形态）

## Context
ADR 0010 设想由 FastAPI 内嵌一个不需要构建的单页控制台，以避免 Node.js 运维负担。控制台需要实例、主播、任务、切片四类面板以及总览、表格筛选和定时刷新，并且以后要从录制机以外的设备访问。后端方案将由另一个 agent 根据前端方案单独编写和实现。

## Decision
控制台前端作为独立工程，使用 Vue 3、Vite 和 TypeScript 编写，构建成静态文件，由调度服务在 API 的同一端口托管。Node.js 只在开发和构建时需要，运行时不需要。前后端只通过前端方案中列出的接口需求协作，前端一律用相对路径请求接口。远程访问通过 Tailscale、ZeroTier 等组网工具或远程桌面进入录制机所在网络，不直接向公网开放端口，因此控制台不做登录验证。

## Considered Options
- 不需要构建的单页：完全不需要 Node.js，但界面变复杂后代码难以维护。
- 前端单独部署、跨域访问后端：只有在一个界面里汇总多台录制机时才需要，目前不需要。
- 桌面程序：远程查看不方便。
- 直接开放公网端口：没有验证时，任何拿到地址的人都能停止录制或删除主播。

## Consequences
- 开发机需要安装 Node.js；部署或打包时须包含构建好的静态文件。
- 如果以后改为直接开放公网，必须先补充访问验证。
