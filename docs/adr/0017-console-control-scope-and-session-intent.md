# 0017 控制台首版聚焦录制控制，保留本场录制意图与目标历史

## Status

accepted（2026-11-11 后端方案讨论 Q1～Q14 确认，随后按定向 review 修订；同日另获明确代码实施授权，后端已实施，验证与余项见[后端方案](../方案/20261111-调度控制台后端接口实施方案.md)）

## Context

[前端方案](../方案/20261111-调度控制台前端方案.md)需要五个页面的查询、控制操作、日志和静态托管，允许上传未启用时隐藏相关界面。当前代码已有 CLI 与 SQLite 调度闭环，但没有 HTTP 服务或自动录制开关命令；当前调度条件直接检查长期自动录制开关，不能完整表达关闭开关后仍保障本场的意图；重新添加已移除的目标只返回旧 ID，并不恢复监控。

## Decision

1. 本轮后端只完成控制台所需接口、运行日志读取与前端静态文件托管，声明 `upload_enabled=false`。上传交付另做专项，既有上传方向不因此取消。
2. 关闭自动录制开关后，已排队或正在录制的本场继续，失败仍自动重试；该开关只阻止后续场次自动开录。结束本场可按主播和指定场次取消意图，即使退避期间没有活跃任务也可操作；有可控任务时同时平滑停止，场次已变则拒绝误停新场。任务页保留按任务停止。领域边界见 [本场录制意图](../../CONTEXT.md#language)，其余终止条件继续遵循 [ADR 0015](0015-auto-retry-while-live-without-manual-unblock.md)。
3. 再次添加已移除且匹配到的目标时恢复原记录，沿用目标 ID 和历史任务、切片关联，自动录制设置采用本次添加的选择。移除目标不删除历史录像。
4. 本轮只提供统一启动：调度器、API 与静态网页服务一起启动，正常关闭时平滑停止录制并退出整个服务；不另设只读网页启动模式。服务关闭后不能通过网页提交命令，不保留“主控已关闭但网页仍可排队”的交互承诺。
5. 页面采用每 2 秒查询当前页面数据的方式，操作后立即刷新；隐藏标签页可降低频率，返回前台立即刷新。5 秒显示时效从后端取得新状态起算，以页面正常连接且接口及时响应为验收前提；不将既有开下播扫描周期改成 2 秒或 5 秒。
6. 手动“立即开录”先查询最新开播状态：确认在播才建立本场录制意图，无空闲实例时照常排队；明确下播或暂时无法确认时给出原因，不留下预约下一场的请求。自动录制仍负责持续等候未来开播。
7. 开启自动录制时，当前已确认在播的场次按正常规则排队；若本场已被人工停止抑制，则仍需显式“立即开录”才能恢复。开关不会解除本场抑制。
8. 添加已处于监控中的目标时只返回“已存在”，不覆盖自动录制设置，不解除本场抑制或修正标记；与第 3 条的恢复已移除目标相区分。
9. 任务处于停止中时，“立即开录”返回“正在停止，请结束后重试”，不撤销封口，也不保存延迟重开请求；已有排队、启动中或录制中任务时返回已有任务，不重复创建；待对账任务须先对账。
10. 接口版调整数据库结构并使用独立的新数据目录，监控主播重新添加；旧数据库、日志和录像原样保留，不迁移、不覆盖。新控制台只显示新库记录，不提供旧历史库查询或兼容层。
11. 调度平台 CLI 的控制与查询改为调用 HTTP 接口，与网页使用相同校验和结果；必须先启动服务，不再离线写数据库或排队命令。`run` 仍是本机服务启动入口；Worker CLI 不在这一调整范围内，仍由调度器作为本机子进程启动。
12. 服务意外退出后，尚未应用到调度状态的命令在重启时标记为已中断，不补执行，使用者可重新提交；已经应用的操作与本场录制意图保留。状态变更与命令执行结果须原子保存，避免操作已生效却被报告为中断。
13. 总览的“今日切片数”按北京时间统计当日完成封口的切片，中止切片单独计入告警；不同设备采用同一统计口径。记录明细时间仍按前端方案用浏览器本地时区显示。
14. 周期扫描、手动查询和启动复核共用按目标递增的观测序号，由调度线程逐目标检查并应用结果；不能使用整批扫描完成时间覆盖较新场次。控制版本和场次检查共同防止迟到结果恢复已取消的意图。
15. 阻塞外网解析在数量受限、可终止的只读辅助进程中执行，复用现有解析器及正常进程中的游客会话；总截止与资源回收由主控执行器保障。辅助进程不参与调度、持久化或录制，Windows 退出归属与录制 Worker 分开管理。容量、期限和验收细则统一见后端方案。

## Considered Options

- 同时实现上传：还需确定接收服务、路径共享、投递重试和结果回报，扩大本轮接口层范围。
- 关闭自动录制即停止本场或禁止失败恢复：行为直接，但混淆长期偏好与本场停止操作，削弱已确认的在播持续恢复要求。
- 重新添加时建立新目标：可分开两段监控历史，但同一主播的任务和切片会被拆到不同记录，增加查看成本。
- 单独提供只读网页模式或用长连接推送页面变化：增加运行模式或断线补齐机制，当前控制台范围内选择统一启动和定时查询。
- 手动开录请求一直保留到未来开播：会把“立即开录”变成预约，产生跨场次延迟执行的意外行为。
- 批量重复添加时覆盖设置、停止过程中记住重开请求：减少单独操作次数，但增加隐含状态变更；首版采用明确分开的操作。
- 让新控制台同时展示旧库历史：增加旧格式读取与兼容范围，不符合本项目当前不做兼容或迁移的约定，本轮不纳入。
- CLI 继续直接访问数据库：保留离线操作能力，但增加另一套入口的行为一致性负担；当前采用 HTTP 统一入口。
- 重启后补执行尚未应用的命令：须额外处理有效期与跨场次问题，本轮选择明确中断并由用户重新提交。
- 按访问者时区统计“今日”：更贴近访问者当地日期，但不同设备统计结果可能不同，本轮统一采用北京时间。
- 让失败任务在整个退避期保持 pending，以复用任务停止入口：会改变现有失败历史与任务状态语义；选择独立的目标/场次停止入口，直接取消持续录制意图。
- 仅在手动命令中检查过期，或用批次完成时间代表观测时间：周期扫描仍能覆盖较新场次；选择所有来源统一排序并逐目标应用。
- 超时后仅取消 Future 或丢弃返回值：不能保证运行中的阻塞调用退出；选择只读查询进程隔离，以有限的进程与 IPC 成本换取可回收边界。

## Consequences

- 调度与持久化需区分长期自动录制设置和本场录制意图；不能仅修改 `auto_record` 后沿用现有调度条件。
- 新增目标逻辑需区分首次新增、已有目标与恢复已移除目标，逐条返回实际处理结果。
- 部署与验收必须显式使用独立新数据目录，不将新建数据库解释为允许删除旧库；旧数据不出现在新控制台中是已接受的范围边界。
- 前端方案已同步刷新约定、关闭服务后的交互、手动开录及停止本场说明，并链接后端唯一接口契约；实施时新增的网页服务生命周期不得绕过既有平滑封口流程。
- 调度 CLI 现有 7 个子命令分别是 `add`、`status`、`record`、`remove`、`stop`、`reconcile`、`run`；接口需覆盖其查询和控制能力，包括前端尚无按钮的对账操作，不把 Worker 参数入口混入网页控制接口。
- 扫描器需同时调整结果时序与执行资源管理；验证须覆盖旧扫描晚到、退避期取消意图、查询超时与主控退出后的资源回收，不能只验证命令返回成功或超时。
- 工程结构、接口契约、数据库调整、实施步骤和验收要求见后端方案；最初文档授权不包含实施，后续代码实施依据 2026-11-11 用户单独授权。
