# 0013 冻结检测改用录像流，画面检查失效不停止录制

## Status
accepted（2026-11-09 决定并实现；实机结果见[冻结检测改用录像流实机验证](../证据/验证/20261109-冻结检测改用录像流实机验证.md)）

## Context
[ADR 0007](0007-preflight-content-gate-and-visual-watchdog.md) 的运行期视觉看门狗通过 ADB 截取模拟器全屏 PNG 来判断画面冻结。实测中，显卡降频时单张截图要 3～4 秒，偶尔超过 8 秒；2026-11-08 的 15 分钟测试就因截图连续失败被判定“画面检查不可用”而停止，可当时录像仍在正常增长。截图只用于画面比较，登录页靠前台 Activity 判断，文件停止增长另有独立检测。

## Decision
continuous 模式下，冻结检测改为从录制管线已经采集到的视频流中取画面：Worker 的字节桥在把录像字节交给封装进程的同时，非阻塞地复制一份给独立的分析进程，解码成低分辨率画面供 Worker 比较，同时统计实际帧率，运行期不再向模拟器索取截图。分析一路跟不上时只丢分析数据，不得反过来拖慢录像写入；分析进程可单独重启，不影响录制。

分析进程自身的故障不得被当成录像冻结：分析一路一段时间没有输出新帧时，先重启分析进程核实，新进程仍收不到新帧才按冻结处理。这一路检查失效时，先自动重启；重启不成功则继续录制，并给切片打“画面检查不可用”的切片质量标记，期间只靠文件增长检测判断卡死，不再因“检查手段不可用”而停止录制。帧率连续 60 秒低于 12 fps 时，给切片打低帧率质量标记，录制照常继续。

## Consequences
- 运行期截图对模拟器的额外负载与截图超时一并消失，原“截图连续失败 60 秒停止”的规则随之取消。
- 每一路录制会在宿主机上多一路 H.264 解码，占用部分 CPU。
- 冻结检测只能看到 scrcpy 实际采到的画面；直播内容本身的静止（如平台临时遮断画面但弹幕仍在滚动）不属于冻结。
- 冻结的分级处理阈值（ADR 0006）不变；restart 诊断模式随 [ADR 0014](0014-remove-restart-mode-and-dual-pipeline.md) 删除，不需要兼容。
