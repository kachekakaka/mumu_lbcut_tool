# 0020 任务结束由 Worker 收尾强制关闭抖音，取消调度器复位状态

## Status
accepted（2026-11-13 用户授权实施，已实现 Worker 收尾关闭抖音并移除 `resetting`，替代 ADR 0015 的对应复位行为；[实施方案](../../archive/docs/方案/20261112-任务结束关闭模拟器抖音进程实施方案.md)已完成，[台式机 T10 实机验收](../证据/验证/20261113-T8按需开机与T10冷启动再录实机验证.md)通过）

## Context
在 [ADR 0019](0019-scheduler-on-demand-instance-boot.md) 确立“热实例不自动关机”后，普通结束路径（手动平滑停止、主播下播、到达设定时长、场次切换及各类非 `15`/`20` 失败退出）只停掉录播采集与 Worker 进程并直接释放实例，模拟器内的抖音进程仍停留在直播间画面或后台推荐流，持续占用宿主机 CPU、显存与网络带宽。此前仅登录强阻断（退出码 `15`）会在 Worker 退出后将实例置为 `resetting`，由调度器后台调用 `InstancePool.reset_app()` 执行 `am force-stop` 并立即 `am start` 冷启动抖音首页。

## Decision
1. **结束仅 `am force-stop`，不主动重开首页**：所有符合条件的在线结束路径统一尝试关闭抖音，不在收尾阶段重开首页。下次任务仍通过正常导航、弹窗消解与身份门禁进房。
2. **执行归属统一放在 Worker 收尾（`_cleanup`）**：正常路径在采集停止和切片封口之后、释放锁之前执行关闭尝试；异常路径通过嵌套 `finally` 保证清理尝试与锁释放。只保证关闭尝试及命令回收先于下一单，不保证关闭必定成功。
3. **短超时容错不改终态**：若设备已离线（如退出码 `20`）或 ADB 命令因短超时未成功，仅记录警告日志，绝不阻断或篡改既有任务终态、切片成果与退出码，也不阻止归还实例锁。
4. **登录强阻断（退出码 `15`）与常规结束合并，移除 `resetting`**：Worker 统一执行关闭尝试后，不再需要单独复位队列；关闭失败仅告警，仍允许实例回到 `idle`，不将清理失败变为任务失败或永久阻断。

## Considered Options
- **关闭抖音后立即重开首页（复用原 `reset_app`）**：减少下一单冷启动等待，但推荐页仍可能持续播放并消耗资源，不符合空闲省资源目标；实际耗时差异待测。
- **仅在正常停止/下播或无排队任务时关闭抖音**：减少换场重开耗时，但普通失败或异常退播往往伴随页面或缓存脏状态，统一清理可让每场录制都从干净进程启动且规则简单。
- **由调度器后台实例池统一关闭抖音并保留 `resetting`（或双保险双端清理）**：可覆盖 Worker 进程被强杀未走 `_cleanup` 的极端情况，但单独跑 CLI、主控崩掉后旧 Worker 自停不生效，且会增加主控 `close()` 关闭链路等待与重复状态维护；而触发强杀进入 `reconcile` 人工对账时本来也应保留现场。
- **保留 `resetting` 仅用于 `15` 号退出后兜底再发一次 `force-stop`**：与 Worker 收尾完全同构，保留独立状态机与前端枚举属于多余复杂度。

## Consequences
- 成功关闭后下一单需冷启动和消解首页弹窗；新增耗时及默认导航时限是否足够均待实机测量，不以固定等待时间作保证。具体异常与验收边界以实施方案为准。
- 已删除 `InstanceStatus.RESETTING`、`InstancePool.reset_app`、调度器 `_resets` 队列及前端复位状态，并同步更新 [控制台接口契约](../控制台接口契约.md) 与 [最小调度运行说明](../最小调度运行说明.md)。
- 对外强杀 Worker 导致进入 `reconcile` 人工对账、或未建立 ADB 连接即因设备不可用退出的场景不触发关闭抖音。
