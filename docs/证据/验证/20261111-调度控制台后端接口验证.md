## 自动化覆盖与实际边界

- SQLite v2 拒绝旧库且原文件保持不变；命令与业务变更共同回滚/提交；成功命令不会在中断处理时改为 interrupted；重复请求优先于已移除对象检查，同编号异内容冲突；批量新增事务故障不留下部分目标。
- 本场意图在关闭自动开关、失败和重启后保留；退避期没有活跃任务也可按主播停止；换场冲突不误停新场；恢复目标保留身份策略和人工标记；未知、下播不留手动预约。
- 周期扫描、手动查询、启动复核使用相同序号；旧 A 结果不会覆盖新 B 意图；较新 UNKNOWN 淘汰旧 LIVE；ENDED 不重复计数；启动复核失效后重新安排；没有槽位时不增加序号。
- 查询使用真实子进程与独立 IPC。DNS、游客锁、重试、持续响应、解析及半截 IPC 阻塞为合成注入，均由父进程期限终止并回收；测试中缩短期限以提高复现速度，生产默认仍为 30 秒。重复超时无进程/读取线程增长；5/1/2 容量隔离；正常进程连续查询复用；回收预算失败报告致命故障且不归还槽位。
- 独立 Windows 宿主验证端口占用不创建运行库、双主控不修改未应用命令、初始化/调度异常非零退出及锁释放、Ctrl+C/Ctrl+Break 满槽位关闭。强杀宿主后其查询 Job Object 进程退出，模拟录制子进程保持存活，随后由测试显式收尾。这里的模拟录制子进程只验证 Job 归属，不等同于真实媒体强杀验收。
- 读取接口验证字段与空值、筛选交集、分页总数、读快照、历史关联、北京时间零点完成数、质量与中止告警；日志验证缺失/空文件、中文尾行、1 MiB 与行数上限、越界；静态夹具验证 SPA、未构建 503、未知 API JSON 404。CLI 经真实 HTTP 向合成 Worker 发停止命令，并验证超时保留请求编号。
