## 联调环境

仓外宿主脚本启动真实的 `run_server`、调度器和 SQLite 运行库，静态页面由后端同端口托管 `web/dist/`。只替换三部分：实例池（由控制文件声明实例是否启动）、开播查询（由控制文件给出在播状态、房间号与昵称）、Worker（线程模拟心跳、20 秒切片、首片低帧率标记、指定目标运行若干秒后以退出码 30 中止、写运行日志）。因此本轮证明的是“前端 ↔ 真实 HTTP 接口与调度状态机”的对接，不是媒体录制验收。

### 合成异常场景

`synthetic-02` 使用真实 FastAPI、Store、SQLite 和页面操作，但固定合成业务状态，不启动 Scheduler 或 Worker。以下全部通过，不冒充真机自然触发结果：

- 将运行中的控制命令留待完成，实际停止并重启夹具服务；同一浏览器自动重连，命令 `2d97034ed20d472b8fd8ae42b69901f2` 显示 `interrupted`。中断使用真实 `Store.interrupt_commands` 路径。
- 日志截断使用既有真实 Worker 的 `events.ndjson` 原文副本（325086 字节、618 行）挂到合成任务的日志索引，接口返回 200 行、`truncated=true`，页面文本和截断提示均核对通过。这是“历史真实事件日志 + 合成任务索引”，不是当前任务自然生成的大运行日志。

首次 `synthetic-01` 夹具使用 Scheduler，预置状态被正常调度推进，未能构造预期场景；保留失败产物，不将其计为产品失败或通过结果。探针早期隐藏控件定位、动态查询时间比较和日志读取时间差造成的断言失败，也分别保留诊断记录，修正探针后以本文列出的最终结果为准。
