## 实现与自动化覆盖

Worker 取得连续两次完整双标识匹配才发布 verified；有限等待切房暂态，可靠冲突在缺证据、返回失败或重新导航后仍阻断显式未确认放行。资料页匹配须返回同一直播任务，已完成取证可再次打开新资料页。重新定位前清空当前身份及证据时间，首次、准备阶段和运行期恢复共享失败码。

调度保留 LIVE 和已知换场事实，缺项不拼接历史字段、不用 web_rid 造场次；新任务、占用实例／按需开机和最终启动都有完整性与新鲜度准入。缺项或过期 pending 可由正常扫描或再次手动查询恢复，同场复用任务，换场结束旧任务；旧结果不能撤销控制意图。

## 实机结果

每轮开始前确认实例 2 的 Android 和进程均关闭，使用共享实例锁；结束后确认关闭并释放锁。A 为 `TuiTui.888_`、B 为 `xxuan0222`，每轮真实查询确认在播且两项完整，未从旧调查记录直接取预期身份。

| 场景 | 观察与结果 |
| --- | --- |
| 冷启动 A | 一次导航、两次完整匹配，通过；定位含画面就绪约 24.6 秒 |
| A→B→A 两轮 | 四次切换均一次导航通过，约 10.1～11.1 秒；第一轮两次切换自然出现新 room_id＋旧 UID，后续两次完整匹配后才放行，没有因暂态立即 reset |
| 快速路径持续不可用 | 仅在仓外探针进程内关闭 Fragment 路径；同一导航内取得两份不同 Activity token 的新资料页证据，两次返回均确认；身份阶段约 28.2 秒，总定位约 37.1 秒，未超过预算 |
| 错房且开启显式例外 | 保持 A 页面，仅隔离探针的导航调用，以 B 的真实查询结果核验；约 8.3 秒后稳定 MISMATCH，未进入画面／采集准入 |
| 资料卡加载中与返回失败 | 首次自然返回 `anchor_card_not_ready`，同一导航内继续观察取得新资料页；仅对探针 Back 命令注入异常，仍保留完整可靠字段，`returned_to_live=false`，与 B 比较仍是 MISMATCH；之后真实导航恢复 A 成功 |
| 实际纠偏 | 探针第一次导航保持 A，稳定错房后由真实 reset 导航到 B，第二次导航连续匹配并通过；没有伪造正确证据 |
| 真实 Worker 短录 | 默认严格模式，冷启动后身份 target_ready 先于正式切片；运行约 30 秒，两个切片正常封口，唯一末片标记，退出码 0，`had_segment_errors=false` |

短录产物为 H.264 720×1280 视频＋AAC 音频；两片时长约 15.9145 秒、14.046 秒，均为 verified。逐流包 DTS 检查无倒退或重复，保留解复用时间基的完整解码均无错误。抽看两片第 5 秒画面，直播页顶部目标昵称与当次查询一致，第二片出现连麦画面但仍是同一直播页；未以昵称替代程序双标识校验。

普通 null 输出解码命令曾因输出时间基取整报告非单调 DTS；随后独立检查输入包 DTS，并以 `-fps_mode passthrough -enc_time_base demux` 完整解码均通过。该命令差异未通过修改源录像消除。这里验证媒体可读与身份流程，不替代长时间音画同步验收。

## 材料与边界

所有批次目录位于仓库同级 `mumu_lbcut_tool_dev/mumu_lbcut_tool_tmp/`，原始日志、图片、录像不进入 Git：

- 同目录 `recovery.py`、`recovery.log`、`recovery-retry.log`：首轮未到故障注入点即停止，重试后验证返回失败与真实纠偏；首次关闭瞬间进程仍在，随后单独查询确认已关闭，重试加入有界关闭确认。
