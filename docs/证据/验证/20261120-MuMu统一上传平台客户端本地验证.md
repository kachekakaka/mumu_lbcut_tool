## 关键场景

- 自动场次跨 Job 按 A1、A2、B1 排列，两个同名切片各自指向真实目录。生成一个 multipart 单元。邻场录像和原 MP4 保留在原路径。
- 注入写 YAML 前、写完未记账两种中断，恢复沿用同一作品 UUID 和路径。平台离线时仍写出本地 YAML。未封口、错房、身份未核实及损坏录像进入待核对。
- 手动反复预览保留作品 UUID，预览和取消均不占用切片。预览后文件、YAML、MID 或部署变化时阻止原确认。手动和整场顺序颠倒仍能关联同一单，部分重合会指出切片。
- 对已预览的 YAML 注入重复键、未知字段及越界相对素材路径。客户端因原字节版本变化拒绝旧确认，且保留改动文件。
- 模拟受理后丢回包，移走 YAML 后按原 Key 只读找回。标记派发后模拟请求未到平台，关闭自动投稿再恢复，未重发 POST，任务数仍为零。
- 新库独立初始化并拒绝以现行格式打开旧库。测试核对旧库字节保持原样。浏览器首轮构建一度写入在用服务的静态目录，随后用基线 `4fe8603` 重建并恢复旧版页面，确认主页面和入口资源返回成功。最终浏览器验证从独立网页目录复跑。
