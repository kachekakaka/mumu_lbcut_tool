## 实现结果

- Worker 成功取得实例锁、连接 ADB 后保存严格绑定 serial 的清理客户端。正常结束先完成采集会话封口，再执行一次 `am force-stop com.ss.android.ugc.aweme`，默认命令超时 4 秒；关闭尝试及命令回收完成后释放锁，不在收尾阶段重开首页，也不关闭模拟器。
- 关闭失败只记录包含实例编号、serial、非零退出码或异常、stdout/stderr 的警告，不覆盖原任务退出码、原因和切片终态。看门狗或管线收尾异常时仍尝试关闭并释放锁，原异常不被应用关闭错误遮蔽。
- 未拿到锁、未成功连接设备时不发送关闭命令；外部强杀未进入收尾的情况不新增调度器兜底动作。
- 移除调度器 `resetting` 状态、复位队列、`reset_app` 与 `finish_reset`。退出码 15 正常回收后直接进入 `idle` 并等待原有退避；退出码 20 及待对账仍分别保留 `offline`、`reconcile` 规则。
- 接口、前端、Mock 与说明同步为五种实例状态；按 `status=resetting` 筛选返回 422，总览不再包含该计数。数据库格式仍为 v3，没有新增迁移或覆盖。

## 自动化覆盖

主要新增 `tests/test_worker_cleanup.py`，沿用真实 `WorkerController.run()`、采集会话和共享实例锁；只在设备执行与采集进程边界使用替身。媒体夹具仍经过真实固定版 FFmpeg/ffprobe 生成和封口校验，不代表真实直播录制。

| 场景 | 结果 |
| --- | --- |
| 到时结束、15/16/17/18/30 失败结束 | 先停止采集、完成正常切片终态，再针对唯一 serial 发送关闭命令；Worker 终态随后发出 |
| 手动停止、下播停止、主控关闭、事件流断开停止 | 原停止原因保留，尾片封口后执行关闭 |
| 关闭命令非零退出、超时或执行异常 | 原退出码与原因保留；成功切片不被改成失败；警告保留原始输出 |
| 看门狗停止、管线 teardown 抛错 | 仍尝试关闭，异常终态保留，锁可以重新获取 |
| 关闭命令执行期间 | 同一实例锁仍无法被其他 Worker 获取 |
| 未拿锁、开机失败、ADB 连接失败 | 无应用关闭命令，不操作其他设备 |
| 同一实例再次运行 Worker | 可重新取得锁并完成第二个独立任务；隔离导航验证从桌面先启动首页，再发送进房入口 |
| 调度器收到退出码 15 | 立即释放为空闲，退避到期后重试，无复位队列 |
| 控制台状态契约 | 旧筛选枚举返回 422，总览无旧计数，前端测试与类型构建通过 |
