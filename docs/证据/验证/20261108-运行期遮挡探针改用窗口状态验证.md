# 运行期遮挡探针改用窗口状态验证

- 日期：2026-11-08～11-09。
- 受测代码：`d651b4c` 之上的未提交工作区改动（窗口状态探针）。
- 环境：Windows（`LAPTOP-42P5GQFB`）/ MuMu 实例 2，Android 15 / Python 3.11 / continuous 采集 / 严格身份模式（`allow_unconfirmed_identity=False`）/ 抖音无登录。实例 3 未启动。
- 外部材料：仓库同级 `mumu_lbcut_tool_dev/mumu_lbcut_tool_tmp/` 下的各轮目录（见下文）。运行器为同级的 `run_live_soak.py`（公开解析确认在播、每 15 秒记录 GPU 温度/时钟/降频状态、可选在第一片开始 N 秒后点一次主播头像打开资料卡，不发 BACK），验收脚本为 `verify_15m_fix_test.py`。
- 性质：实机诊断与真实 MuMu 直播录制；单元测试结果单独标出。

## 1. 问题与诊断

[15 分钟实机验证](20261108-截图容错修复与15分钟实机验证.md)中，运行期 UIAutomator 表面探针每次都在 6 秒时限后被强制结束，录制中的遮挡检测实际不可用。

诊断目录：`20261108-uiautomator-runtime-diagnostic`（若琳Pepper 直播间）。

| 操作 | 结果 |
| --- | --- |
| 直播页 `uiautomator dump`，连续 5 次 | 每次 11.3～11.8 秒；4 次输出 `ERROR: could not get idle state`（退出码 139，没有 XML），1 次成功 |
| 礼物展馆打开时 `uiautomator dump` | 11.5 秒，等不到空闲，没有 XML |
| 离开直播画面后 `uiautomator dump` | 5.9 秒成功 |
| `dumpsys window windows` / `dumpsys window displays` | 每次 0.16～0.20 秒，稳定返回 |

结论：直播页一直在刷新，UIAutomator 内部约 10 秒的空闲等待几乎总是失败。6 秒时限本身也短于这段等待，但把时限加大也只能偶尔拿到 XML，所以不再用 UIAutomator 做运行期探针。

窗口状态的实际表现（主播资料卡，点头像打开）：

| 状态 | 抖音窗口 | 焦点 |
| --- | --- | --- |
| 无遮挡 | LivePlayActivity `BASE_APPLICATION`，可见，`[0,0][1080,1920]` | 该基础窗口 |
| 资料卡打开 | 多出一个同属 LivePlayActivity 的 `APPLICATION` 窗口，可见，`[0,72][1080,1920]`，`DIM_BEHIND` | 新窗口 |
| 按 BACK 后 | 新窗口消失 | 回到基础窗口 |

Android 15 上 `mCurrentFocus` 和 `mFocusedApp` 只出现在 `dumpsys window displays` 中，不在 `dumpsys window windows` 中；ADB 输出需要去掉 `\r`。

## 2. 改动

| 文件 | 修改 |
| --- | --- |
| `src/worker/live_overlay.py` | 改为解析两份 `dumpsys window` 输出：焦点落在与 LivePlayActivity 同一 ActivityRecord 的非基础可见窗口时，判为遮挡 `live_panel_window`；焦点不明、焦点在系统窗口或记录对不上时，判为“不可用”，不做动作。删除基于 UIAutomator XML 的旧识别 |
| `src/worker/navigator.py` | `inspect_live_surface` 改读窗口状态（单次时限 3 秒）；`dismiss_live_overlay` 每次按 BACK 前重新探测，最多 2 次，确认已不是遮挡才算关闭；删除对旧观察结果的缓存 |
| `src/worker/continuous_session.py` | 运行期表面探针周期由 30 秒改为 10 秒 |
| 测试 | 新增 `tests/test_live_surface_probe.py` 及两份实机窗口转储夹具（资料卡打开、无遮挡）；删除旧 XML 夹具；更新相关测试 |

身份核验、房间定位、画面冻结/文件停止增长/登录页检测、截图探针、FFmpeg 编码和切片机制均未改动。

单元测试：`py -3.11 -m pytest -q tests` 为 226 passed（日志在诊断目录 `pytest-tests.log`）。

### 已知局限

- 窗口探针只知道“直播页上方有一个应用窗口”，分不出是资料卡、礼物展馆还是粉丝团，统一记为 `live_panel_window`。
- 抖音直接画在直播基础窗口内部的浮层（不新开窗口）无法识别。
- 只有资料卡做过实机注入；礼物展馆、粉丝团等面板是否以独立窗口出现尚未实测。

## 6. 测试中的操作失误

诊断时为观察礼物展馆，脚本点了入口 (926,366)，但展馆没有打开，脚本仍按了 BACK，直接退出了直播间，抖音随后弹出登录面板（`DYLoginActivity` / 首页登录弹层）。处理方式只是点关闭按钮 (994,690)，没有登录，随后重新进入直播间。这次失误没有改动账号状态和应用数据，但说明测试脚本在按 BACK 前必须先确认遮挡确实存在；产品代码的 `dismiss_live_overlay` 已按这一规则实现（每次 BACK 前重新探测）。
