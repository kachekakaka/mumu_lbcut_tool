# 导航取证效率优化验证

- 日期：2026-11-06
- 基线：`8494d2b57e57678b35a43ad9c3efc578faef103c`（`origin/main`）
- 实施范围：Worker 导航身份取证、UI dump、ADB 耗时观测；不改录制管线、调度职责、身份核验规则和默认 300 秒定位预算。
- 当前状态：代码及测试修改保留在工作区，未 commit / push。

## 本轮修改

1. **限制主播入口点击次数**
   - 每次实际导航代际最多点击一次主播入口。
   - UI 树暂时未刷新时只重读，不重复点击同一位置。
   - 同一导航代际的后续取证复检继承已点击状态；真正重新导航时才重置。
   - 点击入口后若资料卡证据暂时未出现，保留当前页面供下一轮读取，避免收尾逻辑把刚打开的资料卡关闭。

2. **减少 UI dump 的 ADB 往返**
   - 将 `uiautomator dump`、读取 XML 和临时文件清理合并到一次 `adb shell sh -c` 调用。
   - 仍使用每次唯一的临时文件名，并解析完整 hierarchy XML；读取失败不复用旧 XML。
   - 超时情况下另行尽力清理临时文件。

3. **复用新鲜遮挡观测**
   - 资料页清理阶段刚取得、且不超过 5 秒的遮挡观测可供最终画面确认复用。
   - 页面发生导航时清空缓存；缓存过期或 Activity 不匹配时重新检查。
   - 不把 UNKNOWN 观测当作“已无遮挡”。

4. **减少重复前台页面查询**
   - `get_current_focus_package()` 与 `get_current_focus_activity()` 共用同一份 250ms 前台快照，避免连续调用重复执行 `dumpsys window`。
   - 点击、返回、Intent 导航前失效缓存；新导航开始也清空旧快照，避免把旧页面当成当前页面。
   - Activity / Window 观测仍保留原有回退路径，缓存只用于极短时间内的连续读取。

5. **补充性能计量**
   - ADB 按 UI dump、Activity / Window 查询、截图命令、点击、返回键、Intent 分类计数。
   - 记录各类命令 count、total、max、P50、P95、失败和超时次数，并保留慢命令样本。
   - 内存截图另记耗时与失败次数。
   - 每次定位结束写入 `NAVIGATION_PERF` 结构化日志，供下一次实机对照分析。
