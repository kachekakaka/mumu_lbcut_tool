## 为什么出现展馆

上一轮没有安排“故意打开礼物展馆”的故障注入。旧导航存在两处直播中部坐标点击：无法读取主播入口时点击预设背景，以及取证返回后无条件点击预计空白处。这些位置随客户端布局会变成活动/展馆入口，是自动化误触的明确风险。旧测试没有每次点击前后的对应截图，不能百分之百反推哪一次点击造成用户截图；不能归咎给用户，也不能称为故意测试。

本轮已删除两处中部盲点。清理资料卡/展馆需新的 UI 证据，使用 BACK 后复核，不点关注、充值、赠送或直播退出 X。只识别“甄选展馆/礼物展馆标题＋独立面板标记”等支持场景，不因弹幕出现礼物文字而关闭页面。

## 已实现

默认 `continuous`：一个 scrcpy 连续向独占 Windows 命名管道输出 MKV；字节桥持续传给 ffmpeg，使用 stream copy 在关键帧处分装。计划分段不重启采集、不重编码、不插帧。旧路径仅可通过 `recording_mode=restart` 显式选择，Worker/SDK/调度 CLI 一致。

异步校验封口文件，分段独立 started/finished/aborted；正常停止先排空采集、再封口尾片与完成事件。故障恢复另建代际和目录并继续递增序号，不能假装故障恢复也零空档。输出无覆盖、队列有界，未封口文件保留。

运行时以只读 UI 探针识别已知遮挡；主线程尝试 BACK、重检并等待直播画面恢复，采集不中断。影响区间追加质量警告而不是删除原录像。无法读取 UI 时不盲点，仍存在未知面板漏检的限制。

## 实播阻断与未完成事项

MuMu 的对应日志明确记录 `Graphics Driver crash`、`crashModule=nvoglv64.dll`，实例退出；发生于目标页面导航阶段，尚未启动本轮连续录制进程。换另一个在播目标仍复现，停止继续反复拉起。未更换驱动、未变更显卡或模拟器渲染配置。日志证明退出类型，但具体触发条件还需专项诊断，不能据此保证与自动化动作完全无关。

还发生一次“候选目标均已下播”的前置条件失败；保留记录后换候选，不能记为录制通过。所有失败、原始日志都保留。首个实时合成输送测试曾因 ffmpeg 未允许写已存在的命名管道而退出，已修正该测试生产者的参数后重跑；不是放宽包完整性断言。

持续分装解决的是计划重启空档，不会恢复源、播放、渲染或编码阶段已经丢掉的帧。真机测试片第一片内部仍有源帧跳号，不能宣称“所有帧零丢失”。分段时长受关键帧影响；音画同步、长稳、多实例负载、未知布局面板仍未完成专项验收。

完整直播中的展馆自动恢复需要环境稳定后再补验。当前是“实现与自动化通过，持续采集已通过受控真机验证，直播遮挡恢复待实机验证”，不是全面稳定版本。
