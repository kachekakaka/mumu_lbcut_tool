# 目标直播定位与实录验证

- 日期：2026-11-06。
- 代码基线：`e6acb4bd2e478209ad5b1217858911e52cf6a71c` 上的本机未提交工作区；不是远程已发布版本。
- 范围：主动定位与纠偏、独立当前房间证据、Worker 主流程接入和单实例真实录制。
- 实际环境：Windows / Python 3.11 / MuMu Android 15，使用本轮确认空闲的 VM2。
- 完整代码状态、日志、录像、截图与清单：仓库同级 `mumu_lbcut_tool_dev/mumu_lbcut_tool_tmp/20261106-target-navigation-6d04a2/`。

## 实施结果

目标元数据仍由调度层解析，Worker 不新增外网查询。Worker 现在执行“定向进入—观察页面—切换入口/重新进入—当前主播资料取证—返回直播画面—开录”。优先尝试实际可用路径，最多三次，失败后才报告原因，不是只增加拒绝条件，也没有默认开启未确认身份放行。

当前客户端直播 UI 不显示数字 UID。实测通过点开当前主播资料卡，读取客户端新生成的 UserProfileActivity Intent，可取得独立 `room_id` 和 `uid`。代码要求同一直播任务、新 Activity 标识、来源 live，不采信历史页面或待导航目标。取证后关闭自己打开的资料页/登录提示，画面就绪后才开始录像。

UI XML 改为每次唯一临时文件，防止 dump 失败后读取旧页面；MuMu dumper 写出有效 XML 后返回 139 的情况按新文件内容处理。分享链接在游客模式会要求登录，已放弃作为本轮生产路径；剪贴板实验代码仅保留在仓外证据目录，未引入产品依赖。

## 失败记录与边界

- 新增定位入口前的回归失败、整合时参数不匹配、两个旧测试夹具与新接口不一致，均保留日志，修复后重新跑全量。没有通过放宽错房断言伪造成功。
- 第二轮最初因原选源房间已下播，不满足“两间不同在播房间”的前置条件；保留失败记录后刷新目标。
- 跨房间追加验证中遇到模拟器未运行，以及进入直播后页面尚未稳定导致暂时无法取证；补上就绪检查、先等画面再取证、同页复检，并按实际顶部主播节点与资料头像坐标操作。所有原始失败记录保留。
- 主播资料入口仅对本次真实客户端竖屏布局完成适配；其他版本/横屏仍待验证。
- 运行期监控离开直播 Activity 会触发纠偏；相同 Activity 内的切房可能直到后续强复核才发现。最近一次强证据的来源和时间显式上报。
- 串行切片仍有物理空档；本轮未验收交叠连续性、双 MuMu 并发、8～24 小时长稳或音画同步。
- 未修改 F2 来源项目，未使用本机 Codex，未提交或推送。
