## 本机实测补充

- 本机 Windows 首次启动测试发现上传端以小写形式写路径，录播端用原字符串对照，把同一目录误报为冲突。改为按 Windows 路径比较后，候选 5 实际写入绑定。首次失败输出保存在本轮的 `native-desktop.log` 和 `录播.log`。候选 5 第一次复测查询面板 API 等待 2 秒时超时，录播端随后记录了 HTTP 200。把测试器等待时间调到 12 秒后，相同步骤通过。录播服务正常关闭后，测试器遇到 CMD 的终止批处理确认，续测从已关闭的工作区继续，换包通过。
- 独立上传包在默认深层测试目录加载 `pywintypes` DLL 失败。缩短解压前缀后能启动。测试清理阶段曾用未规范化的设置路径构造退出绑定，改为使用上传端校验过的路径后整组通过。三轮日志为 `upload-native-regression.log`、`upload-native-short-path.log` 和 `upload-native-final.log`。
- 专用录像盘已在本机用 C、D 两个卷实测。第三片开始事件和终态丢失等断点使用受控模拟。
