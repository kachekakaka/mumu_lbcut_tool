## 一、背景与验证目标

1. **待办 T4 核心要求**：
   - 在此前 [20261111 台式机实机验证（L5）](20261111-录制自动恢复台式机实机验证.md#6-l5两路同时录制) 中，已验证过两路同时录制；但受限于当时仅有两个模拟器实例，三路并发一直作为待办 T4 暂缓挂起。
   - 本次在台式机配置并就绪第 3 个实例（`lb3`，实例索引 2）后，全面验证三路同时并发录制能力。
2. **全自动生产调度链条检验**：
   - 不采用手工逐个开机脚本，而是完全依托生产级 `Scheduler` + `Store` 调度架构；
   - 调度器由关闭待机状态开始，按需自动开机 3 个实例（`[0, 1, 2]`）、自动探测开播状态、自动导航定位、执行严格身份比对，拉起 3 个独立的 Worker 录制子进程。
3. **系统承载力与资源负载摸底**：
   - 周期性采样宿主机 CPU 占用、系统物理内存、GPU 核心利用率、GPU 显存占用、GPU 编码器利用率及 GPU 核心温度，评估台式机运行 3 个 Android 15 实例同时录像时的负载水位与稳定性。
4. **媒体质量与独立性（防串扰）验收**：
   - 切片时长设为 180 秒（3 分钟），三路各自需稳定产出至少 2 个以上切片；
   - 产出切片必须通过 FFprobe 容器与时间戳检查、Gyan FFmpeg 完整软解、音频电平检测；
   - 必须有确凿证据证实三路录制内容各自独立，没有实例间的音频串音或画面串流。
