# T24 Windows 录播便携包台式机验收

2026-11-21，Windows x64 录播内部候选 `portable-test.2` 通过 T24 台式机验收。录播源码基线为 `86b2809`，包含该提交后的工作区实现，实际构建输入见各 ZIP 的 `release.json`。录播与上传在同一台 Windows 11 x64 台式机使用两个独立 ZIP。模拟器沿用 lb3 的 1080 × 1920、480 DPI。[归档方案](../../../archive/docs/方案/20261121-T24-Windows录播便携包实施方案.md) · [分辨率对照](20261121-T25台式机单实例720P对照验证.md)

## 成品与环境

- 录播包内置 Python 3.11.9 x64、26 个锁定依赖、scrcpy 5.0.1、Gyan FFmpeg / ffprobe 9.0.2 和按网页锁文件构建的静态控制台。测试启动的 PATH 只含 Windows 和 System32。MuMu 和 ADB 使用台式机原安装。
- 上传使用 `fileUploadPlatform-0.2.0-windows-x64-mumu-portable.3.zip`，32,694,455 字节。录像根、录播私有数据、上传私有数据分别放在台式机本批目录内，原有账号和日常录像独立保存。
- 第一候选 `portable-test.1` 的 ZIP 共 2,340 个文件，226,915,285 字节，整包 CRC32 为 `754b1b8a`。台式机核对整个 ZIP 并校验全部条目。在禁止创建文件的真实 Windows 目录上，启动超过 35 秒还未报告拒写。第二候选改为在录像盘独占创建一次小文件，写入后删除。
- 第二候选 `mumu_lbcut_tool-0.2.0-windows-x64-portable-test.2.zip` 为 226,915,421 字节，整包 CRC32 为 `895a37fd`。台式机校验全部 2,340 个条目后，将整包分别解压到「中文 验包」和「换包 复验」目录。
- 为使用两个成品的默认端口，先查实原服务没有活动录制、上传或账号维护，获准后关闭。原录播库、平台库及成品保留。

## 目录、缺件与数据库

在只提供系统命令的 PATH 下，第二候选的「环境自检.cmd」通过。双击录播入口后，取消原生文件夹窗口，未留下调度库或录像设置。再次双击，在目录树选中包外的「录像 成品」。用独立测试进程占住 8000 后，新启动明确返回失败，原监听仍可用，已选路径正确保存。验收工具一开始尝试移动鼠标，远程会话无法移动系统光标，随后通过原生目录树完成了同一操作。

第二候选的 3 项目录设置回归在台式机全部通过。另在真实 Windows 文件系统逐项验证了 9 个故障场景。缺少 MuMu 管理程序、MuMu ADB、scrcpy server、网页入口或 ffprobe 会指出相应文件。原录像目录离线、被 Windows 权限拒写时会指出原目录。原调度库缺失时不会补建空库，旧版数据库也保留了原表、原值和版本。详细结果见台式机本批的 `faults.json` 和 `v2-tests.out`。
