## 行为与取舍

事实依据见[六小时长稳后续取证](20261112-六小时长稳测试验证.md#后续取证两次真实风险登录页)。登录 Activity 是登录提示证据，不直接证明主播下播，也不自动推断具体平台风控原因。

Scheduler 收到 `login_prompt_detected/login_blocked` 的恢复事件后，用独立的 1 个查询槽位复核目标，总槽位上限 9，不占用原有扫描、启动复核和手动容量。恢复期间按既有下播间隔（默认 10 秒）继续复核；需两次明确 ENDED 且间隔达标才确认下播并停止恢复，LIVE/UNKNOWN 不当下播。恢复成功或任务结束就取消后续复核，窗口上限 120 秒；既有 Worker 恢复不等待查询，不增加双向控制协议。查询结果仍受控制修订、观测顺序、任务生命周期和复核窗口约束，迟到结果不覆盖新状态。

任务 API 增加 `recovery_context`，以持久化事件投影最近一次恢复的触发原因、最后真实失败原因和结果，不新增数据库字段或迁移运行数据库。前端列表和详情同时展示这三项及原有 `stop_reason/error_reason/exit_code`。例如真实两次样本都显示：出现登录提示 → 页面加载超时 → 恢复已取消 → 主播下播停止；原失败状态和退出码 30 保留。契约正文只维护在[接口契约第 3 节](../../控制台接口契约.md#3-读取对象字段)。
