## 关键测试与证据含义

### 真实主控制流程

`tests/test_worker_controller.py` 调用实际 `WorkerController.run()`，保留状态机、事件发射和实际归档/ffprobe 校验，只替换设备和录制进程边界。覆盖正常轮转、两次崩溃后序号 1/2/3、最后产物损坏、交叠中停止、主次管线分别崩溃、不同 UID 阻断以及严格/逃逸身份边界。

真实看门狗图像差分也接入 Controller 回归测试：文件观测持续增长而图像静止时，触发恢复并受滚动/全局预算限制。不是只单测一个从未被调用的辅助函数。

### SQLite 与调度

`tests/test_scheduler_integration.py` 保留实际 Store、RoomScanner、InstancePool 和 Scheduler，只替换网络结果与外部子进程。验证 3 目标/2 槽位 FIFO、排队目标下播取消、UNKNOWN 往返不丢状态、不重复派单、人工停止同场抑制、启动前重新确认、启动失败上限、数据库失败收尾和重启保留占用。

### Windows 真实测试子进程

`tests/test_real_process_delivery.py` 通过实际 Windows Python 子进程验证：

- 并发 stdout/stderr 消费，约 20 MiB stderr 加 320 个心跳事件；业务回调故意变慢，仍能收齐终态。
- `CTRL_BREAK_EVENT` / 信号停止，进程退出后才提供完整的切片快照。
- 回调失败报告 `EventStreamIncomplete`，不静默宣布成功。
- 两个真实测试子进程同时占用两个逻辑槽位，第三个任务等待；通过真实调度 CLI 提交停止命令，释放后第三个任务启动；SQLite 中产物和终态完整保存。

最后一次真实子进程调度结果：三个任务均为 `finished`，退出码均为 0，`collection_complete=1`；两个逻辑槽位均已归还，本轮测试进程无残留。

这些子进程是有明确归属的测试夹具，模拟录制进程边界。它们不是 MuMu 实例，不能据此声称完成真实双模拟器直播验收。

### 真实媒体完整性

ffmpeg 在外部临时目录生成约 1 秒的合成双轨媒体，Controller 收尾使用真实 ffprobe 检测。有效小体积尾片通过；空文件、无音频、缺失校验能力及归档冲突拒绝成功。归档失败保留原文件，已有目标字节不被改变。

## 未执行及剩余边界

1. 本轮未启动或切换真实 MuMu/抖音实例，未使用真实主播直播素材；未验证默认严格身份在实际客户端中的可读取性。
2. 未进行 8～24 小时实际录制与真实双/多模拟器资源压力测试；本轮测试耗时不是录播性能基准。
3. 视频静止阈值、探针周期、冷启动等待和工具组合仍需目标环境标定。正常低动态节目与播放器冻结可能需要进一步区分。
4. 交叠录制默认关闭，未宣称零缺口；媒体同步、重叠去重和设备同时音频捕获需实测。
5. 主控不无缝接管旧进程的 stdout；存活或归属不明的任务保留 `needs_reconcile`，不重复派单，不强杀未知进程。
6. 串行封口/ffprobe 有有界等待，严格时延和真实故障恢复效果仍需实机验收。
7. 上传投递、完整 WebUI 及高并发优化不在本轮交付范围。

本轮结论：最小调度与录制边界已有实现和可重复测试证据，适合进入明确分配实例后的实机验收；不能据此标记所有历史问题、所有环境和长稳要求均已完成。
