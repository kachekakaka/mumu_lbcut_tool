# 任务切片、资源回收与性能修复验证

验证日期 2026-11-19。受测代码为基于 `1d92cc5` 的实施工作区。测试使用 Windows、Python 3.11、PowerShell 7、固定版 Gyan FFmpeg/ffprobe 9.0.2，使用独立 SQLite、合成媒体和隔离的 Core 接口。以下证据来自实际运行的隔离用例。[实施方案](../../../archive/docs/方案/20261119-任务与切片记账、资源回收和性能分阶段修复方案.md)

## 任务与切片

- 旧主控在创建 Worker 进程后、写入 PID 前被结束。独立连接看到旧任务仍占用实例，新主控用启动参数找回存活进程。第二实例继续录制，目标 B 保持等待。日志回放分段提交并重启后，旧实例继续归原任务。最后一条停止事件入库、结算提交后，B 才开录。合成尾片字节与夹具一致，低帧率风险保留。重复对账继续保留 B 的实例占用。[真实进程测试](../../../tests/test_real_process_delivery.py)
- 在线停止、自然退出及重启回放使用相同规则。完整性对照覆盖正常完成、带告警、非零退出、空切片、缺序号、缺停止、缺开始、缺终态和重复尾片。4,001 条心跳与另一 Worker 交错提交，队列第一次拒绝收尾标记，后续仍在提交所有证据后才结算。截断 UTF-8 与重复事件由同一日志回放用例覆盖。[调度集成测试](../../../tests/test_scheduler_integration.py)
- 真实 ASGI 入口验证切片冲突先于确认、登记或提交时分别拦截对应操作，原已发单仍可查询。另一片可独立安排一次。SQLite 短时占锁后服务继续工作，锁超时和提交 I/O 故障触发实际服务停机分支，保留日志，重新启动后补齐两项任务。[投递测试](../../../tests/test_segment_uploads.py) · [服务故障测试](../../../tests/test_real_process_delivery.py)
- 运行期空前台观测按独立计数处理。真实分类入口的两次读空后回到直播页保持一代采集，尾片正常封口；连续三次读空、两次确认离页分别报告相应恢复原因。[页面探针测试](../../../tests/test_live_surface_probe.py)

## 资源与响应

- 查询进程实测预热空闲基线及 10 轮启停后的结果均为 **208 个句柄、1 个 Python 线程、0 个子进程**。单独同步点让 IPC 线程晚于关闭预算交还进程。受理请求得到关闭结果，Job 句柄关闭，放行后 IPC 线程和自有进程退出。[查询进程测试](../../../tests/test_console_query_process.py)
- Windows 命令的真实三层进程继承双管道。独占命令超时后进程树全部退出，共享服务样本在客户端超时后仍写出响应，两组都回到原线程数。MuMu 窗口调用的成功、失效和竞争通过系统调用替身逐项核对。跨进程安装使用本地压缩包，验证了成功并发、首进程退出接手、缺件拒绝和占用保护。[命令测试](../../../tests/test_worker_executor.py) · [窗口测试](../../../tests/test_mumu_client.py) · [安装测试](../../../tests/test_dep_manager.py)
- 抽屉保留 31 个在途操作，结束后回调各一次、历史裁到 30 条。跟踪断线和无回执记录均能结束本页跟踪，迟到响应失效。前端 47 项测试及独立类型检查通过。[网页命令测试](../../../web/tests/commands.test.ts) · [切片页测试](../../../web/tests/upload.test.ts)
- 投递库和扫码库分别持写锁约 350 毫秒。各自的轻量 HTTP 请求和 25 毫秒定时器在释放锁之前完成。领取提交前后取消、旧代次迟回、扫码原请求取消及同键重试均走真实 ASGI 路由。核对了原单标识、派发权及 Core 替身上的业务次数。[投递测试](../../../tests/test_segment_uploads.py) · 扫码测试（历史版本 `4fe8603` 中的 `tests/test_bilibili_bridge.py`）
