# 当前设计说明

本文维护当前架构、内部流程和控制台交互设计；操作方法、接口字段、领域术语和未完事项分别见[运行说明](最小调度运行说明.md)、[接口契约](控制台接口契约.md)、[词汇表](../CONTEXT.md)和[待办](待办.md)。设计取舍见 [ADR](adr/)，实际验证结果见对应证据记录。

## 架构与职责

- 调度服务运行在单台录制机：`src/orchestrator/server.py` 组织 HTTP 服务、静态网页和调度线程；`api.py` 接收查询与控制请求，`queries.py` 整理查询结果，`cli.py` 通过同一 HTTP 接口操作。
- `scheduler.py` 根据直播观测、本场录制意图和实例状态排队、分配、重试及对账；`room_scanner.py` 和 `room_query_process.py` 分派受限的外部状态查询，`instance_pool.py` 管理实例探测与按需开机。
- `storage.py` 以 SQLite 事务保存目标、场次意图、任务、实例、命令、事件和切片；运行数据库与录像目录的边界见[运行说明](最小调度运行说明.md#环境与目录)。控制命令受理成功不等于媒体动作完成。
- 每个录播 Worker 控制一个模拟器实例。`src/worker/controller.py` 负责生命周期，`room_locator.py` 和 `navigator.py` 负责本地定位与准入，`continuous_session.py` 负责持续采集会话及恢复，`continuous_pipeline.py` 通过 scrcpy、命名管道与 ffmpeg 分装切片；`watchdog.py` 与 `stream_monitor.py` 负责运行期监测。
- `web/` 为独立前端源码，构建结果由调度服务托管。当前不提供上传、Webhook 或跨主机接管；网页访问与未验收边界见[运行说明](最小调度运行说明.md#当前交付边界)。

## 主要数据流与边界

1. 调度器查询目标直播状态，可信结果与用户控制共同决定本场意图、排队和实例分配；网络查询由调度层负责，Worker 使用本地设备证据进行准入。
2. 调度器启动 Worker，Worker 通过 NDJSON 上报生命周期、切片和健康事件；调度器保存事件与切片状态。运行日志和录像与数据库分开存放。
3. Worker 持续采集，由封装器按关键帧切片；计划切片不重启采集。完成须结合封口与校验结果，强杀或断电可能损坏未封口片。
4. 主控重启后对遗留进程和事件进行对账；归属无法确认时保留人工对账，不接管或终止未知进程。具体规则和操作见[运行说明](最小调度运行说明.md#重启对账)。

## 目标定位与开录准入

身份要求和显式放宽边界见[需求说明](需求说明.md#2-严格目标身份核验)。`room_locator.py` 组织目标直达、页面观察、替代入口和重新进入；确认直播 Activity 后取得独立身份，再检查最终画面，不能以 Intent 被系统接受替代到达目标。

`navigator.py::observe_live_room` 优先从当前 LivePlayActivity 的 LivePlayFragment 参数读取 room_id 与 UID，成功时不点击资料卡。参数尚未就绪时最多读取 6 次，读取间隔 1 秒，停止或剩余预算不足会提前结束；仍取不到时才回退资料卡／资料页，恢复直播画面。资料页证据仅接受本次任务中新出现、来源为 live 的页面记录，不回填待导航标识或沿用旧历史条目。

定位最多尝试三次，各步骤共享总截止时间；为最终画面确认预留 `min(45 秒, 总时限 / 3)`。每次导航后的身份阶段最多 60 秒，观察结束后至少间隔 1 秒再读；连续两次完整匹配才确认。冲突有 5 秒宽限期，宽限后连续两次相同冲突才按错房纠偏；任何可靠冲突候选在本次定位中持续阻断未确认例外，直到稳定匹配。非匹配样本使匹配计数归零，重新导航也清除旧匹配及证据。

尚无匹配候选时，将扣除观察间隔后的剩余预算至多一半交给当前取证，留出第二次读取的机会；已有匹配候选时可用剩余预算。每次预算包含资料页返回，不另加清理时长。资料卡加载中的点击标记保留以防连点；取证完成并确认返回同一直播任务后清除标记，允许再次取得新资料页证据。身份字段与返回结果分别处理：返回失败的匹配不计数，但可靠冲突仍保留。确认身份后画面暂不可读只等待当前阶段，明确离开直播页则作废身份并重新导航。可配置时限和诊断字段见[运行说明](最小调度运行说明.md#定位等待时限与慢页面)。

Controller 在进入每次定位、任何回调和心跳之前清空当前身份与证据时间；只有最终裁决发布新身份。首次定位、开录准备重定位与运行期恢复共用裁决及失败映射，身份失败为 18、登录阻断为 15、设备离线为 20；运行期先封口旧段，再进入新核验，不改写旧切片身份。

调度最近 LIVE 观测的 room_id／UID 同源覆盖，缺项置空，不拼接历史字段；已知新 room_id 仍更新场次并停止旧场。缺 room_id 时只保留最近已知场次键用于控制，不生成 web_rid 场次键，恢复 room_id 后与该键比较换场。创建、占用实例／按需开机和启动分别检查完整性与新鲜度（沿用 `max(60 秒, 扫描间隔×2)`）；启动使用当次复核结果。pending 因缺项或过期被阻断时，扫描补齐或手动重新查询可恢复，命令及结果入口均不能用已有任务幂等返回吞掉必要刷新。同场复用任务、换场结束旧任务，序号与控制修订仍保护迟到结果和停止意图。

`continuous_session.py` 在采集前、采集启动等待期间和登记正式切片前复核窗口状态。单次探针预算 1 秒，启动等待期间两次检查之间至少间隔 0.5 秒；登录页、离开直播页、遮挡或不可靠窗口状态均拒绝准入。先收尾临时采集再重新导航，每次启动最多三轮准备，不扣运行期恢复预算。准备耗尽报 `startup_gate_exhausted`，设备离线以 20 退出。拒绝的准备媒体保留在独立目录，通过 `capture_startup/discarded` 记录，不登记正式切片。

开录前弹窗按页面特征和安全动作白名单处理，具体文案匹配由 `src/worker/popup_bypasser.py::WHITELIST_PATTERNS` 维护；登录提示消解、冷启动等待及资料卡适配在 `navigator.py`。这些动作遵循[无登录基线](需求说明.md#1-运行基线抖音无登录)，不能把任意返回或确认点击当作安全消解。页面和横屏适配的实际覆盖见[运行说明](最小调度运行说明.md#主动定位而非只做-uid-门禁)。

## 外部状态查询与登录复核

`src/mvp/room_resolver.py` 通过 `live.douyin.com/webcast/room/web/enter/` 查询状态，使用向 `ttwid.bytedance.com` 注册的游客 `ttwid`，不使用登录 Cookie 或抓取直播间网页。`a_bogus` 签名来自 F2，来源见 [vendor/NOTICE.md](../src/mvp/vendor/NOTICE.md)。空正文会更换游客会话重试一次；房间状态 2 映射 LIVE，0、4 或业务码 30003 映射 ENDED，其余情况（含 3 暂停）为 UNKNOWN。主播 UID 优先取 `room.owner`，缺失时取外层 `data.user`。

`room_query_process.py` 将阻塞查询放在只读辅助进程中，容量分为扫描 5、启动复核 1、手动 2、登录复核 1 个槽位。默认查询总截止 30 秒，超时后确认进程与 IPC 回收才释放槽位；关闭时所有查询共用 5 秒回收预算，与录制收尾并行。各来源共用每目标观测序号，以发起时间排序；较旧、重复、场次或控制版本已变化的结果不更新状态。

登录事件由 `scheduler.py` 优先派发独立复核，不等待周期扫描，也不阻塞 Worker 当前恢复。复核窗口最多 120 秒，仍遵循[可信下播确认](最小调度运行说明.md#unknown-与下播)；满槽等待、过期结果、换场和移除都受观测序号及控制版本校验。开录准备阶段的登录拒绝同样触发复核，正式采集开始后取消该轮复核，晚到结果不得覆盖新状态。对外恢复摘要的字段与取值仍由[接口契约](控制台接口契约.md#3-读取对象字段)维护。

## 持续采集与监测实现

### 采集、封装与代际

`continuous_pipeline.py` 通过独占 Windows 命名管道接收 scrcpy 的 MKV，由字节桥送入 ffmpeg，以 stream copy 按关键帧分装 MP4。音频输出使用 `-copyinkf:a` 保留未标为关键包的 AAC-LC 数据，视频不重编码，修复依据见[音轨验证](证据/验证/20261112-固定FFmpeg9与AAC音轨修复验证.md)。

`continuous_session.py::sync` 等待 CSV 完整行确认封口，再将切片交给后台校验；最多四个待校验片，校验失败报告 aborted。正常停止先排空采集输出，再封装末片、完成校验和事件交付；对外终态与产物限制见[运行说明](最小调度运行说明.md#持续采集与切片终态)。

`_start_prepared_epoch` 在每次新建采集管线时增加 `generation_id`；正常物理切片轮转只增加切片序号。控制器据代际丢弃旧看门狗请求，并合并当前代际重复动作；计划切片不重置健康证据或恢复预算。启动即停止时先有界等待 `worker_started`，再发送中断；调度任务在收到首个 `segment_started` 后才进入 running。事件和时序排障入口见[运行说明](最小调度运行说明.md#录制事件与时序)。

### 窗口探针与画面分析

运行期以只读 Activity／窗口查询检查直播页面；普通录像分析不向模拟器索取截图，导航、画面确认及遮挡恢复仍可截图。窗口状态探针约每 10 秒执行，连续离开直播页或无法可靠读取时触发恢复。独立遮挡窗口的识别要求、关闭动作和可见限制见[运行说明](最小调度运行说明.md#直播面板遮挡)。

字节桥非阻塞地向独立分析 ffmpeg 复制录像流，解码为灰度 160×288 画面。分析队列上限约 8 MB，溢出只丢分析数据，不阻塞录像。`stream_monitor.py`、`watchdog.py` 和 `continuous_session.py` 分别负责分析健康、看门狗判定和主线程恢复：

| 检测 | 当前默认判定与处理 |
| --- | --- |
| 无新帧／冻结 | 10 秒无新帧时重建分析进程核实；新进程收到输入后 5 秒仍无帧且录像字节持续流入，才确认冻结，起点追溯到最后一帧。文件停止增长也参与停滞检测；看门狗按 10／20／45 秒阈值投递分级动作，由主线程执行恢复或停止 |
| 画面静止 | 有新帧但画面上中部变化低于 0.003；满 10 秒标记 `static_picture`，持续 120 秒且仍在直播页时重新定位一次。画面恢复变化后才重新计时，不把静止直接当成冻结 |
| 分析失效 | 分析进程退出、管道断开或队列溢出后自动重建；连续 3 次失败则标记 `visual_check_unavailable`，继续录像并依靠文件增长检测，之后每 60 秒重试 |
| 低帧率 | 60 秒平均低于 12 fps 时标记 `low_frame_rate`；平均值持续不低于 12 fps 满 60 秒才恢复。同一持续异常对每个切片只标一次 |

同一切片的多种质量标记保存在 `risk_json` 中。恢复前或重建采集失败时使用 `adb get-state` 确认设备离线，离线以 20 退出；其他恢复次数限制及用户可见结果见[运行说明](最小调度运行说明.md#失败处理)。相同 Activity 内切房的身份复核覆盖由[待办 K17](待办.md#已知缺陷与未验证事项)继续排查。

## 控制台页面与交互

本节依据当前 `web/src/views/`、`poller.ts`、`commands.ts` 和公共组件维护页面行为；旧[前端方案](../archive/docs/方案/20261111-调度控制台前端方案.md)只作为实施历史。接口字段、命令结果、筛选和统计口径见[接口契约](控制台接口契约.md)，业务取舍见 [ADR 0017](adr/0017-console-control-scope-and-session-intent.md)。

| 页面 | 当前用途与操作 |
| --- | --- |
| 总览 | 查看录制／排队数量、实例及告警，按对象跳转任务、目标或切片；今日切片数标明北京时间 |
| 实例 | 查看本机发现的实例并切换“参与录播”，支持启用与状态筛选；占用、开机中或待对账时禁止停用。启用选择与自动开机边界见 [ADR 0018](adr/0018-console-instance-selection-and-cleanup.md)、[ADR 0019](adr/0019-scheduler-on-demand-instance-boot.md) |
| 主播 | 批量添加、移除、切换自动录制、立即开录与停止本场；按主播停止固定使用点击时场次，确认期间换场不自动换参数重发；网页不提供身份放宽开关 |
| 任务 | 查看活跃／历史任务、任务详情、恢复原因、切片和日志，平滑停止任务；首版不提供对账按钮，对账使用 CLI |
| 切片 | 筛选切片、查看质量标记、复制路径和请求在录制机打开目录；任务详情复用同一切片表格 |

- 页面默认每 2 秒刷新当前页与系统信息，隐藏时为 10 秒；前一轮未完成时不叠加请求，回到前台立即刷新。后端已取得新状态、连接正常且接口及时响应时，以 5 秒内显示为验收目标；不含外部开下播探测耗时。日志只手动刷新。
- 调度操作提交后跟踪命令，终态后立即刷新；操作完成含义按契约显示。超时后重试保留原请求编号和参数；已中断操作由使用者重新提交。删除主播、停止本场和平滑停止任务有确认对话框。
- 断线时保留最后数据与更新时间，恢复后刷新；普通调度操作要求连接正常、服务与调度器均运行。“打开目录”为即时操作，只要求连接已确认，不等待调度命令；请求期间及结束后 1.5 秒内禁用同一表格的打开目录按钮，复制路径仍可用。提示请求已发送并要求在本机／录制机桌面确认，不能把接口成功显示成实际高亮成功。
- 明细时间按浏览器本地时区显示，总览统计口径由接口返回。未知状态、原因代码和质量标记保留原文；上传未启用时隐藏对应内容。窄屏使用横向滚动，任务／主播操作列取消固定，对话框适配窄屏；不把组件实现等同于真实手机验收。

构建与访问见[运行说明](最小调度运行说明.md#控制台网页)，前端测试入口见[测试说明](../tests/README.md#前端测试)。第二设备、真实手机及桌面定位实机验收仍分别由 T6、T9 跟踪。

### 桌面定位的异常边界

`src/orchestrator/api.py` 只在桌面启动调用处捕获 `Exception`（包括 `OSError`、`RuntimeError`、`ValueError`），记录完整异常并转换为 `desktop_open_failed`；此前的查询和路径校验保留各自错误语义，不拦截 `KeyboardInterrupt`、`SystemExit`。响应字段及成功／失败含义以[接口契约第 8 节](控制台接口契约.md#8-切片桌面定位desktop-reveal)为准。

## 子进程工作目录边界

MuMu 管理命令与主程序使用管理程序父目录，直接 ADB 调用及 scrcpy 使用外部 ADB 父目录；Windows Explorer 使用经验证的系统目录。工具、资源和输出路径先规范为绝对路径，调用端为子进程传入 `cwd`，不切换父进程全局目录，也不改变通用执行器的默认行为。主要入口为 `src/mvp/mumu_client.py`、`app_launcher.py`、`stream_recorder.py`，`src/worker/adb_client.py`、`continuous_session.py`、`continuous_pipeline.py`、`navigator.py`，以及 `src/orchestrator/desktop.py`；参数与失败边界测试见 `tests/test_cwd_isolation.py`。

这些设置只影响后续启动；复用已有常驻进程不会自动改变其工作目录，不通过自动强杀或重启共享服务解除历史占用。实机证据覆盖和剩余补验见[验证记录](证据/验证/20261114-模拟器与ADB常驻进程工作目录隔离实机验证.md#5-2026-11-15-归档前证据复核与更正)及[待办 K14](待办.md#已知缺陷与未验证事项)。

测试入口、隔离方式和适用范围见 [tests/README.md](../tests/README.md)；实机结果以具体验证记录为准，不以本文概述代替验收。
