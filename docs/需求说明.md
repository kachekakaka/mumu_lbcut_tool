# 需求说明

## 1. 运行基线：抖音无登录

确认来源：用户于 2026-11-08 明确要求，作为正式运行基线。

1. 模拟器中的抖音默认以无登录状态运行。部署和运行都不要求预先登录账号。
2. Worker 与调度器不要求登录，也不主动触发登录：不打开登录页，不输入手机号、验证码或密码，不执行任何登录操作。
3. 客户端自行弹出登录引导时，只允许使用不会登录的跳过、关闭或返回动作。无法关闭时按登录强阻断（退出码 15）上报，由调度器处置，不尝试登录绕过。
4. 不为规避登录引导而清除抖音数据、重装抖音或重置模拟器。
5. 不执行关注、送礼、充值、发言、分享等账号行为。

本条替代 [ADR 0007](adr/0007-preflight-content-gate-and-visual-watchdog.md) 第 3.1 节“模拟器实例预先登录抖音账号”的部署要求。ADR 0007 的开录门禁、视觉看门狗与退出码 15 等其余决定继续有效。

**状态**：当前代码没有任何依赖登录的步骤。无登录状态下的实机录制与身份核验结果见 [截图容错修复与 15 分钟实机验证](证据/验证/20261108-截图容错修复与15分钟实机验证.md)。客户端今后收紧游客风控时，此基线能否长期可用尚未验证。

## 2. 严格目标身份核验

1. 开录前必须连续取得两次独立、完整的匹配证据：当前直播间的 room_id 等于调度器本场解析出的 room_id，且当前主播 UID 等于目标主播 UID；不能跨观察拼接字段。
2. 证据缺失、来源不可靠或字段内部歧义时，结果为 UNCONFIRMED；可靠字段与目标不一致先作为冲突候选，经过有界稳定复核后裁决 MISMATCH。默认均不开录。此状态不同于开播状态查询的 UNKNOWN。
3. 默认 `allow_unconfirmed_identity=False`。无登录基线不能作为放宽身份核验的理由，不得以昵称、展示短号或历史场次 room_id 代替身份证据。
4. 只有使用者显式开启 `--allow-unconfirmed-identity` 时，才允许在有界复核后证据仍不完整时未确认录制；任何尚未解决的可靠冲突（包括单次冲突、返回资料页失败前已取得的冲突）都阻断该例外，须稳定双项匹配才能解除，未确认放行不记为 verified。
5. 调度器创建或启动任务必须取得同一次新鲜查询中的合法 room_id 与 UID，显式例外不豁免这一要求。在播查询缺项仍保留 LIVE 与已知换场事实，停止旧场与允许新任务分别处理。独立 Worker 默认也必须显式提供完整预期身份；参数非法在设备操作及创建产物之前失败。参数用法见[运行说明](最小调度运行说明.md#主动定位而非只做-uid-门禁)。

**状态**：双标识与稳定复核已接入代码，本次验收范围与结果见[K15 实施验证](证据/验证/20261116-K15双标识稳定复核实施验证.md)。取证路径与预算见[定位设计](设计说明.md#目标定位与开录准入)；运行期同一 Activity 内切房的覆盖仍由 K17 单独跟踪。
