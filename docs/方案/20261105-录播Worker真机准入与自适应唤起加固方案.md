## 问题陈述 (Problem Statement)

在完成录播 Worker 的职责纯化（剥离公网 HTTP 依赖，实现纯离线执行）并进行真实模拟器与真实抖音推流实机验证后，发现了以下在真实运行环境中威胁录制正确性的隐患：

1. **短视频误判与误录漏洞**：
   当目标主播已下播、或 Intent 唤起偶发异常退回抖音首页时，前台停留在推荐短视频信息流。由于短视频中人物存在动态动作，原先仅基于首帧白底检测与像素帧差动态比对的开录前置门禁（Pre-flight Content Gate）被动态画面欺骗放行，导致系统将短视频当作直播流误录入切片；
2. **标识契约失配导致退回首页**：
   抖音 Android 底层的直接开播 Intent 协议（`snssdk1128://live?room_id=...`）在客户端内仅识别在播时动态生成的 19 位真实内部房间 ID。当人工调试或外部传入几位数的 Web 端展示短号（`web_rid`，如短号数字或网页 URL）时，抖音客户端找不到对应内部 ID，会默默放弃并退回到首页推荐短视频；
3. **冷启动闪屏吞没 Intent 与系统弹窗阻塞**：
   模拟器首次拉起抖音 App 时存在 3~4 秒的黑底 Logo 闪屏，若过早注入深度 Intent 极易被闪屏吞没；同时客户端偶发的“未成年人模式/青少年模式”弹窗带有“不再提醒”按钮，若未被轻量穿透，会遮挡画面并诱发门禁超时。

## 解决方案 (Solution)

围绕 Worker 的真机运行鲁棒性实施准入卡口加固与离线自适应唤起：

1. **引入 Activity 类名硬卡口校验**：
   在开录前置门禁（Pre-flight Content Gate）放行推流录制前，通过微秒级 ADB 查询强制校验 Android 前台当前聚焦的 Activity：
   - 必须确认处于直播间页面（类名包含 `LivePlayActivity` 或 `Live`）；
   - 若前台停留在 `MainActivity`（首页短视频推荐流）或其他非直播界面，门禁坚决不予放行，立即阻断盲目录制，判定为未进入直播间，触发原地自愈或以专用码退出；
2. **纯离线自适应双模唤起**：
   Worker `--target` 在保持纯离线、零外网 HTTP 请求的前提下，增加对标识长度的智能自适应分流：
   - 若传入 19 位真实内部 ID（调度平台派发），直接走 `snssdk1128://live?room_id={id}` 实现秒级直达；
   - 若传入展示短号或网页 URL（人工调试或单兵场景），自动 fallback 到带有包名的应用内网页深度链接（`am start -a android.intent.action.VIEW -d https://live.douyin.com/{web_rid} -p com.ss.android.ugc.aweme`），保证单兵调试也不会退回首页；
3. **冷启动闪屏预热与弹窗穿透加固**：
   - Worker 导航器在唤醒直播间时，若检测到抖音未在前台运行，先预热 3.5 秒平滑度过 Logo 闪屏，再精准打入直播间 Intent；
   - 弹窗消解动作库（Popup Dismiss Matrix）将“未成年人模式/青少年模式”完整纳入白名单规则，自动点击“不再提醒”或关闭按钮穿透遮罩，且避免耗时 UI dump 阻塞门禁主线程。

## 用户故事 (User Stories)

1. 作为录播 Worker，我希望在正式启动录制管线落盘前，通过微秒级检查确认当前 Android 前台 Activity 确为直播间类名（`LivePlayActivity`），以便于在主播下播或系统退回首页推荐短视频时彻底阻断盲录，坚决杜绝误录短视频。
2. 作为开发者/测试人员，我希望在手动单兵调试 Worker 并输入几位数展示短号或网页 URL 时，Worker 能离线自适应通过应用内 Web 深度链接拉起直播间，以便于兼顾离线纯粹性与人工调试的便利性。
3. 作为录播调度平台，我希望在调度 Worker 录制时直接传入已解析好的 19 位内部房间 ID，以便于 Worker 通过标准 Schema 秒级直达直播流并开启推流录制。
4. 作为录播 Worker，我希望在模拟器冷启动抖音 App 时自动等待 3.5 秒度过闪屏，以便于避免过早注入 Intent 被闪屏挂起或吞没。
5. 作为录播 Worker，我希望在遭遇“未成年人模式/青少年模式”干扰弹窗时自动识别并点击“不再提醒”或关闭按钮，以便于防止全屏遮罩导致录制画面被遮挡。

## 实现决策 (Implementation Decisions)

### 1. 模块调整与接口优化

- **`src/worker/navigator.py` (WorkerNavigator)**：
  - `launch_room` 增加预热选项支持：当检测到前台不是抖音包名时，先执行 `am start -n com.ss.android.ugc.aweme/.main.MainActivity` 等待 3.5 秒闪屏结束，再注入直播间 Intent；
  - `launch_room` 增加短号离线分流逻辑：当目标标识非 19 位时，自动退回到 `https://live.douyin.com/{web_rid}` 并带上 `-p com.ss.android.ugc.aweme` 参数；
  - `verify_preflight_content_gate` 增加 Activity 强校验：在计算白底和像素帧差前，首先获取 `get_current_focus_activity()`：
    - 若包含 `LivePlayActivity` 或 `Live`，允许进入推流视觉动态判定；
    - 若为 `MainActivity` 或不包含直播特征，直接标记未就绪，继续重试或抛出阻断。
- **`src/worker/popup_bypasser.py` (PopupBypasser)**：
  - 在 `WHITELIST_PATTERNS` 中将规则更新为覆盖 `未成年人模式|青少年模式`，关闭按钮匹配 `不再提醒|我知道了|开启|进入青少年模式`；
  - 优化 UI dump 超时保护，避免冷启动期间的 ADB 延迟拖累门禁。
- **`src/worker/controller.py` (WorkerController)**：
  - 在唤起直播间时启用预热参数；
  - 开录前门禁超时放宽至 15 秒（默认从 8 秒调整），兼顾冷启动极端场景；
  - 未通过门禁且处于非直播间时，如实派发 `LoginBlockedEvent(reason="preflight_gate_failed")` 并以退出码 15 退出，由上层调度器执行切机漂移。

## 测试决策 (Testing Decisions)

### 1. 核心 Seams（测试接缝）

- **Seam 1: Worker 页面导航与门禁拦截 Seam (`tests/test_worker_navigator.py`)**
  - **断言与验证**：
    1. 模拟前台停留在 `MainActivity`，断言门禁坚决返回 `False`，绝不因视觉动态帧差被误放行；
    2. 模拟前台处于 `LivePlayActivity` 且有动态像素，断言门禁顺利返回 `True`；
    3. 模拟传入 19 位内部 ID 与展示短号，断言分发正确的 Android Intent 命令行。
- **Seam 2: 弹窗白名单穿透 Seam (`tests/test_preflight_gate_popup.py`)**
  - **断言与验证**：
    1. 注入包含“未成年人模式”和“不再提醒”的 UI Automator XML，断言正确解析出坐标并执行点击穿透。
- **Seam 3: 实机端到端推流与封口验证 (`scripts/verify_worker_e2e_live.py`)**
  - **断言与验证**：
    1. 驱动真实在播主播（林思琪），验证真实进入直播间推流；
    2. 验证常规交叠切片 `is_final: false`；
    3. 注入 `CTRL_BREAK_EVENT` 信号，验证切片平滑封口 `is_final: true` 与退出码 0；
    4. 截取 MP4 真实多点画面验证无短视频误录。

### 2. 良好测试标准
- 外部单测通过 Mock ADB 严格测试返回值与公开退出码，不依赖公网；
- 实机端到端脚本通过真实推流音视频文件与 `ffprobe` 验证合法性。

## 范围外说明 (Out of Scope)

- **公网房间号解析与开下播探测**：100% 归属于调度平台（基于类似 f2 机制），Worker 坚决不发起外网请求；
- **模拟器实例池并发分配与切机漂移**：归属于调度平台的实例池与状态机编排管线。
