## 问题陈述 (Problem Statement)

在直播录播运维过程中，切片落盘保存在宿主机的文件系统目录中。当前控制台网页在切片列表中仅支持一键“复制”文件绝对路径：
1. **本地排查翻找繁琐**：运维人员在录制机宿主机操作时，如果需要快速用播放器抽检某个切片、检查同目录下生成的原片与日志，必须先手动打开资源管理器，再把路径粘贴到地址栏，或在上百个切片中手动翻找，操作链路繁琐；
2. **多端交互边界未定义**：控制台已支持在第二设备（如笔记本或手机）通过局域网/私网组网访问，需要明确在非本机设备上触发打开目录时的安全边界（防止任意本地路径遍历或系统注入）与用户交互反馈（防止手机端点击后因手机无反应产生困惑）。

---

## 解决方案 (Solution)

构建端到端的**录制机桌面切片文件定位与高亮展示功能（Desktop Reveal）**：

1. **实体主键寻址与输出目录白名单保护**：新增专用即时接口 `POST /api/segments/{job_id}/{segment_index}/open-folder`。接口不接受前端传入的任意路径，严格依据切片主键查询已登记的真实落盘路径，并强制校验解析后的路径必须落在配置的 `output_dir` 录像根目录之内，从根本上杜绝任意文件系统遍历与越权执行风险；
2. **桌面高亮定位与优雅降级**：后端以异步非阻塞子进程方式调用 Windows 资源管理器（`explorer.exe /select,"<file_path>"`），直接在录制机屏幕上弹出并高亮选中该切片文件；若切片已被人工移动或文件不存在，自动降级为仅打开其所在的上层录像目录；
3. **私网设备全放行与设备感知交互反馈**：遵照控制台纯私网运行基线（ADR 0016），允许所有可信局域网客户端（包括手机）调用该接口；前端提供 1.5 秒防抖与局部 Loading 保护防连击，并根据当前浏览器访问主机名感知设备类型：
   - **本机访问**（`localhost` 或 `127.0.0.1`）：提示“已打开所在目录”；
   - **远程/手机访问**（局域网 IP 如 `192.168.x.x`）：明确提示“已在录制机桌面打开所在目录”。

## 用户故事 (User Stories)

1. 作为录播运维人员，当我在录制机本机查看切片列表时，我希望能够一键在 Windows 资源管理器中打开并高亮定位当前选中的 MP4 切片，以便于我立即用本地播放器快速复核画面或排查文件。
2. 作为录播运维人员，当我坐在工位用手机或笔记本浏览控制台时，我希望能远程点击“打开目录”让身旁的录制机屏幕立即展开该切片所在文件夹，以便于我无需回到录制机键盘前逐级点击寻找。
3. 作为录播运维人员，当我在手机上点击“打开目录”后，我希望界面明确告诉我“已在录制机桌面打开所在目录”，以便于我知晓动作发生在录制机屏幕上，而不是误以为手机端应当下载或报错无响应。
4. 作为录播运维人员，当我手抖快速连续点击“打开目录”按钮时，我希望界面进入短暂防抖保护，以便于避免录制机桌面被瞬间弹出的几十个文件夹窗口卡死。
5. 作为系统安全边界，我希望该接口绝不接受前端直接传入的任意本地操作系统路径，且只允许打开属于录像输出目录内的已登记切片，以便于防止恶意构造的路径遍历攻击或操作系统提权。
6. 作为录播运维人员，若某个切片已被手动删除或移动导致文件不存在，我希望系统优雅降级为打开其上层文件夹（若文件夹仍在）或给出清晰提示，以便于我了解文件当前的实际状态。

## 实现决策 (Implementation Decisions)

### 1. 后端接口设计与安全校验

- **端点与路由**：
  `POST /api/segments/{job_id}/{segment_index}/open-folder`
  - 属于即时 Action 接口，不进入持久化调度命令队列（不阻塞主控循环）。
  - 不需要请求体（允许空体）。
- **参数校验与业务安全流程**：
  1. 通过 `(job_id, segment_index)` 查询已持久化的切片记录，不存在返回 404 `segment_not_found`；
  2. 检查切片记录中是否存在已落盘的 `file_path`，若尚在录制未落盘则返回 404 `segment_file_not_ready`；
  3. **输出目录白名单硬卡口**：解析 `file_path` 的规范绝对路径 `target_file = Path(file_path).resolve()`，以及当前系统配置的 `output_root = Path(config.output_dir).resolve()`。严格校验 `target_file.is_relative_to(output_root)`；若超出白名单，记录警告并返回 403 `path_forbidden`；
  4. 检查 `target_file` 状态：
     - 若 `target_file.is_file()`：以定位模式执行 `reveal_in_desktop(target_file, is_file=True)`；
     - 若 `target_file` 不存在但父目录 `target_file.parent.is_dir()`：降级打开父目录 `reveal_in_desktop(target_file.parent, is_file=False)`；
     - 若父目录亦不存在：返回 404 `folder_not_found`。
- **响应结构（成功 200）**：
  ```json
  {
    "status": "succeeded",
    "file_path": "D:\\recordings\\job_1\\seg_001.mp4",
    "folder_path": "D:\\recordings\\job_1",
    "revealed": true
  }
  ```
  （降级打开目录时 `revealed` 为 `false`）。
- **宿主机进程拉起机制**：
  - 核心逻辑封装在 `src/orchestrator/desktop.py` 的 `reveal_path_in_explorer(path: Path, is_file: bool)`；
  - Windows 环境下使用 `subprocess.Popen` 异步拉起：
    - 文件定位：`explorer.exe /select,"<file_path>"`
    - 目录打开：`explorer.exe "<folder_path>"`
  - 为防止线程阻塞与 I/O 停顿，使用 `asyncio.to_thread` 执行调用；
  - 非 Windows 环境（如 Linux/CI 测试容器）做平滑降级（如 mock 或静默模拟，避免测试在跨平台环境下直接崩溃）。

### 2. 前端组件与交互设计

- **API 客户端更新**（`web/src/api/index.ts`）：
  - 新增 `openSegmentFolder(jobId: string, segmentIndex: number): Promise<OpenFolderResponse>`
- **切片表格改造**（`web/src/components/SegmentTable.vue`）：
  - 在“文件路径”列的“复制”按钮旁边新增“打开目录”按钮（或链接按钮）：
    ```html
    <el-button
      v-if="row.file_path"
      link
      type="primary"
      size="small"
      :loading="openingKey === `${row.job_id}:${row.segment_index}`"
      @click.stop="handleOpenFolder(row)"
    >打开目录</el-button>
    ```
- **交互逻辑与防抖**：
  - 点击后为该行设置 `openingKey`，防抖保护持续 1.5 秒后复位，期间禁用重复点击；
  - 设备检测：
    `const isLocal = ['localhost', '127.0.0.1', '::1'].includes(window.location.hostname)`
  - 成功提示：
    - `isLocal` 时弹出 `ElMessage.success('已打开所在目录')`；
    - 非本机时弹出 `ElMessage.success('已在录制机桌面打开所在目录')`；
  - 异常提示：捕获后端错误码（如 `folder_not_found`、`segment_file_not_ready`），使用 `ElMessage.warning` 显示针对性提示。

## 测试决策 (Testing Decisions)

本功能遵循“少而精、直击最高层 Seam”的测试原则，设立两个端到端高层验证 Seam：

### 1. 后端接口集成 Seam (`tests/test_console_api.py`)
- **标准**：使用 FastAPI TestClient 直接对 HTTP 接口发起请求，测试真实参数解析、数据库查表、白名单拦截与降级逻辑，不测试子进程内部细节。
- **测试场景**：
  1. **正常定位**：切片存在于 `output_dir` 且文件在磁盘，模拟执行返回 200，入参正确携带 `/select,` 且 `revealed=true`；
  2. **优雅降级**：切片文件不存在但目录存在，返回 200，执行打开目录且 `revealed=false`；
  3. **白名单拦截**：切片文件的实际路径不在 `output_dir` 范围（模拟越权路径），严格拦截并返回 403 `path_forbidden`；
  4. **不存在资源**：切片不存在或目录在磁盘已被彻底清除，分别返回 404 `segment_not_found` / `folder_not_found`；
  5. **严格参数**：非法参数或缺失路由时返回 404 / 422。

### 2. 前端组件与交互 Seam (`web/tests/commands.test.ts` 或新设 `web/tests/segment_table.test.ts`)
- **标准**：在 Vue Test Utils 环境下渲染 `SegmentTable.vue`，模拟真实用户点击行为。
- **测试场景**：
  1. 渲染切片表格时，“打开目录”按钮正常出现；
  2. 点击按钮后触发防抖 Loading，调用对应的 API 方法；
  3. 模拟本机访问（`localhost`），验证成功提示为“已打开所在目录”；
  4. 模拟第二设备访问（`192.168.3.250`），验证成功提示为“已在录制机桌面打开所在目录”；
  5. 模拟后端接口失败，验证正确弹出警告消息并解除防抖 Loading。

## 范围外说明 (Out of Scope)

1. **切片大文件 HTTP 跨设备下载/串流传输**：切片单文件通常达数百 MB 至数 GB，本功能只负责在录制机宿主机桌面定位高亮，不提供向远程手机或浏览器传输视频二进制文件的下载管道；
2. **公网权限认证系统**：控制台维持现有私网/局域网组网访问基线，本功能不新增独立的公网鉴权体系；
3. **文件批量操作与删除**：本功能只提供只读式的“打开目录高亮定位”，严禁向文件系统发送删除、重命名或覆盖命令。
