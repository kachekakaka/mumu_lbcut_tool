## 1. 背景与目标

调度器目前只有命令行：用 `status` 输出整库 JSON，`add` 直接保存目标，`record`、`stop`、`remove` 等写入命令队列（见[最小调度运行说明](../最小调度运行说明.md)）。查看几路录制的状态、失败重试和切片质量都要读 JSON，不能在录制机以外的设备上查看；后续统一入口见[后端方案](20261111-调度控制台后端接口实施方案.md)。

目标：做一个网页控制台，在录制机本机或通过组网的其他设备上：

1. 一眼看清正在录几路、各实例状态和需要关注的问题；
2. 管理监控主播，手动开录和平滑停止；
3. 查看任务运行情况、运行日志和切片（含质量标记与上传状态）。

## 2. 范围与非目标

范围：

- 前端工程（`web/`）：总览、实例、主播、任务、切片五个页面，以及第 5 节的交互规则。
- 第 6 节“接口对接”：引用后端唯一接口契约，说明页面如何使用。
- 上传状态的展示界面（后端未启用上传时隐藏）。

非目标：

- 后端 API 与调度服务托管静态文件——由后端方案负责；上传交付另做专项，本轮后端未启用上传。
- 登录验证（ADR 0016：只经组网访问）。
- 网页内播放切片；单独的手机布局（手机能看清即可，表格可横向滚动）。
- 实例操作按钮（ADR 0015 已取消人工解封，实例只查看）。
- 后端状态探测周期与命令执行机制；页面刷新按第 5 节及后端接口契约执行。

## 3. 技术与工程结构

- Vue 3 + Vite + TypeScript + Element Plus，Vue Router 管理五个页面。不引入额外的状态管理库，各页面直接调用接口模块。
- 源码在仓库根目录的 `web/`；`npm run build` 输出到 `web/dist/`，不提交 Git（`.gitignore` 增加 `web/node_modules/`、`web/dist/`）。打包发布时带上构建结果。
- 后端在 API 同一端口托管 `web/dist/`，前端所有请求使用相对路径 `/api/...`，不写死主机和端口；任何地址或组网隧道下都可直接使用。
- 开发时 Vite 开发服务器把 `/api` 代理到本机后端（地址用环境变量配置）。后端还没提供的部分（如上传状态）用 `web/src/mock/` 下的固定样例数据，开发服务器以 `npm run dev:mock`（或 `VITE_MOCK=1`）启用；带模拟开关构建会直接报错，构建产物不包含模拟数据。
- Node.js 只在开发和构建时需要（笔记本当前为 Node 24、npm 11）。台式机测试时从笔记本拷贝构建结果，不必安装 Node。
- 界面文字为中文；时间按浏览器本地时区显示（`MM-DD HH:mm:ss`，跨年显示年份），时长显示为 `时:分:秒`。

## 4. 页面设计

所有页面共用顶部栏：控制台名称、与后端的连接状态（正常 / 断开，断开时显示最后一次成功更新的时间）、上一次数据更新时间。左侧导航：总览、实例、主播、任务、切片。

### 4.1 总览

- 数字卡片：正在录制路数、排队任务数、空闲 / 离线实例数、今日完成切片数（标注“北京时间”，统计口径见后端方案）。
- 实例条：每个实例一个小卡片（编号、名称、状态颜色、当前主播）。
- 告警列表（按时间倒序，点击跳到对应页面）：
  - 失败重试中的目标：第几次、下次重试时间、最近失败原因，直接使用告警返回的数据；
  - 需要修正的目标（`needs_fix`）；
  - 需要人工对账的任务（`needs_reconcile`）；
  - 最近 24 小时内带质量标记或中止（aborted）的切片；
  - 上传失败的切片（上传启用时）。

### 4.2 实例（只查看）

表格列：编号、名称、状态、当前任务（链接到任务）、原因、状态更新时间。状态中文：空闲、录制中、复位中、离线、待对账；原因（如 `android_not_started`、`not_discovered`）显示中文说明，未知值原样显示。

### 4.3 主播

- 表格列：昵称（无则显示地址）、地址、开播状态（在播 / 已下播 / 未知，附确认时间；尚无确认时间时显示最近查询时间）、自动录制开关、当前任务状态、提示（本场已抑制 / 需要修正：原因 / 失败重试中：第 N 次，下次 hh:mm:ss）。
- 筛选：在播、自动录制开 / 关、有提示。按名称或地址搜索。
- 操作：
  - 新增：对话框输入一个或多个地址（每行一个），可选“仅手动录制”。提交后追踪命令，逐条显示结果（新增 / 已存在 / 已恢复 / 失败原因）；已有目标不因重复添加而改变设置。
  - 删除：二次确认，提示“正在录制的任务会平滑停止，录像保留”。
  - 自动录制开关：直接提交指定开/关值，拿到命令结果后刷新；提示关闭不停止已承接的本场，结束本场可用本页“停止本场”或任务页平滑停止。开启后按正常条件安排当前在播场次，不解除人工抑制。
  - 立即开录：对已抑制或需要修正的目标同样可用，提示后端会重新确认开播；只有成功安排本场时解除相关标记。未开播或暂时无法确认时显示原因，不显示“等待下次开播”。已有任务时跳到该任务；停止中或待对账时显示明确原因，不预约重开。
  - 停止本场：后端返回本场录制意图有效时可用，包括失败退避且没有活跃任务、等待对账的情况。二次确认说明“本场不再续录，正在录制的可控任务会平滑停止；继续监控，自动录制开关不变”。确认与提交固定使用点击时看到的场次；若后端返回场次已变，显示原因并刷新，不自动换成新场次重发。有待对账任务时明确提示“后续重试已取消，遗留进程仍需对账”，不显示已完成封口。
- 身份放宽开关（`--allow-unconfirmed-identity`）首版不在界面提供，仍通过 CLI 使用。

### 4.4 任务

- 默认显示进行中的任务（排队、启动中、录制中、停止中、待对账），切换后显示历史任务，支持按主播、状态、时间筛选，分页。
- 表格列：任务 ID（缩短显示，可复制）、主播、实例、状态、实际开录时间（尚未收到首片开始事件时为空）、已录时长、当前帧率、身份核验状态、切片数（完成 / 中止）、结束原因与退出码。详情另列 Worker 拉起时间。
- 状态中文：排队中、启动中、录制中、停止中、待对账、已完成、完成但有警告、失败、已取消。退出码附中文说明（0 正常、9 目标无效、15 登录强阻断、20 设备不可用、30 录制失败等，未知码原样显示）。
- 操作：
  - 平滑停止（录制中、启动中、排队中可用）：二次确认，提示“当前切片会封口保存，本场不再自动开录，可在主播页立即开录恢复”。
  - 查看日志：抽屉显示该任务运行日志的最后 N 行（默认 200），手动刷新，不自动滚动更新。
- 任务详情（展开行）：该任务的切片列表、最近导航与恢复事件摘要。

### 4.5 切片

- 按主播、任务、状态（录制中 / 完成 / 中止）、是否有质量标记、上传状态筛选，时间倒序分页。
- 表格列：主播、任务、序号、状态、时长、大小、是否末片、质量标记、上传状态、文件路径（可一键复制）。
- 质量标记显示为标签：遮挡（`overlay_*`）、低帧率、画面静止、画面检查不可用、身份未确认；鼠标悬停显示疑似开始时间。未知标记原样显示。
- 上传状态（上传启用时显示）：状态、尝试次数、最近错误、更新时间。真实字段与状态分类以后续上传专项为准；当前模拟界面按进行中灰色、成功绿色、失败红色显示，只展示，不提供重新推送按钮。

## 5. 交互规则

- **时效**：按后端契约每 2 秒查询当前页与系统信息，避免重叠请求；正常连接和接口及时响应时，在后端取得新状态后 5 秒内显示。该时限不包含外部开下播探测周期；日志只手动刷新。隐藏标签页可降低频率，回到前台立即刷新一次。
- **操作是异步的**：每次操作生成并保留一个请求编号，取得命令编号后显示“已提交”并查询结果；按契约区分处理中、已执行、失败和已中断。命令执行成功只提示“已安排录制”或“停止请求已生效”，实际开录/封口继续看任务状态。批量结果逐条显示，不把部分失败显示成全部成功。
- **重试与关闭**：网络结果不明时保留请求编号，同一次请求重试不得换编号；已中断命令由用户重新操作，生成新编号。服务关闭时网页无法提交，提示无法连接并禁用操作，不显示离线排队成功。
- **二次确认**：删除主播、停止本场、平滑停止任务需要确认对话框；其余操作不确认。
- **连接断开**：顶部栏变红并显示最后更新时间，页面保留最后一次数据，不清空；恢复后自动刷新。
- **未知值**：后端返回前端不认识的状态、原因代码或标记时原样显示，不报错。业务原因使用后端提供的 `code` 与 `detail`，前端只翻译已知代码并保留详情，不拆分冒号文本。
- **上传未启用**：后端声明上传未启用时，隐藏上传相关的列、筛选和总览告警。
- **手机**：页面在 375px 宽度下可读，表格横向滚动，操作列在窄屏不固定，对话框全屏显示；不做单独布局。
- **组网 http 访问**：非 HTTPS 地址不是浏览器安全上下文，`crypto.randomUUID` 与剪贴板接口可能不可用；请求编号改用 `crypto.getRandomValues` 生成 UUID v4，复制退回选中文本复制。

## 8. 实施步骤与依赖

1. 后端接口方案已定稿并由第 6 节链接引用；前端页面方案按其自身范围确认与授权。
2. 后端获实施授权后，实现 API 与静态托管（后端方案负责）。
3. 前端搭建工程、接口模块与中文映射，用模拟数据完成五个页面。
4. 接入真实后端，按第 9 节验收；上传部分在后端启用上传前只用模拟数据验证。

第 3 步可以在后端开发期间进行，第 4 步依赖第 2 步。

## 9. 验收标准

1. `npm run build` 成功；Vitest 覆盖状态与原因的中文映射、未知值原样显示、上传未启用时隐藏、命令提交后的状态变化，全部通过。
2. 接真实后端和运行中的调度器（测试实例与目标按当时授权）：五个页面与相同筛选、分页条件下的 API 及 CLI 查询结果一致，不再对比旧 CLI 整库转储格式。
3. 在页面上新增、删除主播，开关自动录制，立即开录，停止本场，平滑停止任务，各操作均能追踪命令结果；实际开录、停止和封口再核对任务及切片，不以提交成功代替执行验收。
4. 正常连接下，后端取得任务开录、实例离线、切片完成等新状态后 5 秒内页面更新；外部开下播探测周期不包含在该时限内。
5. 停止后端后页面显示断开并保留数据，恢复后自动刷新。
6. 从另一台设备经组网打开控制台，功能正常；手机宽度（375px）下各页面可读。
7. 上传界面：模拟数据下按状态类别正确显示；`upload_enabled` 为假时完全隐藏。
8. 命令中断、同编号重试、批量部分失败、停止中再次开录、日志缺失/截断均显示准确；服务关闭时不可提交，不出现离线排队成功提示。
9. 失败退避且无活跃任务时仍能在主播页停止本场，后续不再重试，监控与开关保持不变；确认框打开后发生换场时拒绝误停新场，不自动重发。有待对账任务时准确区分“已取消续录”和“遗留进程已结束”。

## 10. 风险与待确认事项

- 接口契约已经转由后端方案唯一维护；实施时的必要变更须同步页面适配，不能只改单边字段。
- 服务未运行时无法提交；已提交命令也可能因重启而中断。界面必须区分提交、执行和媒体完成，不能混用成功提示。
- 无验证依赖“只经组网访问”，若以后直接开放公网，需先补访问验证（ADR 0016）。
- Element Plus 体积较大，首屏加载在慢速隧道上可能需数秒；如有问题再按需引入组件。
- 日志默认行数和上限已在后端契约确定；身份放宽开关仍按第 4.3 节保留在 CLI，页面不新增入口。
- 总览告警自身包含目标名称、重试次数及时间，不依赖主播列表分页。
- 前端已通过合成联调与台式机真实录制验收；组网第二设备和真实手机访问未完成，方案保持待验证，不归档为完成。FFmpeg 版本兼容性发现见验证记录及待办 K14。

## 11. 实施调整记录

2026-11-11 初次前端实施未修改后端；收尾阶段经授权先修订后端第 6 节契约，再同步前后端。以下为当前实现：

| 调整 | 原因 | 落点 |
| --- | --- | --- |
| 总览直接读取完整告警，删除额外主播列表查询 | 后端提供次数、重试时间与目标名称，消除超过 200 个主播时信息缺失 | 第 4.1 节、第 10 节 |
