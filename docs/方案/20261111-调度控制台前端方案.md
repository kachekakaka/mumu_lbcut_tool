## 1. 背景与目标

调度器目前只有命令行：用 `status` 输出整库 JSON，用 `add`、`record`、`stop`、`remove` 写入命令队列（见[最小调度运行说明](../最小调度运行说明.md)）。查看几路录制的状态、失败重试和切片质量都要读 JSON，不能在录制机以外的设备上查看。

目标：做一个网页控制台，在录制机本机或通过组网的其他设备上：

1. 一眼看清正在录几路、各实例状态和需要关注的问题；
2. 管理监控主播，手动开录和平滑停止；
3. 查看任务运行情况、运行日志和切片（含质量标记与上传状态）。

## 2. 范围与非目标

范围：

- 前端工程（`web/`）：总览、实例、主播、任务、切片五个页面，以及第 5 节的交互规则。
- 第 6 节“前端所需接口”：列出前端需要的数据和操作，作为后端方案的输入。
- 上传状态的展示界面（后端未启用上传时隐藏）。

非目标：

- 后端 API、调度服务托管静态文件、上传交付本身——由后端方案负责。
- 登录验证（ADR 0016：只经组网访问）。
- 网页内播放切片；单独的手机布局（手机能看清即可，表格可横向滚动）。
- 实例操作按钮（ADR 0015 已取消人工解封，实例只查看）。
- 刷新机制的选择（轮询或推送由后端决定，前端只提出时效要求）。

## 3. 技术与工程结构

- Vue 3 + Vite + TypeScript + Element Plus，Vue Router 管理五个页面。不引入额外的状态管理库，各页面直接调用接口模块。
- 源码在仓库根目录的 `web/`；`npm run build` 输出到 `web/dist/`，不提交 Git（`.gitignore` 增加 `web/node_modules/`、`web/dist/`）。打包发布时带上构建结果。
- 后端在 API 同一端口托管 `web/dist/`，前端所有请求使用相对路径 `/api/...`，不写死主机和端口；任何地址或组网隧道下都可直接使用。
- 开发时 Vite 开发服务器把 `/api` 代理到本机后端（地址用环境变量配置）。后端还没提供的部分（如上传状态）用 `web/src/mock/` 下的固定样例数据，开发服务器以 `VITE_MOCK=1` 启用；构建产物不包含模拟数据。
- Node.js 只在开发和构建时需要（笔记本当前为 Node 24、npm 11）。台式机测试时从笔记本拷贝构建结果，不必安装 Node。
- 界面文字为中文；时间按浏览器本地时区显示（`MM-DD HH:mm:ss`，跨年显示年份），时长显示为 `时:分:秒`。

## 4. 页面设计

所有页面共用顶部栏：控制台名称、与后端的连接状态（正常 / 断开，断开时显示最后一次成功更新的时间）、上一次数据更新时间。左侧导航：总览、实例、主播、任务、切片。

### 4.1 总览

- 数字卡片：正在录制路数、排队任务数、空闲 / 离线实例数、今日切片数。
- 实例条：每个实例一个小卡片（编号、名称、状态颜色、当前主播）。
- 告警列表（按时间倒序，点击跳到对应页面）：
  - 失败重试中的目标：第几次、下次重试时间、最近失败原因；
  - 需要修正的目标（`needs_fix`）；
  - 需要人工对账的任务（`needs_reconcile`）；
  - 最近 24 小时内带质量标记或中止（aborted）的切片；
  - 上传失败的切片（上传启用时）。

### 4.2 实例（只查看）

表格列：编号、名称、状态、当前任务（链接到任务）、原因、状态更新时间。状态中文：空闲、录制中、复位中、离线、待对账；原因（如 `android_not_started`、`not_discovered`）显示中文说明，未知值原样显示。

### 4.3 主播

- 表格列：昵称（无则显示地址）、地址、开播状态（在播 / 已下播 / 未知，附最近确认时间）、自动录制开关、当前任务状态、提示（本场已抑制 / 需要修正：原因 / 失败重试中：第 N 次，下次 hh:mm:ss）。
- 筛选：在播、自动录制开 / 关、有提示。按名称或地址搜索。
- 操作：
  - 新增：对话框输入一个或多个地址（每行一个），可选“仅手动录制”。逐条显示结果（新增 / 已存在 / 失败原因）。
  - 删除：二次确认，提示“正在录制的任务会平滑停止，录像保留”。
  - 自动录制开关：直接切换。
  - 立即开录：对已抑制或需要修正的目标同样可用，说明会解除抑制或修正标记。
- 身份放宽开关（`--allow-unconfirmed-identity`）首版不在界面提供，仍通过 CLI 使用。

### 4.4 任务

- 默认显示进行中的任务（排队、启动中、录制中、停止中、待对账），切换后显示历史任务，支持按主播、状态、时间筛选，分页。
- 表格列：任务 ID（缩短显示，可复制）、主播、实例、状态、开始时间、已录时长、当前帧率、身份核验状态、切片数（完成 / 中止）、结束原因与退出码。
- 状态中文：排队中、启动中、录制中、停止中、待对账、已完成、完成但有警告、失败、已取消。退出码附中文说明（0 正常、9 目标无效、15 登录强阻断、20 设备不可用、30 录制失败等，未知码原样显示）。
- 操作：
  - 平滑停止（录制中、启动中、排队中可用）：二次确认，提示“当前切片会封口保存，本场不再自动开录，可在主播页立即开录恢复”。
  - 查看日志：抽屉显示该任务运行日志的最后 N 行（默认 200），手动刷新，不自动滚动更新。
- 任务详情（展开行）：该任务的切片列表、最近导航与恢复事件摘要。

### 4.5 切片

- 按主播、任务、状态（录制中 / 完成 / 中止）、是否有质量标记、上传状态筛选，时间倒序分页。
- 表格列：主播、任务、序号、状态、时长、大小、是否末片、质量标记、上传状态、文件路径（可一键复制）。
- 质量标记显示为标签：遮挡（`overlay_*`）、低帧率、画面静止、画面检查不可用、身份未确认；鼠标悬停显示疑似开始时间。未知标记原样显示。
- 上传状态（上传启用时显示）：状态、尝试次数、最近错误、更新时间。状态值以后端定义为准，前端按第 6 节的约定着色；只展示，不提供重新推送按钮。

## 5. 交互规则

- **时效**：实例、任务、目标、切片状态变化后 5 秒内在页面上反映；日志只在手动刷新时更新。浏览器标签页不可见时可以降低刷新频率，回到前台立即刷新一次。
- **操作是异步的**：调度器通过命令队列执行操作。点击后按钮进入“已提交”状态并显示提示；拿到命令结果后显示成功或失败原因。调度器未运行时，提示“命令已排队，调度器未运行，暂不会执行”。
- **二次确认**：删除主播、平滑停止任务需要确认对话框；其余操作不确认。
- **连接断开**：顶部栏变红并显示最后更新时间，页面保留最后一次数据，不清空；恢复后自动刷新。
- **未知值**：后端返回前端不认识的状态、原因或标记时原样显示，不报错。
- **上传未启用**：后端声明上传未启用时，隐藏上传相关的列、筛选和总览告警。
- **手机**：页面在 375px 宽度下可读，表格横向滚动，对话框全屏显示；不做单独布局。

## 6. 前端所需接口（交给后端方案）

本节只描述前端需要什么，不规定后端实现；路径为建议，后端方案可调整，调整后回写本节。字段名沿用现有数据库和事件命名（见 `src/orchestrator/storage.py`、`src/worker/events.py`）。

### 6.1 通用约定

- 全部在 `/api` 下，JSON；时间为 Unix 秒（浮点）。
- 出错返回非 2xx 和 `{"message": "中文说明"}`。
- 列表接口支持 `limit`、`offset` 和第 4 节列出的筛选条件，返回 `{items, total}`。
- 状态枚举使用当前代码中的英文值，前端负责中文显示：
  - 实例：`idle`、`busy`、`resetting`、`offline`、`reconcile`；
  - 任务：`pending`、`starting`、`running`、`stopping`、`needs_reconcile`、`finished`、`finished_with_warnings`、`failed`、`cancelled`；
  - 切片：`started`、`finished`、`aborted`；
  - 目标可信状态：`live`、`ended`、`unknown`。
- 数据刷新方式（轮询或推送）由后端决定，需满足第 5 节的 5 秒时效。

### 6.2 读取

| 用途 | 建议接口 | 需要的数据 |
| --- | --- | --- |
| 总览 | `GET /api/overview` | 各状态的实例数、任务数，今日切片数；第 4.1 节告警列表所需的条目（类型、对象 ID、说明、时间） |
| 系统信息 | `GET /api/system` | 调度器是否在运行、上传是否启用、服务版本（便于排查前后端不一致） |
| 实例 | `GET /api/instances` | `vmindex`、`name`、`status`、`job_id`、`reason`、`updated_at`，以及当前任务的主播昵称 |
| 主播 | `GET /api/targets` | `id`、`raw`、`nickname`、`trusted_status`、`confirmed_at`、`auto_record`、`room_id`、`anchor_uid`；是否本场已抑制（`suppressed_session` 等于当前场次）、需要修正原因（`note` 去掉 `needs_fix: ` 前缀）、`attempts`、`retry_at`；当前活跃任务的 ID 与状态 |
| 任务 | `GET /api/jobs` | `id`、`target_id`、主播昵称、`vmindex`、`status`、`created_at`、`started_at`、`ended_at`、`exit_code`、`stop_reason`、`error_reason`；最新心跳中的 `elapsed_sec`、`fps`、`room_identity_status`；切片完成数与中止数 |
| 任务详情 | `GET /api/jobs/{id}` | 上述字段，加最近若干条导航与恢复事件（`room_navigation`、`stall_detected`、`stall_healed`、`worker_failed` 等）的摘要 |
| 任务日志 | `GET /api/jobs/{id}/log?lines=200` | 运行日志（`events/<job_id>.log`）最后 N 行文本；文件不存在时说明原因 |
| 切片 | `GET /api/segments` | `job_id`、`segment_index`、主播昵称、`status`、`file_path`、`duration_sec`、`file_size_mb`、`is_final`、`reason`；质量标记列表（每项含 `flag`、`suspected_start_time`）；上传状态（见 6.4） |

### 6.3 操作

| 操作 | 建议接口 | 说明 |
| --- | --- | --- |
| 新增主播 | `POST /api/targets`，`{targets: [地址...], manual_only: bool}` | 逐条返回 `target_id` 与结果（新增 / 已存在 / 错误原因） |
| 删除主播 | `DELETE /api/targets/{id}` | 对应现有 `remove` 命令 |
| 开关自动录制 | `PATCH /api/targets/{id}`，`{auto_record: bool}` | 现有 CLI 无此命令，需要后端新增 |
| 立即开录 | `POST /api/targets/{id}/record` | 对应现有 `record` 命令 |
| 平滑停止 | `POST /api/jobs/{id}/stop` | 对应现有 `stop` 命令 |
| 命令结果 | `GET /api/commands/{id}` | 走命令队列的操作返回 `command_id`，前端据此查询 `status`、`result` |

### 6.4 上传状态（后端实现上传后提供）

- `GET /api/system` 的 `upload_enabled` 为假时，前端隐藏全部上传界面，切片不需要带上传字段。
- 启用时，每个切片带 `upload` 对象：`status`（字符串，取值由后端定义）、`attempts`、`last_error`、`updated_at`。
- 后端方案需给出状态值列表，并标明每个值属于“进行中”“成功”“失败”中的哪一类，前端按类别着色（灰 / 绿 / 红），未列出的值按灰色原样显示。

## 9. 验收标准

1. `npm run build` 成功；Vitest 覆盖状态与原因的中文映射、未知值原样显示、上传未启用时隐藏、命令提交后的状态变化，全部通过。
2. 接真实后端和运行中的调度器（测试实例与目标按当时授权）：五个页面显示的数据与 CLI `status` 输出一致。
3. 在页面上新增、删除主播，开关自动录制，立即开录，平滑停止任务，各操作都能看到命令结果，并在 CLI `status` 中确认生效。
4. 任务开始录制、实例离线、切片完成后 5 秒内页面更新。
5. 停止后端后页面显示断开并保留数据，恢复后自动刷新。
6. 从另一台设备经组网打开控制台，功能正常；手机宽度（375px）下各页面可读。
7. 上传界面：模拟数据下按状态类别正确显示；`upload_enabled` 为假时完全隐藏。

## 10. 风险与待确认事项

- 第 6 节字段以当前代码为准，后端实现时可能调整；不回写会导致前后端对不上。
- 操作经命令队列执行，调度器未运行时操作不会生效；界面必须说明，不能显示为成功。
- 无验证依赖“只经组网访问”，若以后直接开放公网，需先补访问验证（ADR 0016）。
- Element Plus 体积较大，首屏加载在慢速隧道上可能需数秒；如有问题再按需引入组件。
- 待确认：身份放宽开关首版不在界面提供（第 4.3 节）；日志默认 200 行是否够用。
